# Проверки редактора v2

Из корня репозитория (`O:/Engine/Engine`):

```powershell
./Editor/tools/test-regression.ps1 -Configuration Debug
./Editor/tools/test-regression.ps1 -Configuration Debug -Full
./Editor/tools/test-regression.ps1 -Configuration Release -Full
```

Обычный запуск собирает и выполняет CoreTests, HostTests и UiTests. `-Full`
дополнительно собирает runtime/редактор с Assimp и проверяет движок, HUD,
нативную замену DLL и реальные сценарии Qt:

- импорт, материалы, шейдеры, трансформации, свет, сохранение и Play/Stop;
- переимпорт и перенос ассетов;
- групповое выделение, перемещение, дублирование, отмена/повтор;
- восстановление несохранённой сцены после завершения процесса;
- изменение размеров, перетаскивание, отделение и восстановление панелей;
- hot reload без закрытия окна, с работающими камерой и оверлеями.

Нужны Visual Studio C++, bundled Qt, Assimp для полного набора и доступ к
Windows desktop/D3D. Qt-тесты временных файлов нельзя запускать в среде,
которая запрещает запись в созданные `QTemporaryDir` каталоги.

Каждый запуск создаёт отдельный каталог `Engine/build/editor-regression/`
с логами и одноразовыми игровыми проектами. Runner не удаляет пользовательские
проекты и кэш установленных движков и не завершает чужие процессы. Таймаут
одного теста по умолчанию — 180 секунд; превышение и ненулевой код считаются
ошибкой. `-SkipBuild` предназначен только для уже собранной текущей конфигурации.

## Регрессии интеграции main

`HostRegressionTests.h` — 45 проверок маршрутизации команд, групп, свойств,
совместимости без расширений API, ошибок checkpoint/load, истории и дочерних
объектов. Проверяется разрыв объединения nudges после промежуточного изменения,
очистки истории и undo/redo.

`OverlayHostTests.h` — 18 проверок камеры, копирования и дедупликации иконок,
повторной загрузки после ошибки, смены/исчезновения сервиса DLL и очистки
оверлеев. Они не требуют рендера.

`Engine/tests/input/EditorReloadTests.cpp` дополнен 9 проверками реального
overlay API после выгрузки старой DLL. Таблица расширения обязана переходить
вместе с основной сессией при успешном reload и оставаться прежней при ошибке.

Все новые проверки выполняются и в Release; они не используют отключаемый
`assert`. Счётчик интеграционных `EditorUiTests` включает проверки каждого
отрисованного кадра, поэтому его значение меняется со скоростью выполнения.

`UiSmokeTests.h` проверяет, что `ConfigureTabBars` не переключает вкладки
отложенными синтетическими кликами: после настройки обрабатывается очередь
событий в течение 550 мс, текущая вкладка и число её изменений должны сохраняться.
Синтетические клики для проверки взаимодействий остаются только в тестах.

При интеграции изменений viewport дополнительно запускайте
`Engine/tests/run-viewport.ps1` (D3D readback и размер иконок на разных дистанциях)
и `Engine/tests/subsystems/run.ps1` (жизненный цикл GameSession/GameSubsystem).
`EngineTests` сохраняет контракт вызова пользовательского Draw без окна и
возврата InvalidArgument для образца курсора до attach или с неверным размером.
HUD-фикстура задаёт координаты через `Input::SetCursorPosition`, как embedded host,
и не зависит от положения системной мыши. `EditorUiTests` проверяет немедленное
обновление прямоугольника UI при изменении числового поля без потери фокуса.
Сценарий `--reload` проверяет сохранение сессии и показ уведомления при попытке
загрузить отсутствующую DLL: ошибки пользовательского Hot Reload не должны
подавляться вместе с фоновыми командами viewport.

`run-editor.ps1` не обновляет DLL внутри пользовательских проектов. Их сборкой
и обновлением управляют launcher/ProjectTools; подмена модулем SceneProject
уничтожает пользовательскую C++-реализацию.

## PR №24 и интеграция 0.3.0

CoreTests включает правила расширений и защищённые операции с папками.
HostTests проверяет объединение gizmo-команд и замену Engine.Model с Undo/Redo.
UiTests покрывает выбор ресурсов, миниатюры, фильтры Content, повторное
прикрепление панелей, стабильность инспектора и размеры иконок viewport.
Полный EditorUiTests дополнительно проверяет, что «Нет текстуры» остаётся
доступным при поиске; необязательный запуск с моделью проверяет отказ
превращать примитив в Engine.Model, затем добавление нового модельного объекта.

При слиянии сохранены карточки скриптов и ИИ и их периодическое обновление.
