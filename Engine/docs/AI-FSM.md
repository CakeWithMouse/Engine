# Автоматы ИИ в файлах `.fsm`

Автомат ИИ можно описать не только в C++ (`Ai::MachineBuilder`), но и файлом `.fsm`. Его будет сохранять редактор ИИ,
а движок строит из файла тот же `Ai::StateMachine`: те же проверки, тот же исполнитель и отладчик. Файл работает и в
проектах без C++.

Состояния, переходы и ключи памяти записаны в файле. Что делает состояние — список **блоков**:
- задачи (Task) — что делать в состоянии;
- условия (Condition) — когда можно войти в состояние или пройти по переходу;
- службы (Service) — фоновая работа с интервалом.

Встроенные блоки называются `Ai.*`. Игра добавляет свои на C++ (см. [Свои блоки](#свои-блоки-на-c)), и редактор
предлагает их по имени. API: `Engine/Include/Engine/AI/MachineFile.h`, тесты — `Engine/tests/ai/Source/MachineFileTests.cpp`.

## Как запустить

У «ИИ-персонажа» (`Gameplay.AiCharacter`) автомат задаёт свойство `stateMachine`:
- имя, зарегистрированное в C++ (`Guard`), как раньше;
- путь к файлу, оканчивающийся на `.fsm` (`/Game/AI/Guard.fsm`), — тогда автомат читается из файла.

**В редакторе** это карточка **«Автомат ИИ»** в свойствах персонажа (и его C++-наследников):
- поле — путь к `.fsm` или имя автомата из C++;
- **Создать** — новый `Content/AI/<имя объекта>.fsm` (одно состояние «Idle», ключ памяти `Target` — цель восприятия),
  он сразу назначается персонажу и открывается в окне автомата; **Открыть** — окно автомата; **Выбрать…** — файл из
  Content; **Убрать**;
- под кнопками подсказки: файл не найден, путь не из `/Game/`, автомат из C++;
- **«Память у этого объекта»** — переменные файла (кроме `object`): пустое поле — значение из файла (в подсказке),
  заполненное — своё у этого объекта, ↺ возвращает значение файла. Хранятся в свойстве `machineMemory` как JSON
  `{"Speed": 3.5}` и идут через Undo/Redo, сохранение сцены и «Создать копию». В Play они применяются поверх значений
  файла; ключ, которого нет в файле, и значение другого типа пропускаются. Автомату из C++ значения не передаются.

**Проверка и отладка.** Раз в секунду редактор проверяет назначенный `.fsm` тем же загрузчиком, что и Play
(после каждого изменения файла): ошибки с номерами нод появляются под кнопками карточки — с ними Play не начнётся.
В Play карточка выделенного персонажа показывает активную цепочку состояний («Сейчас: Patrol › Walk»), память
персонажа и три последних перехода. Это делает расширение `Engine.Scene.AiMachine` (см. ниже).

## Окно автомата

Открывается из карточки («Открыть»), двойным щелчком по `.fsm` в Files или через ПКМ → «Редактировать автомат ИИ».
В Files есть и «Новый автомат ИИ…». Каждая правка сразу записывается в файл и проверяется движком: ошибки — красной
рамкой на ноде и строкой в списке под холстом (щелчок показывает ноду), подозрительное — жёлтым.

- **Холст.** Ноды — «Состояние», «Закончить», «Следующее» (+ Нода, Tab или ПКМ). Связь от выхода `out` состояния
  к входу — переход. В состоянии видны его задачи (▶), условия входа («если …»), службы (⟳) и связанный автомат (⇢).
  Дети состояния обведены пунктирной рамкой вместе с ним. Отмена, буфер обмена, «Упорядочить», комментарии — как в
  окне скрипта.
- **Состояние** (двойной щелчок): имя, «Внутри состояния» (родитель; дети упорядочены сверху вниз), связанный
  автомат и три вкладки блоков — задачи, условия входа, службы. Блок добавляется из меню (встроенные, затем блоки
  игры), порядок — ↑ ↓, параметры — полями под списком; ключи памяти выбираются из подходящих по типу. У условия есть
  «Наоборот (НЕ)», у службы — интервал.
- **Переход** (двойной щелчок по связи): когда срабатывает (состояние завершилось, успех, провал, по событию,
  каждое решение), событие, задержка, приоритет и дополнительные условия. Подпись на связи кратко говорит то же.
- **Слева — память и настройки:** ключи с типом и начальным значением (переименование ключа переименовывает его во
  всех блоках и настройках), «Цель восприятия», «Где видели» и интервал решений персонажа.
- Удалили состояние-родителя — его дети встают на верхний уровень (в той же правке, отменяется вместе с ней).

Группы условий «Хотя бы одно из» / «Все из» окно показывает и переставляет, но их состав пока правится в файле.

Файл читается при первом Play и кэшируется, пока он сам и связанные с ним файлы не изменятся. Если в файле есть ошибки,
Play не начинается: в сообщении — путь, первые три ошибки с номерами нод и сколько ещё.

Из C++: `Ai::LoadMachineFile(path)` возвращает `asset` (или список `problems`), `asset->Run(controller, values)` задаёт
память (значения файла, затем `values` — JSON объекта), настройки и запускает автомат. Текст файла без диска —
`Ai::LoadMachine(json, name, reader)`.

## Пример

Готовый учебный проект без C++ — [Game/AiTutorial](../../Game/AiTutorial/README.md): двор с охранником (патруль,
погоня, поиск, возврат), посетителем, который ходит к умным объектам, и игроком. Создаётся скриптом `Create.ps1`,
урок на 5 минут — в его README. Ниже — упрощённый охранник из одного файла.

Охранник смотрит по сторонам, пока не увидит игрока, бежит к нему и возвращается, потеряв из виду.

```json
{
  "format": "ITMOEngine.Graph", "version": 1, "schema": "ai.fsm", "schemaVersion": 1,
  "variables": [
    {"name": "Player", "type": "object"},
    {"name": "LastSeen", "type": "vec3"},
    {"name": "Home", "type": "vec3", "value": [0, 0, 0]}
  ],
  "settings": {"targetKey": "Player", "lastSeenKey": "LastSeen", "thinkInterval": 0.1},
  "nodes": [
    {"id": 1, "type": "Fsm.State", "title": "Idle", "x": 0, "y": 0,
     "properties": {"name": "Idle", "tasks": [{"type": "Ai.WaitRandom", "minimum": 1, "maximum": 3}]}},
    {"id": 2, "type": "Fsm.State", "title": "Chase", "x": 300, "y": 0,
     "properties": {"name": "Chase", "tasks": [{"type": "Ai.MoveTo", "target": "Player", "radius": 1.5}]}},
    {"id": 3, "type": "Fsm.State", "title": "Return", "x": 300, "y": 200,
     "properties": {"name": "Return", "tasks": [{"type": "Ai.MoveTo", "target": "Home"}]}}
  ],
  "connections": [
    {"fromNode": 1, "fromPin": "out", "toNode": 2, "toPin": "in",
     "properties": {"trigger": "tick", "conditions": [{"type": "Ai.CanSee", "target": "Player"}]}},
    {"fromNode": 2, "fromPin": "out", "toNode": 3, "toPin": "in",
     "properties": {"trigger": "tick", "conditions": [{"type": "Ai.CanSee", "target": "Player", "not": true}], "delay": 2}},
    {"fromNode": 3, "fromPin": "out", "toNode": 1, "toPin": "in", "properties": {"trigger": "completed"}}
  ]
}
```

У Idle нет перехода по завершению. Поэтому, когда ожидание кончается, автомат выбирает состояние заново с корня — снова
Idle, первое по порядку.

## Формат

Общий формат графов `ITMOEngine.Graph` версии 1 (как `.vscript`), схема `ai.fsm` версии 1. Поля `title`, `comments` и
незнакомые поля нод движок не читает: это данные редактора.

### Память: `variables`

Ключи памяти (Blackboard), которыми пользуются блоки, объявляются в файле — так опечатка в имени ключа видна сразу.

| Поле | Значение |
|---|---|
| `name` | Имя ключа. |
| `type` | `bool`, `int`, `float`, `vec3`, `string`, `object` (объект сцены). |
| `value` | Необязательное начальное значение: записывается в память при запуске. У `object` начального значения нет. |

Ключ без `value` пуст, пока его не запишет блок, восприятие или C++.

### Настройки: `settings`

Все поля необязательные.

| Поле | Значение |
|---|---|
| `targetKey` | Ключ типа `object`: восприятие пишет сюда лучшую видимую цель (`Perception::WriteTargetTo`). |
| `lastSeenKey` | Ключ типа `vec3`: где цель видели последний раз. |
| `thinkInterval` | Секунды между решениями; 0 — каждый кадр. Без поля контроллер оставляет свой интервал. |
| `services` | Службы всего автомата (как `MachineBuilder::Service`). |

Зрение и слух включаются свойствами «ИИ-персонажа» (радиус зрения, угол, слух); без зрения `Ai.CanSee` всегда ложь.

**Кого видит ИИ без C++.** Другие ИИ-персонажи видны всегда. Игрок — так:
- обычный «Игрок» (`Gameplay.Player`), которого игра не зарегистрировала сама (`World::AddTarget`), становится целью
  команды 1, когда стартует первый ИИ-персонаж;
- «ИИ-персонаж» с галкой «Игрок» им не управляется, а виден как цель своей «Команды».

Разные команды враждебны, команда 0 нейтральна ко всем: охраннику, который должен замечать игрока, поставьте команду 2.

### Ноды

| `type` | Что это |
|---|---|
| `Fsm.State` | Состояние. Вход `in`, выход `out`. |
| `Fsm.Finish` | Цель перехода «закончить»: автомат останавливается, а внутри связанного автомата завершается состояние, которое его связало. |
| `Fsm.Next` | Цель перехода «следующее»: следующее по порядку состояние того же родителя. У последнего — ошибка. |

Свойства состояния (`properties`):

| Поле | Значение |
|---|---|
| `name` | Имя: уникальное, без `/`. Путь в отладчике — `Родитель/Ребёнок`. |
| `parent` | id родительского состояния; нет или 0 — верхний уровень. |
| `tasks` | Задачи. **Состояние завершается, как только завершилась любая его задача** (успех — если без провала); остальные прерываются. |
| `enterIf` | Условия входа: войти можно, только если выполнены все. |
| `services` | Службы, пока состояние активно. |
| `linked` | Связанный автомат: имя из C++ или путь к другому `.fsm`. Его состояния становятся детьми этого; своих детей у такого состояния быть не может. Память и настройки связанного файла не используются. Глубина — до 8 файлов, циклы — ошибка. |

**Порядок.** Дети одного родителя (и состояния верхнего уровня) упорядочены так, как нарисованы: сверху вниз (`y`),
при равном `y` — слева направо (`x`), затем по id. Порядок решает, кто входит первым (родитель входит в первого
допустимого ребёнка, автомат — в первое допустимое верхнее состояние) и куда ведёт `Fsm.Next`.

### Переходы: `connections`

Связь от `out` состояния к `in` состояния, `Fsm.Finish` или `Fsm.Next`. Переход родителя действует, пока активен любой
его потомок. Свойства (`properties`), все необязательные:

| Поле | Значение |
|---|---|
| `trigger` | Когда проверять: `completed` (по умолчанию — состояние завершилось), `succeeded`, `failed`, `event` (пришло событие), `tick` (каждое решение). |
| `event` | Имя события для `trigger: "event"`. События шлют `Ai.SendEvent`, C++ (`Controller::SendEvent`) и восприятие (`Ai.Spotted`, `Ai.Lost`, `Ai.Heard`, `Ai.Damaged`). |
| `conditions` | Дополнительные условия: переход проходит, только если выполнены все. |
| `delay` | Секунды между срабатыванием и переходом; состояние должно оставаться активным. |
| `priority` | Целое; меньше — проверяется раньше. При равных — порядок связей в файле. Срабатывает первый подходящий переход. |

### Блоки

Блок — объект `{"type": "Ai.Wait", "seconds": 2}`: тип и параметры. Незнакомый параметр — ошибка (защита от опечаток),
пропущенный — значение по умолчанию; ключи и события обязательны. У условий есть `"not": true` (отрицание), у служб —
`"interval"` (секунды, по умолчанию 0 — каждое решение).

Группы условий: `{"type": "Ai.Any", "items": [...]}` — хотя бы одно, `{"type": "Ai.All", "items": [...]}` — все
(вложенность до 8).

**Задачи**

| Тип | Параметры | Что делает |
|---|---|---|
| `Ai.Wait` | `seconds` = 1 | Ждёт и завершается успешно. |
| `Ai.WaitRandom` | `minimum` = 1, `maximum` = 2 | Ждёт случайное время в этих пределах. |
| `Ai.MoveTo` | `target` (ключ `object` или `vec3`), `radius` = 1 | Идёт к объекту или точке. Провал — ключ пуст или цель недостижима. |
| `Ai.FollowRoute` | `radius` = 0.5 | Идёт к следующей точке маршрута (маршрут задаёт C++: `Controller::SetRoute`). |
| `Ai.LookAt` | `target` (ключ `object`) | Поворачивается к объекту, пока состояние активно; сама не завершается. |
| `Ai.SendEvent` | `event` | Шлёт событие своему автомату (переход сработает в следующем решении). |
| `Ai.SetValue` | `key`, `value` (того же типа, что ключ) | Записывает значение в память. Ключ `object` так не задать — есть `Ai.FindObject`. |
| `Ai.ClearKey` | `key` | Удаляет значение из памяти. |
| `Ai.FindObject` | `object` (имя в сцене), `key` (ключ `object`) | Записывает объект сцены в память. Провал — такого нет. |
| `Ai.Log` | `text` | Строка в историю контроллера (видна в отладчике). |
| `Ai.UseSmartObject` | `tag`, `seconds` = 2, `radius` = 50 | Находит ближайший свободный умный объект с меткой, идёт к нему и использует. |
| `Ai.CallScriptEvent` | `event`, `target` (необязательный ключ `object`) | Запускает «Своё событие» в визуальном скрипте персонажа (или объекта из `target`) и сразу завершается. Провал — нет скрипта или такого события. |

**Условия**

| Тип | Параметры | Истина, когда |
|---|---|---|
| `Ai.HasKey` | `key` | В памяти есть значение ключа. |
| `Ai.IsTrue` | `key` (`bool`) | Ключ равен «да». |
| `Ai.Compare` | `key` (`int` или `float`), `op` = `>` (`<`, `<=`, `==`, `!=`, `>=`, `>`), `value` = 0 | Число в памяти сравнивается со значением; пустой ключ — ложь. |
| `Ai.Near` | `target` (`object` или `vec3`), `distance` = 2 | До цели по горизонтали не дальше `distance`. |
| `Ai.CanSee` | `target` (`object`) | Цель видна прямо сейчас. |
| `Ai.TimeInState` | `seconds` = 1 | Состояние активно не меньше этого времени. |
| `Ai.Chance` | `probability` = 0.5 (0–1) | Случайно, при каждой проверке. |
| `Ai.ScriptVariable` | `variable`, `op` = `==`, `value` = 1, `target` (необязательный ключ `object`) | Число или логическое (1 — да) переменной визуального скрипта персонажа (или объекта из `target`) сравнивается со значением. Нет скрипта или переменной — ложь. |

Встроенных служб нет: службы пишутся на C++.

### Ошибки

Загрузчик собирает все ошибки сразу, каждую — с id ноды (0 — файл целиком: заголовок, `variables`, `settings`).
Тексты английские, редактор будет их переводить. Примеры:
`task 2 "Ai.Wait": "seconds" must be 0 or more`, `enter condition 1 "Ai.IsTrue": "key": no variable "Alert"; declare it in "variables"`,
`transition to Next: "Rest" is the last state of its parent`.

## Связь с визуальными скриптами

Автомат и [визуальный скрипт](VISUAL-SCRIPTING.md) одного или разных объектов работают вместе: автомат решает, что
делать, скрипт — как это выглядит в игре (звук, эффект, счёт, двери).

- **Из автомата в скрипт:** задача `Ai.CallScriptEvent` запускает «Своё событие» скрипта, условие
  `Ai.ScriptVariable` читает его переменную. Без `target` — скрипт самого персонажа.
- **Из скрипта в автомат** — ноды группы «ИИ»: «Отправить событие ИИ» (переходы «по событию»), «Записать в
  память ИИ» (целый ключ остаётся целым), «Память ИИ: число / логическое / вектор / объект» (с выходом `Has`),
  «Состояние ИИ» (активный путь, работает ли автомат) и «ИИ в состоянии» (истина и для родителя активного).
  `Target` — ИИ-персонаж; другой объект — ошибка скрипта «объект — не ИИ-персонаж».
- **Порядок в кадре.** Скрипт выполняется в Tick объекта, автомат — на шаге ИИ: событие из скрипта автомат увидит в
  следующем решении, запись в память — сразу. Пока персонаж не начал игру (его BeginPlay позже в том же кадре),
  событие и запись в память пропускаются.

Пример — [Game/AiTutorial](../../Game/AiTutorial/README.md): по `E` скрипт игрока пишет охраннику точку шума и
отправляет `Noise`, а поймав игрока, автомат охранника вызывает `OnCaught` скрипта игрока.

## Расширение для редактора: `Engine.Scene.AiMachine` v1

Таблица `EngineAiMachineApi` в `Engine/Include/Engine/Runtime/EditExtensions.h`, сервис `EngineAiMachineService`.
Необязательное: без него редактор не проверяет файлы и не показывает состояние в Play.

| Функция | Что делает |
|---|---|
| `describe` | Каталог для редактора — `Ai::MachineCatalogJson()`. В любом состоянии. |
| `check` | Загружает `.fsm` по пути `/Game/...` загрузчиком Play и отдаёт все ошибки (нода, сообщение). Нет файла — одна ошибка `cannot read the file`. |
| `listUnits` | ИИ-персонажи сцены Play, у которых `stateMachine` равно аргументу (пустая строка — все): id объекта сцены редактора, имя, автомат, активный путь, работает ли. В Edit — никого. |
| `readStates` | Активная цепочка персонажа от внешнего состояния к внутреннему: id ноды в `.fsm` (0 — автомат из C++ или состояние связанного автомата), имя, путь. |
| `readMemory` | Память персонажа: ключ, тип, текст значения (объект — по имени в сцене). |
| `readHistory` | Строки истории контроллера, старые первыми: время, откуда, куда, причина. |

## Свои блоки на C++

Задача, условие или служба на C++ становится блоком: её параметры описываются, а редактор показывает их полями.

```cpp
#include <Engine/AI/Ai.h>

class Fire final : public Ai::Task<int>
{
public:
    explicit Fire(int salvos) : salvos_(salvos) {}
    Ai::Status Enter(Ai::Context&, int& left) const override { left = salvos_; return Ai::Status::Running; }
    Ai::Status Tick(Ai::Context&, int& left, float) const override { return --left > 0 ? Ai::Status::Running : Ai::Status::Succeeded; }
private:
    int salvos_;
};

ENGINE_AI_BLOCK(Ai::TaskBlock("Battle.Fire", "Огонь", "Fire",
    {Ai::Param::Int("salvos", "Залпов", "Salvos", 3, 1, 10)},
    [](const Ai::Params& p) { return std::make_shared<Fire>(p.Int("salvos")); }))
```

- Имена `Ai.*` и `Fsm.*` принадлежат движку; своё имя лучше начинать с имени игры.
- Параметры: `Param::Bool / Int / Float / Vec3 / String / Event`, `Param::Key(name, ParamType::KeyObject, …)` — ключ
  памяти нужного типа (`Key` — любой, `KeyNumber` — `int`/`float`, `KeyPlace` — `object`/`vec3`), `Param::Value` —
  значение того же типа, что параметр `key`. Для чисел — пределы, для строк — обязательность.
- Фабрика получает `Ai::Params`: `Int`, `Float`, `String` (и имя ключа), `KeyType` — тип объявленной переменной.
  `Params` живёт только во время загрузки: строки копируйте в задачу. Плохое сочетание значений — `throw
  std::invalid_argument("...")`: сообщение попадёт в ошибки файла у этой ноды.
- `ENGINE_AI_BLOCK` ставится в `.cpp` проекта игры (не статической библиотеки — компоновщик может выбросить файл).
  Можно и вызвать `Ai::RegisterBlock(...)` до запуска автомата.
- `Ai::MachineCatalogJson()` — все блоки с параметрами и подписями для редактора.
