# Физика и Mesh-коллайдеры

В сборке 0.4.0 r2 физика Jolt поддерживает Box, Sphere, Capsule и Mesh.
В Edit сохраняются настройки; симуляция выполняется в Play и Game при
включённой физике мира. CMake-сборка должна включать `PAIN_ENABLE_JOLT=ON`.

## Выбор формы в редакторе

Выберите объект с геометрией, включите его физику и задайте тип тела и форму
в карточке «Физика». Для пола, арки или неподвижного здания используйте
Static + «Меш (сложная)». Для груза — Dynamic + Mesh, для управляемого
движущегося препятствия — Kinematic + Mesh.

| Тип тела | Mesh-форма | Что происходит с отверстием |
|---|---|---|
| Static | Точные треугольники CPU-геометрии, обе стороны | Проём сохраняется |
| Dynamic | Одна выпуклая оболочка | Впадины и отверстия заполняются |
| Kinematic | Одна выпуклая оболочка | Впадины и отверстия заполняются |

Например, статическая арка пропускает предмет через центральный проём.
Движущийся U-образный груз сталкивается как выпуклое тело: предмет не должен
проваливаться внутрь его визуальной впадины. Выпуклая декомпозиция здесь не реализована.
Примитивные коллайдеры остаются подходящим простым вариантом для обычных коробок и шаров.

## C++

```cpp
#include <Engine/Components/GameComponents.h>
#include <Engine/MainGame/BaseGameClass/Game.h>
#include <Engine/Render/MeshPrimitives.h>

void AddCrate(Game& game)
{
    std::unique_ptr<GameComponent> crate = std::make_unique<GameComponent>();
    crate->SetPrimitive(MeshPrimitives::Cube());
    crate->SetPosition({0, 3, 0});
    crate->SetPhysicsBodyType(PhysicsBodyType::Dynamic);
    crate->SetPhysicsShapeType(PhysicsShapeType::Mesh);
    crate->SetPhysicsDensity(1000.0f);
    crate->SetPhysicsEnabled(true);
    game.GetScene().AddComponent("Crate", crate);
}
```

Геометрию можно задать также `MeshComponent::SetMesh` или импортированной моделью.
В низкоуровневом `PhysicsBodyDesc` поля `meshVertices` и `meshIndices` указывают
на треугольники в локальных координатах тела. Данные нужны до завершения `CreateBody`.
Массу динамической оболочки определяют её объём и `density`.

Вершины без ссылок из пригодных треугольников не влияют на оболочку и массу.
Треугольники с неверными индексами, нечисловыми координатами и нулевой площадью
пропускаются. Если пригодной формы нет, `CreateBody` возвращает 0.
Подвижной оболочке нужна объёмная геометрия. В игре наличие тела можно проверить
через `HasPhysicsBody()` после начала симуляции.

## Преобразования и ограничения

Mesh преобразуется из координат видимой геометрии в координаты тела.
Учитываются отражение, отрицательный масштаб и преобразования родителей,
включая поворот при неравномерном масштабе. В r2 исправлены потеря этих
преобразований и влияние неиспользуемых вершин на массу.

Форма создаётся из имеющихся CPU-вершин при создании тела. Скелетная/VAT-анимация
и последующие изменения геометрии не перестраивают её автоматически.
После изменения геометрии пересоздайте тело, например выключив и снова
включив физику компонента. Отдельные экземпляры пакета инстансинга не получают
индивидуальные тела автоматически.

## Сохранение и совместимость

В сцене Mesh записывается как `"physics":{"enabled":true,"body":"static",
"shape":"mesh","friction":0.5,"restitution":0,"density":1000}`.
Сами вершины этот блок не сохраняет: их восстанавливает ресурс модели или
фабрика игрового C++-компонента. Произвольную процедурную геометрию необходимо
воспроизводить кодом, а не рассчитывать на один physics-блок.

В `Engine.Scene.PhysicsObject` v1 значение `shapeType=3` означает Mesh.
Размер C-структуры и базовые Module/Edit API не изменены. C++ `PhysicsBodyDesc`
расширен указателями: пересоберите проект с согласованными заголовками и библиотекой r2.
Старые runtime не понимают `shape:"mesh"`, хотя номер формата сцены остаётся 3.
Храните исходную копию сцены; сцены без Mesh продолжают использовать прежние формы.
