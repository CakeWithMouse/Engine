# Статистика завершённого кадра и LOD

SDK 2026.11.05.1. C++ API локален игровой DLL; замороженные C ABI не изменены.

## Завершённый кадр

```cpp
void MyGame::PreUpdate(float dt) {
    Game::PreUpdate(dt);
    const auto& frame = GetCompletedFrameStats();
    if (!frame.valid) return; // ещё не было отрисованного кадра
    // frame.frameIndex — номер кадра, frame.counters — FrameStats.
    UpdateMyHud(frame.counters.DrawCalls, frame.counters.InstancesDrawn);
}
```

Снимок публикуется после основных render passes, перед диагностической панелью и Present.
В PreUpdate это предыдущий отрисованный кадр. Он остаётся доступным, когда текущие Stats
уже сброшены. valid=false до первой отрисовки и после освобождения графики. Пауза симуляции
не останавливает публикацию, пока рисуются кадры. Минимизированное окно не создаёт новые
снимки. frameIndex позволяет отличить новый результат от повторного чтения старого.

GetCompletedFrameStats возвращает const-ссылку, действующую до следующей публикации/завершения
Game. Для хранения скопируйте структуру. Чтение — на потоке игры. Это не гарантия успешного
Present, не GPU timing и не измерение FPS. DrawCalls/InstancesDrawn/IndicesDrawn включают
основные проходы и тени; один объект может участвовать в нескольких проходах.
Собственный игровой HUD учитывается, диагностическая панель движка исключается.

GetFrameStats сохраняет прежний контракт: изменяемые накопительные счётчики **текущего**
незавершённого кадра для render-интеграции. В PreUpdate они обычно нулевые. Для игрового
HUD используйте GetCompletedFrameStats, а не случайный момент чтения GetFrameStats.

## Панель

В окне игры или viewport с игровым фокусом: **F7** показывает/скрывает панель,
**F8** выбирает следующий InstancedMeshComponent. Программно:

```cpp
SetRenderDiagnosticsVisible(true);
SetLodDiagnosticsTarget(componentId); // 0 — первый; удалённый ID → первый доступный
```

Панель расположена справа сверху, работает в standalone и embedded viewport, в Forward,
Deferred и Custom после основного рендера. Не добавляется в сцену, не сохраняется в SaveGame,
не захватывает мышь и не создаёт игровых input-подписок. F3/F4/F5 продолжают выполнять
прежние функции; F7/F8 зарезервированы для диагностики. Панель выключена по умолчанию.

Показываются завершённый кадр, общие counters и выбранный компонент:

- Color visible / total — уникальные экземпляры основного прохода.
- Hidden — bVisible=false; distance — отсечены DrawDistance; frustum — вне камеры.
  Проверки идут в этом порядке: причины взаимоисключающие, total = drawn + три причины.
- Camera distance — минимум/максимум по включённым экземплярам, в том числе отсечённым.
- Draw limit и способ выбора LOD: distance в world units либо screen pixels.
- Для каждого LOD — число записей в color bucket, порог перехода; sprite отмечается явно.
  При fade один экземпляр может попасть в два bucket. Сумма bucket тогда больше drawn.
- Not prepared this frame означает отсутствие актуальных данных, а не ноль нарисованных
  объектов. Это важно для пустого mesh, пропущенного render и пользовательского Draw.

При узком viewport строки обрезаются с многоточием, при малой высоте показана подсказка
увеличить окно. Полные данные доступны в frame.lodComponents; GetRenderDiagnosticsLines()
возвращает строки панели для автоматических проверок. Имена/ID относятся к сохранённому
кадру; не используйте ID как гарантию, что объект ещё существует в изменённой сцене.

В InstancedMeshComponent остаются SetLodDebugColors, GetDrawnInstancesForLod и
GetLodDiagnostics — текущие CPU-данные подготовки компонента. Для согласованного набора
одного завершённого кадра используйте Game::GetCompletedFrameStats().lodComponents.

С 2026.11.05.2 screen-size LOD учитывает текущую проекцию камеры:
при orthographic размер зависит от orthoHeight и высоты viewport, а перемещение
камеры вдоль направления взгляда само по себе не меняет уровень. При perspective
сохраняется оценка по радиусу bounding sphere, FOV и расстоянию. DrawDistance
по-прежнему применяется в мировых единицах в обоих режимах.

В 2026.11.05.3 F7/F8 читают общий Input::System, поэтому доступны также при
вводе через встроенный игровой viewport; удержание клавиши не повторяет действие.
Неназначенный материал InstancedMesh теперь выбирает штатный instanced shader:
позиции, масштабы, цвета и fade экземпляров учитываются GPU без ручного выбора HLSL.
Явно заданный материал или пользовательский shader сохраняет приоритет.

В 2026.11.05.4 исправлены также обычные primitive `CreateInstance`:
без явно заданного legacy shader копии используют штатный mesh/material путь.
Позиции и цвета учитываются как с материалом, так и без него; экземпляры,
созданные после первого кадра, тоже отображаются. Исходный компонент остаётся
шаблоном и отдельно не рисуется. Для трёх видимых объектов нужны три вызова
CreateInstance. Явные legacy shader pairs сохраняют свой прежний путь рендера.

В 2026.11.05.5 MeshComponent, InstancedMeshComponent и FBXComponent загружают
отложенную текстуру при создании GPU-ресурсов. Назначение TrySetTexture до
присоединения к Game сохраняет путь; после подключения к инициализированному
Game HasTexture отражает загруженный ресурс. Это относится и к текстурам
объектов, восстановленных из сцены: повторный setter в игровом коде не нужен.

в embedded и standalone, доступ из PreUpdate, отсутствие первого снимка, причины отсечения,
переход LOD, исключение панели из counters, пауза/минимизация/resize/удаление объекта и BMP.
