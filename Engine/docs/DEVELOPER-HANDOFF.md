# Передача проекта разработчикам — 0.3.0

Состояние на 14.11.2026. Windows x64, C++17, Direct3D 11, Qt 6.7, Assimp.
Пути ниже относительны корню репозитория; в готовом пакете начните с `Docs/index.html`.

## 1. Назначение и границы

Engine предоставляет сцены, компоненты, рендер, ввод, ресурсы, звук, скрипты и ИИ.
Editor.dll — работающий Qt-редактор с D3D viewport, инспектором, ресурсами,
материалами, визуальными скриптами, автоматами ИИ, Undo/Redo и Play/Pause/Stop.
EngineRuntime.exe загружает проект и его Game.dll; EngineLauncher.exe управляет
проектами, версиями и запуском. Учебные игры также имеют отдельные exe.
Не следует принимать исторические описания каркаса 032 за состояние выпуска.

## 3. Сборка и запуск

Нужны Visual Studio C++ Build Tools и Windows SDK. Скрипты определяют установленный
v145/v143; Release SDK отдельно собирается базовым v142 и проверяется на совместимость.
Для сборки Editor нужен Qt MSVC x64 в `Editor/ThirdParty/Qt6.7` или `QTDIR`.
Для полного импорта моделей нужен Assimp из vcpkg. Готовый пакет уже содержит runtime
зависимости; компилятор нужен только для создания и изменения C++ проектов.

```powershell
./Engine/build.ps1 -Configuration Release -Target All -EnableAssimp $true
./Game/build/x64/Release/EngineLauncher.exe
```

Отсутствие Qt допускается скриптом сборки, но такой результат не является полным
пакетом редактора. Для командлетов отдельно собирайте EditorModule с `-EngineCommandlet`
через `Engine/BuildSupport/Invoke-MSBuild.ps1`.

## 4. Собственный проект и SDK

В лаунчере создайте проект в новой папке. `Project.json` задаёт модуль, Content и
startupScene; `Engine.lock.json` закрепляет версию. Для C++ подключите код через
интерфейс редактора либо CLI `--enable-code`. Release SDK находится в `Runtime/SDK`:
заголовки, Engine.lib, генератор компонентов, шаблоны MSBuild, примеры и справка.
Не смешивайте заголовки и библиотеку разных выпусков. Используйте штатные скрипты
проекта для выбора toolset и проверки окружения.

Маршрут: [CLI](LAUNCHER-CLI.md) → [C++ проект](CODE-PROJECTS.md) →
[макросы свойств](PROPERTY-MACROS.md) → [API](API-REFERENCE.html).
Рабочие примеры: `tutorial/examples` и `api-reference/examples`.

## 5. Сцена и данные

Поддерживаются JSON v1/v2/v3. Тип модели — `Engine.Model`, путь — `assets.model`.
Проектные классы имеют собственные ключи типа и кодеки `projectData`.
Сохранение непустого `projectData` требует v3 даже после загрузки старого файла.
Версия не служит причиной автоматически переименовывать тип объекта.

Play использует отдельное состояние; Stop возвращает состояние редактирования.
Редактирование объекта и редактирование общего ресурса материала — разные операции.
Изменённый материал сохраняйте отдельно. Подробнее: [сцены](SCENE-JSON.md),
[материалы](MATERIALS.md), [обновления ресурсов](ASSET-UPDATES-AND-PROPERTIES.md).

## 6. Обновление кода и ресурсов

C++ проект поддерживает сборку и reload через штатный рабочий процесс редактора.
Старый модуль остаётся рабочим при ошибке компиляции; успешная перезагрузка должна
сохранять согласованное состояние. Не заменяйте DLL вручную внутри работающего процесса.
Импорт/переимпорт ресурсов, reload C++ и загрузка сцены проверяются отдельно.
Подробности: [надёжный рабочий процесс](RELIABLE-WORKFLOW.md), [версии](ENGINE-VERSIONS.md).

## 7. Работа над редактором

Core не зависит от QWidget/Host/UI; Host не включает панели UI. UI отправляет команды,
Host выполняет их на стороне движка и публикует snapshot. Указатели в snapshot
действительны только пока жив сам snapshot. Явный `objectId` команды нельзя заменять
текущим выделением: оно может уже измениться к моменту выполнения.

В 0.3.0 инспектор, Scene.ReplaceModel и Host используют один `IsModelObjectType`.
Замена модели создаёт одну точку Undo. Примитив блокируется, неизвестный тип получает
собственную диагностику. Исходный файл сцены не переписывается до Save.

## 8. Внедрение редактора: согласованный контракт

Editor.dll размещается рядом с EngineRuntime.exe. Между DLL используется C ABI;
не передавайте Qt или STL-объекты через границу модулей. Базовые версии выпуска:
Module API 5, Edit API 6, адаптеры Edit 4/5/6. Новые возможности проверяются через
версионированные расширения, а не через предположение об их наличии.

Контракты: [Edit session](EDIT-SESSION-API.md), [Scene module](SCENE-MODULE-API.md),
[Core Scene](SCENE-EDITOR-API.md). После обновления проверяйте путь реально загруженного
Editor.dll и комплектность зависимостей, а не только название папки проекта.

## 9. Проверки перед передачей

```powershell
./Editor/tools/test-regression.ps1 -Configuration Release -Full
./Editor/tools/test-model-replacement.ps1 -Configuration Release
./Engine/tests/run-viewport.ps1 -Configuration Release
```

Пакет дополнительно проверяется из собственного каталога: запуск всех игр,
редактор, создание проекта, подключение C++, сборка и запуск с его SDK.
Состав и результаты конкретной поставки — `RELEASE-MANIFEST.json` и `VALIDATION.json`
в корне пакета; контрольные суммы — `SHA256SUMS.txt`. Исторические runtime отдельно.

Ограничения и ручной сценарий: [релиз 0.3.0](RELEASE-0.3.0.md).
