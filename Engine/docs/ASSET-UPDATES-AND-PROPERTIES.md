# Переимпорт ресурсов и свойства классов

Доступно с 2026.10.31.1. Игровой модуль должен поддерживать необязательное
расширение `Engine.Editor.Authoring` v1. Старые DLL продолжают работать;
для новых команд C++-проект нужно пересобрать SDK этой версии.

## Ресурсы

В проводнике редактора нажмите правой кнопкой на модель или текстуру:

- **Переимпортировать…** — выберите исходный файл. При обычном импорте путь
  запоминается в соседнем `.source.json`, поэтому диалог откроется у исходника.
  Для старых импортов или перенесённого исходника укажите новый путь.
- **Переместить / переименовать…** — задайте новый путь относительно Content.
  Текстуру и `.mat` можно переименовать. Для модели перемещается целая папка
  зависимостей: например, `Models/Tree/tree.glb` → `Models/Oak/tree.glb`.
  Имя основного файла модели сохраняется; целевая папка должна быть новой.
  Внутренние текстуры и материалы модели по отдельности не перемещаются:
  переносите папку модели, чтобы сохранить ссылки glTF/FBX и метаданных импорта.

Переимпорт сохраняет путь `/Game`, размещение объектов, назначенные материалы
и существующие правки `.mat`, `.hlsl`, `.import.json`. Новый исходник должен
давать тот же формат; BLEND по-прежнему преобразуется в GLB через Blender.
Новая геометрия/текстуры читаются с диска и текущая сцена пересоздаётся.

Перенос обновляет ссылки в открытой сцене, всех `*.scene.json` внутри Content
и относительные ссылки текстур/шейдеров в `.mat`. Строки `/Game/...` в
`projectData` также обновляются. Пути, зашитые в C++, внешние сцены и собственные
бинарные форматы автоматически не изменяются. Храните сцены проекта в Content.
Не меняйте одновременно один проект в нескольких редакторах: блокировка
предотвращает параллельные операции ресурсов, но не редактирование другой сцены.

Команды доступны в Edit. Окна материалов сначала закрываются с обычным
предложением сохранить правки. После успешной операции история Undo сцены
очищается, сцена помечается изменённой. Проверка ошибки импорта/сцены откатывает
файлы и сохраняет открытую сцену. Прежние файлы и описание операции остаются
в `.painengine/AssetBackups/<операция>`; это резервная копия для ручного
восстановления, не отдельный Undo ресурсов и не автоматическое восстановление
после выключения питания. Каталог резервных копий автоматически не очищается.

## Сворачиваемый инспектор

Общие данные, трансформация, отображение, свет, параметры персонажа и поля
класса находятся в разделах. У трансформации есть подразделы «Позиция»,
«Поворот», «Масштаб». Нажатие заголовка сворачивает раздел. Состояние сохраняется
между выборами объектов и перезапусками редактора, для полей класса — по типу.

## Объявление свойств C++

Добавьте компоненту независимый интерфейс `EditorPropertyProvider` из
`Engine/Components/EditorProperties.h`. Метод `DescribeEditorProperties()`
возвращает описание полей. Данные остаются в существующих
`SaveProjectData()` / `LoadProjectData()`; автоматического обхода полей C++ нет.

```cpp
std::string DescribeEditorProperties() const override {
    return R"({"version":1,"fields":[
      {"path":"/speed","type":"number","label":"Скорость",
       "group":"Поведение/Движение","min":0,"max":20,"step":0.5},
      {"path":"/enabled","type":"bool","label":"Включено","group":"Поведение"},
      {"path":"/mode","type":"enum","label":"Режим","options":[
        {"label":"Стоять","value":"idle"},{"label":"Идти","value":"walk"}]},
      {"path":"/target","type":"object","label":"Цель"},
      {"path":"/icon","type":"asset","label":"Иконка","extensions":[".png"]}
    ]})";
}
```

`path` — JSON Pointer существующего значения, включая вложенные объекты и
массивы; `/version` не редактируется. Типы: `number`, `integer`, `bool`, `enum`,
`object`, `asset`, `string`. `group` разделяется `/`; можно задать `description`,
`readOnly`, `decimals`, `objectType` для фильтра ссылок. Числа без указанного
диапазона ограничены ±10¹²; строки — 4096 символами; описание — 256 полями.
Для `object` пустая ссылка — ID 0, для `asset` — пустая строка. Ресурсы должны
существовать в Content; сохранённое значение — `/Game/...`.

Редактор отправляет одно значение. Игровой модуль проверяет объявленный тип,
диапазон, enum и наличие ссылки, затем передаёт полный обновлённый документ
в `LoadProjectData`. Codec обязан проверять данные, не оставлять частичное
изменение при ошибке и уметь загрузить собственный сохранённый документ.
Изменения участвуют в обычных Undo/Redo, сохранении и копировании в Play.
`RemapProjectReferences` по-прежнему обязателен для ссылок на объекты при
загрузке/дублировании; объявление `type: object` не заменяет этот контракт.

Для независимого Object добавьте статический
`ProjectObjectAdapter<T>::DescribeEditorProperties()`. Новый шаблон C++-проекта
уже содержит пример: `RotatingCube`, раздел `Behavior/Rotation`, скорость
вращения и переключатель Enabled. Существующие исходники шаблон не переписывает.

## Проверка

```powershell
./Engine/tests/authoring/run.ps1 -Configuration Release
```

- `AuthoringTests.cpp`: типы, диапазоны, отказ codec, Play read-only, переимпорт
  геометрии, сохранность материалов/размещения, перенос ссылок и откат.
- `EditorUiTests ... --authoring`: настоящие Qt-поля, вложенные разделы,
  сохранение свёрнутого состояния, переимпорт/перенос через очередь редактора.
- Обычные EditorUiTests проверяют прежние пользовательские сценарии.
