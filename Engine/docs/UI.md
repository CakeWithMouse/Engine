# Экранный интерфейс

Слой для того, что рисуется поверх кадра: панели, полосы и текст. Код — `Engine/Include/Engine/UI`, `Engine/Source/UI` и компонент `UIComponent`. Пример использования — HUD в сцене `Game/Battle`.

Это интерфейс **игры**, который рисует движок. Интерфейс редактора — отдельная вещь на Qt, он живёт в `Editor/` и к этому слою отношения не имеет.

## 1. Из чего состоит

| Класс | Что это |
|---|---|
| `UIElement` | база: прямоугольник, видимость, метод `Build` |
| `UIPanel` | заливка, по желанию с рамкой |
| `UILabel` | строка текста |
| `UIBar` | значение от 0 до 1 в виде заполненной дорожки |
| `UIComponent` | компонент сцены: владеет элементами и рисует их |
| `FontAtlas` | шрифт, растеризованный один раз в текстуру |

```cpp
auto hud = std::make_unique<UIComponent>();
hud->AddPanel({UIAnchor::TopLeft, 16, 16, 296, 166}, glm::vec4(0.05f, 0.06f, 0.07f, 0.62f));
UILabel* fps = hud->AddLabel({UIAnchor::TopLeft, 32, 56}, "", glm::vec4(1.0f));
UIBar* load = hud->AddBar({UIAnchor::TopLeft, 32, 150, 264, 10});
game.RegisterComponent("Hud", hud.release());

// дальше каждый кадр меняется только содержимое
fps->SetText("8.1 мс   123 FPS");
load->Fill = 0.48f;
```

Элементы создаются один раз, в кадре у них меняется только текст и значения. `SetText` принимает UTF-8 и переводит его в широкие символы сам.

## 2. Привязка к краям

Координаты задаются в пикселях от якоря (`UIAnchor`), а не от левого верхнего угла экрана. Якорь справа или снизу отсчитывает внутрь, поэтому при изменении размера окна счётчик остаётся в своём углу, а не уезжает за край. Пересчитывать при resize ничего не нужно: разрешение берётся в момент построения вершин.

## 3. Как это рисуется

Один проход, одна текстура, **один draw call** на компонент — сколько бы в нём ни было панелей и букв.

- **Шрифт.** `FontAtlas` растеризует глифы через GDI (`CreateFontW` + `TextOutW` в DIB) и загружает результат текстурой. Отсюда хинтинг, сглаживание и кириллица без шрифтового файла в репозитории и без библиотеки раскладки. Диапазоны: ASCII, А-я, Ё и ё — 161 глиф при 18 px умещается в атлас 512×128.
- **Белый блок.** В углу атласа лежит сплошной белый квадрат. Панель и полоса берут его текселем, буква — свою ячейку. Поэтому и заливки, и текст идут одним материалом, одним буфером и одним вызовом.
- **Вершины.** Пиксельная координата лежит в `POSITION.xy`, координата атласа в `POSITION.zw`, цвет в `COLOR`. Это ровно формат `VertexFormat::Primitive`, который в движке уже есть, так что своего input layout слою не понадобилось.
- **Шейдер** `Engine/Content/Shaders/UI.hlsl` переводит пиксели в clip space и умножает цвет элемента на покрытие из атласа.

## 4. Где в кадре

**Компонент обязан сам поставить свои шейдеры в контекст.** `Game::BindComponentShaders` только записывает пару в компонент — `VSSetShader` и `PSSetShader` вызывает `Render`. Без этого компонент рисуется материалом, оставшимся от предыдущего прохода, и экранные координаты уезжают через 3D-преобразование по всему кадру.


`Game::RenderUI()` идёт последним — после непрозрачной геометрии, неба, частиц и прозрачности, в обоих путях (forward и deferred). Компонент помечает себя `IsScreenSpaceUI()`, и остальные проходы его пропускают: интерфейс не отбрасывает тень, не отсекается пирамидой видимости и не участвует в G-буфере.

Состояния компонент ставит сам: альфа-смешение, глубина выключена целиком (ни теста, ни записи), отсечение граней выключено. После прохода `RenderUI` возвращает состояния движка на место.

## 5. HUD в сцене Battle

`Battle.exe` показывает две панели:

- слева — время кадра, FPS, число вызовов отрисовки, сколько техники отсечено, и полоса загрузки кадра относительно бюджета 60 FPS (краснеет за 16,7 мс);
- справа — сколько техники пришлось на каждый уровень детализации, с теми же цветами, что у раскраски по **F6**.

Время кадра сглажено скользящим средним: без него цифра дёргается и её невозможно прочитать.

Клавиша **F7** убирает панели, ключ `--no-hud` не создаёт их вовсе. На замерах HUD стоит один draw call (19 → 20 в сцене по умолчанию).

## 6. Чего слой не делает

- не принимает ввод: ни нажатий, ни наведения, ни фокуса — это вывод;
- одна строка на `UILabel`, без переноса и без выравнивания по центру;
- один шрифт на компонент, без курсива и полужирного в одной строке;
- без обрезки по родителю: элемент, вылезший за панель, рисуется поверх;
- атлас строится при первом кадре, смена размера шрифта в рантайме перестраивает его целиком.
