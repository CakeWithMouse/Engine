# ИИ: общий инструмент и стратегический слой

Дата: 2026-11-13. Статус: реализовано, этапы 1–10 и 12. Этап 11 заменён: графического редактора нет, автомат выбирается по имени из C++. Код: `Engine/Include/Engine/AI`, `Engine/Source/AI`; тесты: `Engine/tests/ai`; живой пример: `Battle --ai`. Схемы: [AI-DESIGN.html](AI-DESIGN.html). Как писать ИИ на C++: [AI-CPP-GUIDE.md](AI-CPP-GUIDE.md).

## Коротко

1. **Основа — общий инструмент по образцу Unreal.** Иерархическая state machine как StateTree, контроллер, память, восприятие, поиск точек, навигация и отладка. Он подходит для любого жанра: стражник, турель, босс, сценарий миссии.
2. **Стратегия — слой поверх него.** Отряд является обычным контроллером с теми же автоматами и задачами. Добавляются только поле направлений, слоты и лёгкие бойцы-экземпляры.
3. **ИИ работает из коробки.** Подсистема встроена в движок, игра ничего не объявляет: наследуется от `AiCharacter` и описывает автомат.
4. **C++ и файлы `.fsm`.** Автомат собирается кодом или загружается из файла,
   который редактируется в окне ИИ. Оба пути используют один исполнитель.
   `AiCharacter` выбирает зарегистрированный автомат по имени либо ресурс `.fsm`.
   Формат и встроенные блоки описаны в [AI-FSM.md](AI-FSM.md).
5. **Механизмы лежат в Engine, правила — в игре.** Движок не знает, что такое враг или мораль.

## Что изменилось по сравнению с первой версией

- Основой стал общий инструмент. Плоский автомат заменён иерархическим, добавлены задачи, условия, службы, события, контроллер, восприятие и поиск точек.
- `AiBrain` убран: его место занял `Ai::Controller`.
- **Исправлена ошибка первой версии.** Подсистема `BattleAi` с `ENGINE_SUBSYSTEM()` в `Battle` не заработала бы: проект не подключён к генератору. Подсистема теперь встроена в `GameSession`.
- По умолчанию автомат думает каждый кадр, как в Unreal. Реже — по настройке, отряды — 5 раз в секунду.

## Что повторяем из Unreal

StateTree выбран образцом потому, что это и есть иерархическая state machine: она соединяет состояния и переходы с выбором как в Behavior Tree.

| Unreal | У нас | Отличия |
|---|---|---|
| AIController | `Ai::Controller` | Обычный объект C++, как `CharacterController` |
| StateTree: состояния, Enter Conditions, задачи, переходы | `Ai::StateMachine` | Те же правила выбора и порядка проверки |
| Linked state, Subtree | `Linked(machine)` | Вставка другого автомата |
| Evaluators, Global Tasks, BT Services | `Ai::Service` | Одно понятие вместо трёх |
| Blackboard | `Ai::Blackboard` | Типизированные ключи проверяет компилятор |
| Property binding | Ключи памяти в параметрах задач | Проще, без привязки свойств |
| AI Perception: зрение, слух, урон | `Ai::Perception` | Настройка в коде или свойствах |
| Generic Team Agent | `Ai::Team`, `Ai::Attitude` | |
| EQS: генераторы и тесты | `Ai::Query` | Основные генераторы и тесты |
| NavMesh | `NavGrid` | **Плоская сетка: один уровень, без этажей** |
| NavMeshBounds, NavModifier | `NavVolume` | Компонент сцены с тремя режимами |
| PathFollowing, MoveTo | `Controller::MoveTo`, `Ai::Tasks::MoveTo` | |
| Crowd, RVO | Обход по прогнозу сближения через `SpatialHash` | Проще RVO, ORCA при необходимости |
| Smart Objects | `Ai::SmartObject`, задача `UseSmartObject` | Места с захватом |
| Gameplay Debugger, Visual Logger | `Ai::Debugger`, журнал переходов | Запись в файл не планируется |
| Mass | `Ai::Group`, поле направлений | Только для отрядов |
| Редактор StateTree | Автомат по имени из C++ (`Ai::RegisterMachine`) | Графический редактор отложен |
| Behavior Tree | Отдельной системы нет | Выбор детей в автомате закрывает эту задачу |
| Blueprint | **Нет** | Только C++, вместо этого есть Hot Reload |
| NavLink, прыжки, несколько этажей | **Нет** | Нужна другая навигация, см. решение 5 |

## Слои

| Слой | Что входит | Кто пишет |
|---|---|---|
| Игра, `Game/<Name>/Source` | Юниты, свои задачи и условия, автоматы, правила | Автор игры |
| Стратегия, `Engine/AI` | `Ai::Group`, `FlowField`, слоты, бойцы-экземпляры | Движок |

Стратегия зависит от общего слоя, но не наоборот. Игра без отрядов просто не использует `Ai::Group`.

Владелец всего — `Ai::World` внутри встроенной подсистемы. Новый тип добавляется в `GameSession::Initialize`, поэтому ИИ есть в каждой игре, в том числе без генератора. Пока нет ни одного контроллера, тик выключен и ничего не стоит.

## Иерархический автомат

Поведение описано подробно в [руководстве](AI-CPP-GUIDE.md). Здесь только решения.

- **Определение и исполнение разделены.** `Ai::StateMachine` неизменяем и общий для всех юнитов этого типа. У контроллера лежат только активная цепочка состояний и данные задач. Так устроен и StateTree: это экономит память и не даёт юнитам влиять друг на друга.
- **Методы задач `const`.** Данные юнита передаются отдельным параметром `Data&`, поэтому компилятор не даст записать их в общий объект. Проверено: такой код не собирается.
- **Память для `Data` выделяется один раз на контроллер.** Смещения считаются при сборке автомата, вход в состояние не вызывает аллокаций.
- **Правила выбора взяты из StateTree.** Родитель сам не выполняется и входит в первого ребёнка, разрешившего вход. Переходы проверяются от листа к корню. Задачи состояния работают одновременно, первая завершившаяся завершает состояние.
- **Смена состояния только через переходы.** Задача не может переключить автомат напрямую, поэтому логика видна в одном месте.
- **Автомат не требует тела.** Он работает на персонаже, турели, отряде и без объекта сцены.

## Контроллер и тело

`Ai::Controller` — это мозг. Он запускает автомат, хранит память и восприятие, принимает `MoveTo`. Тело — то, чем он управляет.

| Тело | Как создаётся | Ходит |
|---|---|---|
| `AiCharacter` | Наследник `Character`, контроллер создаётся в `BeginPlay` | Да, через `Character::Move` |
| Любой `GameComponent` | `world.Spawn(*this)` | Нет: статус `Unavailable` |
| Нет тела | `world.SpawnDirector()` | Нет |
| Отряд | `world.CreateGroup()` | Да, бойцы через `SetInstancePosition` |

`AiCharacter` регистрируется в каталоге движка рядом с `Gameplay.Character`. Контроллер хранит ID тела, а не указатель, как и `CharacterController`. Персонаж игрока становится целью через `AddTarget`: его видят и обходят, но ИИ им не двигает.

## Память, восприятие, поиск точек

**Память.** Значения по имени и типу. `Ai::ObjectRef` хранит ID объекта, поэтому при загрузке его перевязывает `SaveArchive::Reference`.

**Восприятие.** Кандидаты берутся из `SpatialHash`, поэтому юнит проверяет только соседей. Проверки видимости идут по кругу, не больше N за кадр. По умолчанию видимость считается по сетке, для точных сцен можно включить `Scene::Raycast`. Результат попадает в память и приходит событием.

**Поиск точек.** `Ai::Query` создаёт кандидатов, отсеивает и оценивает. Точек за кадр не больше N, результат приходит в задачу `RunQuery`.

**Smart Objects.** Объект сцены со слотами и резервированием, чтобы два юнита не сели на одну лавку. Это поздний этап, потому что сейчас нет сценария, где они нужны.

## Навигация

**NavGrid.** Плоская сетка в XZ с размером клетки на сцену. В клетке два байта: стоимость прохода (255 — нельзя) и расстояние до препятствия, чтобы широкий юнит не лез в щель. Сетку задают компоненты `NavVolume` или код. Изменение в игре повышает `version` сетки, пути перепроверяются.

**Одиночный юнит: A\*.**

1. `MoveTo` ставит запрос в очередь. За кадр обрабатывается не больше N узлов, поиск может занять несколько кадров.
2. Поиск идёт по 8 соседям без срезания углов.
3. Если цель недостижима, юнит идёт к ближайшей достижимой клетке и получает статус `Unreachable`.
4. Ломаная спрямляется по прямой видимости.
5. Нет продвижения — новый запрос. Несколько неудач подряд дают `Stuck`.

Состояния видят только `MoveTo` и статус. Если позже понадобится navmesh, заменится внутренность `Ai::World`, а не игровой код.

## Стратегический слой

**Отряд.** `Ai::Group` наследуется от `Ai::Controller` и переопределяет `MoveTo`. Стандартная задача `Ai::Tasks::MoveTo` работает с ним без изменений. Автомат один на отряд, поэтому 30000 бойцов в отрядах по 100 дают 300 автоматов. Боец — запись в массиве с позицией, скоростью и радиусом, без контроллера.

**Поле направлений (flow field).** Считается волной от цели и хранит в каждой клетке направление к ней. Боец читает его за O(1).

1. `MoveTo` рассчитывает слоты на месте назначения. Занятые слоты сдвигаются на ближайшую проходимую клетку.
2. Поле берётся из кэша по ключу «цель, класс размера, версия сетки» или считается порциями.
3. Боец интерполирует направление между клетками, иначе будет дёргаться на границах.
4. Как только свой слот виден напрямую и близко, боец уходит с поля к слоту. Без слотов все рвались бы в одну клетку.
5. Дошедший боец засыпает, но остаётся препятствием для соседей.

**Цена растёт с числом разных целей.** Поле на всю сетку `Battle` — около полумиллиона клеток, и 300 разных целей стоили бы 145 миллионов клеток. Что сделано:

- один приказ нескольким отрядам — одно поле, слоты разводят их по местам; поле, которое ещё не начали строить, растёт до общего окна;
- цель в ключе кэша округляется до клетки 16 м;
- поле считается только в окне вокруг отряда, слотов и цели с запасом 64 м. Если меньше половины бойцов может дойти внутри окна, окно растёт вчетверо, в конце — до всей сетки;
- стрелки ставятся прямо во время волны, поэтому построение целиком укладывается в бюджет: 25 000 клеток за кадр.

На замере 324 отряда держали 322 поля, вместе 23.7 МБ.

**Избегание соседей** общее для всех тел. Юнит берёт соседей в радиусе «свой размер + чужой + путь за секунду» из `SpatialHash`: выталкивается из касания и уклоняется, если по прогнозу сблизится. Ровно встречные уходят каждый вправо. Стоящих не толкают, их обходят. В занятую клетку войти нельзя: юнит скользит вдоль стены или стоит. Смещение за кадр не больше половины клетки. Боец отряда выбирает скорость не чаще 15 раз в секунду, по очереди с соседями.

## Порядок в кадре

`Ai::World::Tick` вызывается из встроенной подсистемы внутри `Session->Tick`. Цикл кадра не меняется.

1. Снять позиции и убрать контроллеры удалённых объектов.
2. Пересобрать `SpatialHash`.
3. Обновить восприятие в рамках бюджета.
4. Подумать: службы, задачи, переходы.
5. Продолжить A*, поля и запросы в рамках бюджета.
6. Посчитать желаемую скорость.
7. Применить избегание.
8. Записать результат в тела.

Всё идёт в игровом потоке: подсистемы привязаны к потоку владельца. Исключение из задачи идёт существующим путём: редактор уходит в Pause, runtime сообщает об ошибке кадра.

## Время

`dt` — это реальное время, умноженное на `SimulationTimeScale`. Значение 1.0 ставят проекты и редактор, а `Battle` запускается своим `Main.cpp` и остаётся на 7.8. Там одна «секунда» ИИ равна примерно 0.13 реальной, а скорость 9 м/с на деле становится 70 м/с.

Решение: все таймеры ИИ считаются только по `dt`, а режим `Battle` с ИИ ставит `SetSimulationTimeScale(1.0f)`. Ограничение смещения за кадр защищает от большого шага и при другом масштабе.

## Жизнь объектов и сохранение

- `OnSceneClosing` очищает контроллеры. Подсистема переживает смену сцены.
- Удалённое тело обнаруживается на первом шаге кадра, контроллер убирается сам.
- Как и у других подсистем, hot reload состояние не переносит. Контроллеры уничтожаются до выгрузки DLL.

**Сохраняем:** активные состояния по именам, память, приказы, восприятие, состав отрядов, свои поля контроллера. **Не сохраняем:** `Data` задач, пути, поля, `SpatialHash`, `NavGrid`.

После загрузки автомат возвращается в те же состояния и заново вызывает `Enter`, а сетка и пути строятся заново в `OnSaveGameLoaded`. Это простое и понятное правило: `Wait` начнёт отсчёт сначала, зато задачам не нужен код сохранения. Позиции уже сохраняет движок, у `InstancedMeshComponent` при этом лимит 100000 экземпляров на компонент.

## Редактор автоматов (отложен)

Решение от 2026-11-13: графический редактор пока не нужен, всё делается в C++. Вместо файла есть автомат по имени: `Ai::RegisterMachine("Guard", фабрика)` или `ENGINE_AI_MACHINE`, а у `AiCharacter` свойство «Автомат (имя из C++)». Ниже — набросок на случай, если редактор понадобится. Он не мешает коду: `MachineBuilder` и файл дали бы один объект.

```json
{
  "version": 1,
  "name": "Guard",
  "states": [
    {"name": "Patrol", "children": [
      {"name": "Walk",
       "tasks": [{"type": "Ai.FollowRoute"}],
       "transitions": [{"to": "Rest", "on": "succeeded"}]}
    ]}
  ]
}
```

Что потребуется:

- **Файл `.fsm`:** JSON с версией, как `.mat`, загрузка и проверка ошибок, распознавание в браузере файлов.
- **Каталог задач:** `ENGINE_AI_TASK` и `ENGINE_AI_CONDITION` в `ComponentGenerator`, поддержка `ENGINE_PROPERTY` вне компонентов.
- **Окно редактора:** дерево состояний и граф переходов. Граф материалов — поток данных, поэтому основу виджета придётся дорабатывать.
- **Отладка в Play:** подсветка активного состояния через Edit session API.

Для подсветки в Play понадобится новое расширение Edit session API: игра идёт в модуле игры, редактор видит её только через этот интерфейс.

| 10000 | 120 | 1.36 мс | 1.35 | 1.88 | 2.90 | 4.9 мс |
| 30000 | 324 | 4.15–4.19 мс | 4.2 | 5.8–5.9 | 6.9–7.2 | 11–12 мс |

Значения для 30000 — без первой секунды. Первый кадр стоит 15 мс: тогда один раз считается карта расстояний до препятствий.

- **На что уходит время при 30000 бойцов:** движение и обход 3.0 мс, тела и сетка соседей 0.83, поля направлений 0.19, решения 0.05, восприятие 0.01.
- **Поведение за 60 секунд:** 301 марш дошёл, 0 провалились, 39 прервал враг.
- **`Battle` в Release, 30000 машин:** `ai_ms` = 2.96 мс, медиана кадра CPU 3.15 мс без ИИ и 5.33 мс с ИИ. Кадров больше 60 в секунду, а перепланировка привязана ко времени, поэтому за кадр работы меньше, чем на стенде.
- **Память:** сетка 756 × 756 — 0.6 МБ стоимости и 2.3 МБ расстояний до препятствий. Бойцы — 72 байта, 2.2 МБ на 30000. Поля — до 23.7 МБ.

**Как получили 4 мс из 69.** Первый замер дал 69 мс. Оптимизировали по профилю: в стенде есть `--profile`, сэмплирующий профилировщик с разбивкой по строкам.

1. `SpatialHash` стал плотной сеткой: ряд клеток лежит в памяти подряд, позиции — отдельным массивом, буферы живут между кадрами.
2. Боец выбирает скорость не чаще 15 раз в секунду, по очереди (`Budget::crowdReplanInterval`), а движется каждый кадр.
3. Свободная прямая до слота запоминается и перепроверяется изредка. Раньше на эту проверку уходило 30% времени.
4. Проходимость спрашивается только на переходе в другую клетку. `Group::Size()` и самый большой радиус посчитаны заранее.
5. Стрелки поля ставятся во время волны: раньше проход по окну вне бюджета давал кадры по 42 мс. Проходимость клеток окна кэшируется, а бюджет снижен со 100 000 до 25 000 клеток за кадр.

Дальше, если понадобится запас: распараллелить обход соседей или укоротить горизонт прогноза. Второе меняет поведение, поэтому только с проверкой на глаз.

## Почему не иначе

| Вариант | Почему не сейчас |
|---|---|
| Отдельный Behavior Tree | Две системы вместо одной. Иерархический автомат закрывает выбор поведения, и вы выбрали state machine |
| Плоский автомат | Переходы размножаются: «умер» пришлось бы писать из каждого состояния |
| Задачи с обычными полями и копией на юнита | Проще писать, но память растёт с числом юнитов, а ошибка с общими данными не ловится |
| Navmesh (Recast/Detour) | Сильнее на сложной геометрии, но рельефа нет, это новая зависимость, а толпе всё равно нужна сетка |
| A* на каждого бойца | 30000 поисков на один приказ |
| Логика в `Character::Tick` | Порядок зависит от имён, нет общего бюджета, толпа не покрыта |
| Каждый боец — `Character` | Объект сцены со своей отрисовкой и обновлением, на тысячах не работает |
| ECS | Правила проекта просят его избегать, плотного массива внутри `Ai::World` достаточно |
| Потоки | Один поток уложился около 4 мс на 30000. Если нужен запас, распараллеливается обход соседей |

## Что изменено в существующем коде

- `GameSession::Initialize`: встроенная подсистема ИИ `Engine.Ai` первой в списке.
- `Engine.vcxproj`, `StandardTypes.h`: новые файлы, типы `Gameplay.AiCharacter`, `Gameplay.NavVolume`, `Gameplay.SmartObject`.
- `SaveArchive.h`: `Raw()` для чтения сохранённой секции контроллера.
- `Game.h`, `Game.cpp`, `GameTrace.cpp`: `DebugDrawLine` для линий на один кадр. Оверлей теперь рисуется и вне редактора, если есть линии. Его периодический лог остался только в редакторе.
- `Battle`: `BattleAi.cpp`, флаги `--ai`, `--ai-debug`, `--dump-at`, F9. Режим с ИИ ставит масштаб времени 1.0 и выключает `UpdateUnits`.
- `ComponentGenerator`, `Editor` и `Character` не менялись.

## Этапы

| Этап | Что сделано | Чем проверено |
|---|---|---|
| 1. Автомат | `StateMachine`, `Task`, `Service`, `Blackboard`, `MachineBuilder` | Тесты без сцены: порядок вызовов, выбор детей, переходы, события, `Linked`, ошибки в именах |
| 2. Навигация | `NavGrid`, `NavVolume`, A* по частям, спрямление | Обход стены, нет пути, широкий юнит, углы, стоимость |
| 3. Контроллер | `Ai::World`, встроенная подсистема, `Controller`, `AiCharacter`, `MoveTo`, стандартные задачи | Маршрут, погоня, застревание, удаление тела, турель |
| 4. Восприятие | Зрение, слух, урон, команды, память | Стражник из руководства целиком |
| 5. Сохранение | Контроллеры, память, приказы, отряды | Сохранить и загрузить, в том числе в другом процессе |
| 6. Отладчик | Линии, сводка, выбранный юнит | Тест и `Battle --ai-debug` |
| 7. Поиск точек | `Ai::Query`, генераторы, фильтры, оценки | Юнит выбирает укрытие, которое не видит враг |
| 8. Избегание | Прогноз сближения, разведение стоящих | Встречные, толпа в одну точку, стоящий не толкается |
| 9. Толпа | `Ai::Group`, поля в окне, слоты, `Battle --ai` | 100 бойцов через проём одним полем, расширение окна |
| 10. Замеры | Счётчики, стенд `--bench`, профилировщик, оптимизация | Раздел «Замеры», тест на 60 FPS |
| 11. Без редактора | Автомат по имени, свойство `AiCharacter` | Тест реестра и персонажа без своего класса |
| 12. Smart Objects | Места с захватом, `UseSmartObject` | Двое не занимают одно место, места освобождаются |

## Решения

1. **Редактор автоматов.** Пока не нужен, всё через C++ (2026-11-13).
2. **Базовый класс.** `Character`, от него `AiCharacter`.
3. **Толпа.** Ходит потоком и строится на месте. Марш в строю — следующим слоем, если понадобится.
4. **30000 бойцов.** Это цель и для ИИ, замер — около 4 мс на кадр.
5. **Рельеф и этажи.** Не делались: сетка плоская. Для этажей понадобится navmesh, игровой код это не затронет.
