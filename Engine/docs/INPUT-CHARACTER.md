# Ввод, персонаж и камера Play

Реализация выпуска `2026.10.27.0`. Физики, коллизий и анимаций здесь нет.

```text
Win32 Raw Input / события Qt viewport
  → Input::System: Game / Editor / UI
  → именованное действие + привязки (клавиши, сочетания, оси)
  → обработчик с Input::Scope и Input::Connection
  → CharacterController
  → Character::Move / CharacterController::UpdateCamera / SceneCamera
```

Qt обрабатывает интерфейс, текст и существующие редакторские команды. Их не
нужно повторно регистрировать в игровом коде. Только сфокусированный viewport
в режиме Play передаёт игровые события через необязательное C-расширение
`Engine.Viewport.Input` версии 1. Edit и Pause не отправляют их в игру.
Внутри игры контексты `Input::System` позволяют дополнительно приостанавливать
управление при открытии собственного меню. Приоритеты по умолчанию: UI 200,
Editor 100, Game 0; включён изначально только Game.

## Без кода

1. В палитре выберите **Персонажи → Персонаж → Добавить объект**.
   Трансформация редактируется обычным инспектором, скорость — через
   **Свойства объекта → Персонаж → Скорость**.
2. Откройте **Запуск → Настроить Play…**. Выберите персонажа, оставьте
   «Следовать за персонажем» и стандартное управление. Диалог создаёт один
   служебный объект «Настройки Play» и поддерживает обычные Undo/Redo.
3. Сохраните сцену. Нажмите Play и щёлкните viewport. WASD перемещает
   персонажа, ПКМ + мышь меняет обзор. Диагональное движение нормализуется.
   В редакторе Space зарезервирован для Play/Stop, P — для Pause/Resume;
   эти две клавиши без модификаторов не передаются игре. В standalone такого
   резервирования для персонажа нет.
4. Для отдельной камеры добавьте **Камеры → Камера Play**, задайте
   трансформацию и выберите её в диалоге. Она смотрит вдоль локальной -Z,
   учитывает родителя и остаётся фиксированной при стандартном управлении.
5. Снимите стандартное управление, если оно будет задано кодом, либо
   выберите «Без управления персонажем». Сам Character никогда не подписывается
   на клавиши. Без «Настроек Play» персонажи также остаются неуправляемыми.

Play использует отдельную копию сцены, контроллера и Player (камеры). Stop
уничтожает эту копию; возвращаются исходная сцена и редакторская камера.
Перемещение редакторской камеры через её API запрещено в Play/Pause.
Pause сохраняет изображение, но сбрасывает игровые действия. Фокус текстового
поля отключает игровой ввод, не останавливая остальную симуляцию.

| Возможность | Редактор без кода | C++ / SDK | В каталоге создания |
|---|---|---|---|
| Character | Создание, трансформация, скорость | Наследование, Move, BeginPlay, Tick, собственные данные | «Персонаж» и зарегистрированные конкретные наследники |
| Контроллер | Включение стандартной схемы, выбор персонажа | BindInput, Tick, UpdateCamera, Possess, SetEnabled | Не объект сцены; создаётся Game |
| Камера Play | Отдельный объект либо слежение, расстояние, высота, чувствительность | Наследник SceneCamera или полностью свой UpdateCamera | «Камера Play», зарегистрированные наследники |
| Настройки Play | Диалог с выбором объектов, Undo/Redo, сохранение | PlaySettings, ссылки по ComponentId | «Настройки Play» (один на сцену) |
| Действия и сочетания | Стандартные WASD/ПКМ | Любые имена, комбинации, оси, приоритеты и переназначение | Не объекты сцены |
| Подписчик | Не требуется | Обычный класс, компонент, персонаж, контроллер | Обычный класс — только при регистрации через существующий Object adapter |

## Правила событий

* `Pressed`: один переход из нуля в ненулевое значение. Повторные key-down ОС
  игнорируются. Короткое нажатие и отпускание между кадрами сохраняются в очереди.
* `Held`: один вызов за кадр при ненулевом значении, `deltaTime` — время симуляции.
* `Released`: переход к нулю; при отмене `cancelled=true` и `deltaTime=0`.
* `Axis`: каждый активный кадр, включая нулевое значение. Клавиатурные привязки
  суммируются, например D(+1) + A(-1) = 0. Обработчик сам ограничивает диапазон
  для произвольных шкал. MouseX/MouseY/Wheel суммируют дельты за кадр;
  колесо измеряется в делениях, дельты мыши не нужно умножать на время.
* Все клавиши `chord` должны удерживаться одновременно. `Control`, `Shift`,
  `Alt` означают любую сторону; доступны и Left/Right варианты. Лишние
  модификаторы разрешены. Сначала сравнивается приоритет контекста, затем
  `Binding::priority`, затем число клавиш в сочетании; равенство разрешается
  порядком регистрации привязок.
* `consume=true` резервирует клавиши для выигравшей привязки. Более специфичное
  Ctrl+K подавляет обычное K. Если K был нажат раньше Ctrl, K уже получил Pressed;
  при включении сочетания получает Released, сочетание — Pressed. При отпускании
  Ctrl оставшийся K снова становится активным. Уже доставленные события не
  отзываются. `consume=false` разрешает передачу менее приоритетным привязкам.
* Поглощение относится к привязке, а не к отдельному обработчику: все подписчики
  одного действия получают его в порядке регистрации. Отключённый подписчик
  не убирает привязку; для передачи управления меняйте контекст/привязки.
* У мышиной оси поглощается её источник, а клавиши chord служат условием.
  Поэтому MouseX и MouseY могут одновременно работать при удержании ПКМ.
* Bind/Unbind, смена контекста, Possess и SetEnabled сбрасывают текущие действия;
  удерживаемые клавиши подавляются до отпускания. Scope::SetEnabled отключает
  только владельца; после включения он снова видит текущее состояние.
* Reset отменяет действия и блокирует удержанные клавиши. ReleaseAll дополнительно
  забывает физическое состояние (потеря фокуса). Qt не пересылает автоповторы,
  поэтому после возврата фокуса требуется новое нажатие.

Все операции выполняются в потоке движка. Это не потокобезопасная шина.
Храните `Connection`, иначе временная подписка немедленно отключится.
`Scope` должен принадлежать объекту, на который ссылается обработчик, и быть
объявлен **после** используемых обработчиком полей. Его уничтожение делает
подписки недействительными, даже если Connection хранится снаружи. Нельзя
захватывать посторонний сырой указатель с меньшим временем жизни.
Уничтожать владельцев, отключать другие подписки и менять привязки из обработчика
можно. Уничтожать сам System во время его Tick нельзя. Рекурсивный Tick запрещён.

## Подписка обычного класса и сочетание

```cpp
class Commands {
    Input::Connection mark_;
    Input::Scope scope_; // разрушится первой
public:
    explicit Commands(Input::System& input) {
        input.Bind({"Mark", Input::Context::Game,
                    {Keys::Control, Keys::Shift, Keys::M}});
        mark_ = input.Subscribe(scope_, Input::Context::Game, "Mark",
            Input::Phase::Pressed, [this](const Input::Event&) { Mark(); });
    }
    void Mark();
    void Enable(bool value) { scope_.SetEnabled(value); }
};
// Позже: обработчик менять не требуется.
input.Unbind(Input::Context::Game, "Mark");
input.Bind({"Mark", Input::Context::Game, {Keys::Alt, Keys::K, Keys::J}});
```

Для игрового интерфейса сначала зарегистрируйте действия в `Context::UI`, затем
включите его и отключите `Context::Game`. При закрытии меню сделайте обратное.
Смена контекстов отменит накопленные действия, поэтому клавиша закрытия меню
не начнёт сразу двигать персонажа.

## Пользовательский компонент и Character

`GameComponent::BeginPlay()` вызывается один раз перед первой обработкой ввода
и Tick; в Edit/Pause он не вызывается. Подписывайтесь здесь, сохраняя вызов
непосредственного родителя. Для динамически добавленных объектов BeginPlay
произойдёт на следующей границе обновления. Отдельный EndPlay не нужен для
подписок: их освобождает RAII при уничтожении компонента/копии Play.

Компилируемые примеры обычного класса, компонента и наследника Character находятся
в [InputExamples.h](../tests/input/InputExamples.h). Компонент использует
`GetGame()->GetInput().Subscribe(...)` в BeginPlay; наследник Character может
так же вызвать `Move(direction, event.deltaTime)` в Held. Для такого персонажа
выключите стандартное управление, чтобы не подключать два обработчика движения.

## Замена контроллера и камеры

Через **Проект / C++ → Добавить C++ класс → Character** создайте наследника.
Он использует `ENGINE_COMPONENT`, как остальные компоненты. Генератор сохраняет
вызовы `Character::BeginPlay()` и `Character::Tick(deltaTime)`; для следующего
наследника — вызовы его непосредственного родителя. Конкретные классы с публичным
конструктором без аргументов появятся в «Классах проекта». Абстрактные классы
создавать нельзя, как и раньше.

```cpp
class MyController : public CharacterController {
public:
    using CharacterController::CharacterController;
    void BindInput() override {
        auto& input = game_.GetInput();
        input.Bind({"My.Forward", Input::Context::Game, {Keys::I}});
        connections_.push_back(input.Subscribe(inputScope_, Input::Context::Game,
            "My.Forward", Input::Phase::Axis,
            [this](const Input::Event& e) { forward_ = e.value; }));
    }
    // Можно также заменить Tick и UpdateCamera(Player&).
};
std::unique_ptr<CharacterController> MyGame::CreateCharacterController() {
    return std::make_unique<MyController>(*this);
}
```

Объявите этот override в MyGame.h. Выберите MyGame существующим механизмом
выбора Game проекта. В настройках Play оставьте управление включённым:
это вызывает виртуальный BindInput выбранного контроллера. В этом примере
стандартный BindInput намеренно не вызывается, поэтому WASD не регистрируется.
Tick базового контроллера можно сохранить или заменить полностью. Для полностью
иной камеры переопределите UpdateCamera; готовый пример камеры сверху и сборки
внешнего проекта находится в [run.ps1](../tests/input/run.ps1).

Possess принимает ID, проверяет типы, отменяет текущий ввод и не хранит указатель
на Character. Удаление персонажа безопасно; повторное назначение требует свежего
нажатия. Камера=0 означает следование. Если явно назначенную камеру удалили
во время Play, контроллер сохраняет последнюю позицию обзора.

## Сохранение и совместимость

Character хранит `moveSpeed`, PlaySettings — ID персонажа/камеры, флаг управления
и параметры обзора через существующий projectData schema 1. Сцена с ними
сохраняется в уже поддерживаемом формате 3. Ссылки переназначаются при загрузке
и создании Play-копии; удаление объекта в Edit очищает его назначение. Сцены
версий 1–3 без этих объектов продолжают загружаться. Unknown types по-прежнему
вызывают ошибку, а не исчезают при сохранении.

Базовые C API Module 5 / Edit 5 / Scene 3 не изменены. Ввод подключается через
опциональное расширение с проверкой версии/размера. Старые DLL без расширения
сохраняют прежнюю поддержку редактора. Изменился C++ ABI Game/GameComponent:
пользовательскую DLL следует пересобрать против SDK **2026.10.27.0**.

Используйте существующий путь лаунчера **Обновить копию проекта**: исходная папка
сохраняется, штатный шаблон заменяется только по известному SHA-256. В C++ копии
выполните **Перекомпилировать / Hot Reload** либо `Build.ps1 -Runtime <новый Runtime>`.
SDK проверяет Engine.lock.json, архитектуру, конфигурацию и toolset; новая DLL
активируется по новому build ID только после успешной сборки и проверки запуска.
Одна ручная замена Engine.lock.json не является обновлением проекта.
