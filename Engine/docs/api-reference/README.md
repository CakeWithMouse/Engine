# HTML API Reference

Откройте [API-REFERENCE.html](../API-REFERENCE.html) в браузере. Это самостоятельный файл:
CSS, JavaScript, примеры и снимки заголовков встроены, сервер и интернет не нужны.

Содержимое: карта классов, lifecycle, Scene/GameComponent, свойства, ввод и камеры,
трассировки, модели/LOD/анимация, материалы, UI, VFS, диагностика и граница ABI.
Поиск работает по описаниям и содержимому всех `.h`/`.inl` в `Include/Engine`.
Внутреннее построение геометрии и счётчик кадров рендера исключены из заголовков, поиска и скачиваемого HTML. Остальные private/protected разделы не являются вызываемым игровым API.
Тематические таблицы описывают выбранные основные методы и указывают на строки исходников.

## Обновление

Из корня репозитория, Node.js 18+ (без npm-зависимостей):

```powershell
node Engine/docs/api-reference/build.mjs
node Engine/docs/api-reference/build.mjs --check
```

- `content.mjs` — проверенные вручную объяснения и список основных методов.
- `examples/` — настоящие исходники; фрагменты извлекаются по `example:` маркерам.
- `build.mjs` — проверка наличия символов, ссылок и примеров; выдержки заголовков без внутренних операций построения геометрии,
  версия из `Engine/Version.json` и хеш снимка; формирование одного HTML.
- `app.js`, `style.css` — офлайн-поиск, маршрутизация, просмотр исходников, темы и печать.

`--check` завершается ошибкой, если HTML устарел. Проверка символов лексическая:
она не заменяет C++ компилятор и не выводит контракты автоматически. При изменении
поведения метода обновляйте его описание, а не только пересобирайте HTML.

`New-ProjectSdk.ps1` включает готовый HTML в `SDK/Docs` и примеры в
`SDK/Examples/ApiReference`. Node не требуется пользователю справочника и не добавлен
в зависимости сборки движка. Перед выпуском SDK обновите HTML и выполните `--check`.

## Проверка примеров

Поместите оба файла `examples/ReferenceComponent.h` и `examples/ReferenceExamples.cpp`
рядом в `Source` C++ проекта и соберите его штатным `Build.ps1` с SDK соответствующего
выпуска. Заголовок участвует в ComponentGenerator: методы свойств не нужно писать вручную.
Не добавляйте отдельно `main`; это код DLL проекта.

Примеры используют уникальные имена объектов. Функции AddCube/AddGround предназначены
для однократного создания; проверьте SceneResult перед использованием ID. Procedural
mesh из AddGround не имеет автоматического кодека сохранения геометрии. ClickAction
должен жить меньше Game; объект хранит Connection и Scope до конца подписки.

Проверка выпуска 2026.11.07.6: оба файла примеров скомпилированы в LearningLab
через экспортированный SDK, Release x64 / v143. Кандидат DLL прошёл штатную
валидацию, запуск и активацию. EngineTests: 70/70, EditorUiTests: 5161 проверка.
Полная сборка All с Qt и Assimp завершилась успешно. HTML проверен через
`build.mjs --check` и Edge в режиме file://: 40 разделов, 317 ссылок на объявления,
поиск и мобильная ширина. Генератор запрещает попадание закрытых методов
в описания, исходники и поиск.
Это не заявление о тестировании всех описанных функций движка.

Обложка `assets/painengine-cover.png` создана через встроенный image_gen, исходный
промпт сохранён рядом. Это иллюстрация, не скриншот движка. Картинка встраивается
в HTML как data URL: для просмотра не нужны сервер и отдельная папка assets.
