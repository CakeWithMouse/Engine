# Редактор и лаунчер: обновление интерфейса 2026-10-28

## Расположение команд

| Задача | Где искать |
|---|---|
| Создать или открыть проект, запустить игру/редактор | Основные кнопки лаунчера |
| Добавить C++, собрать проект | Лаунчер → Проект → C++ |
| Установить, закрепить версию, обновить копию | Лаунчер → Версии движка |
| Создать, открыть, сохранить сцену | Редактор → Сцена |
| Импорт модели или текстуры | Ресурсы и код → Импорт; также Сцена → Ресурсы |
| Undo, Redo, Duplicate, Delete | Правка; Duplicate/Delete также в контекстном меню иерархии |
| Play / Pause / Stop | Короткая панель сверху или меню Запуск |
| Назначить персонажа и камеру | Запуск → Настроить Play |
| Отдельное окно игры | Запуск → Запустить отдельным окном |
| Создание классов, сборка, список C++ типов | Проект → C++ |
| Показать закрытую панель | Вид |

Ctrl+D сохраняет дублирование. Delete работает в иерархии и не удаляет объект при редактировании текста. Существующие Ctrl+S, Ctrl+Z/Y, управление камерой, выбор объектов и Play остаются доступными.

## Добавление объектов и свойства

В панели «Сцена / объекты» блок «Добавление объекта» отделён от иерархии. «Категория» меняет только список объектов для размещения. Она не меняет тип выделенного объекта. Затем выберите объект, точку размещения и нажмите «Добавить объект».

Инспектор разделён на «Общие», «Позиция», «Поворот», «Масштаб» и «Визуал». Параметры света и персонажа появляются только для подходящего объекта. Скорость находится в разделе «Персонаж», а назначения для всей сцены — в настройках Play.

В карточке «Геометрия» путь модели доступен для чтения. «Выбрать модель» открывает поиск по ресурсам проекта и заменяет модель только у Engine.Model, сохраняя остальные данные объекта. Превращение примитива в модель заблокировано; добавьте отдельный модельный объект. Замена поддерживает Undo. Отдельные кнопки текстуры убраны из геометрии: текстуры настраиваются в слотах редактора материала. Неподходящий ресурс оставляет сцену прежней. Произвольный C++ компонент или Character не превращается в другой класс: его визуальное представление задаёт C++ реализация. Для нового модельного объекта есть «Сцена → Ресурсы → Добавить модель».

В актуальном интерфейсе добавляйте «Игрок» и задавайте управление/камеру в его свойствах. Без игрока Play сохраняет вид редактора. «Настроить Play» удалён из меню и панели; старые PlaySettings импортируются при загрузке.

Исторический интерфейс: «Камера Play» — объект с трансформацией для фиксированного обзора; доступна в категории «Камеры». «Настройки Play» — служебный сериализуемый объект с назначениями, а не игровой класс для размещения. Он скрыт из палитры, обычной иерархии и перебора Tab; создаётся и редактируется через «Настроить Play». Старые сцены с этой записью читаются без изменения формата. Для исправления старой сцены с несколькими такими записями включите «Вид → Служебные объекты сцены» и удалите лишние через контекстное меню.

## Браузер файлов

Выбранный по умолчанию режим — **Content и Source**. Content содержит сцены, модели и текстуры; Source — пользовательский C++ код. Переключатель **Весь проект** открывает полный корень: Binaries содержит DLL и результаты сборок, Intermediate — временные файлы генерации/компиляции; манифесты и служебные файлы также доступны здесь. Фильтр ничего не удаляет. Для кода используйте контекстное меню «Открыть в приложении».

«Типы C++ проекта» — каталог последней успешной сборки, а не меню создания всех объектов движка. Он показывает пользовательские Game, Component/Character и Object; встроенные примитивы больше не дублируются. Выбор Game задаёт игровую логику следующего Play и хранится в Content/ProjectGame.txt. Размещаемые типы доступны в категории «Классы проекта».

## Перекомпиляция и совместимость

Прежний runtime reload был отключён для новых code-проектов и edit-сессий; кнопка сборки перезапускала процесс. Теперь **Проект → C++ → Перекомпилировать / Hot Reload**, Ctrl+Alt+R, работает в Edit без закрытия окна.

1. SDK собирает DLL по новому уникальному пути и проверяет сохранённые сцены и запуск в отдельном процессе.
2. Поток движка сохраняет временный снимок текущей, в том числе несохранённой, сцены.
3. Кандидат восстанавливает этот снимок, ресурсы и viewport. Старый модуль остаётся жив до успешной проверки.
4. После замены редактор обновляет таблицы API, палитру, выделение и камеру. Старые объекты уничтожаются до выгрузки их DLL. Удерживаемые клавиши сбрасываются.

При успешной замене история Undo/Redo очищается: её снимки могут ссылаться на удалённые типы. Несохранённые правки остаются несохранёнными. Неизменная сборка сохраняет сессию и историю. Ошибка компиляции/проверки сохраняет прежнюю DLL. Ошибка восстановления текущей сцены сохраняет работающую сессию; редактор возвращает прежнее поле module в Project.json, если оно всё ещё указывает на его кандидата, и не перезаписывает посторонние изменения манифеста. Типичные причины отказа — удалённый класс или несовместимый кодек данных.

Это перезагрузка игровой DLL с восстановлением объектов из данных. Стек выполнения Play и произвольные несериализуемые C++ поля не переносятся. Перед сборкой остановите Play/Pause. Сборка из лаунчера обновляет файлы; открытый редактор подхватывает её через команду Hot Reload.

Выпуск 2026.10.28.0 устанавливается рядом с 2026.10.27.0, не подменяя его файлы. Для проекта выберите новый выпуск через «Версии движка → Закрепить версию проекта»; для преобразования старого шаблона используйте «Обновить копию проекта». Module/Edit ABI v5 и формат сцен не изменены. Добавлены необязательная служба EngineEditorReloadService через существующий getService и расширение Engine.Editor.Camera. Старый runtime предлагает перезапуск; старые игровые DLL могут перезагружаться без нового расширения камеры, но её положение сбросится. Чтобы сохранять камеру, пересоберите пользовательскую DLL актуальным SDK закреплённой версии. Исходники проекта мастер повторно не генерирует. Новые регистрации и данные продолжают использовать существующие аннотации и кодеки.

## Экран загрузки

При создании проекта, сборке из лаунчера и запуске редактора/игры показывается обложка с индикатором ожидания. Изображение встроено в лаунчер. Runtime сигнализирует готовность после первого кадра viewport. Для старых выпусков применяется совместимый поиск видимого окна. Ошибка запуска закрывает экран и выводит диагностику; тайм-аут не завершает пользовательский процесс. Во время создания проекта с C++ ошибка сборки сохраняет созданный проект и прежний модуль.

## Проверки

Основные команды из корня репозитория:

```powershell
./Engine/BuildSupport/Invoke-MSBuild.ps1 -Project ./Game/Launcher/EngineLauncher.vcxproj -Configuration Release -EnableAssimp
./Engine/BuildSupport/Invoke-MSBuild.ps1 -Project ./Editor/EditorModule.vcxproj -Configuration Release -EnableAssimp -EditorUiTest
./Game/build/x64/Release/Runtime/EditorUiTests.exe <тестовый-проект> <Runtime/EngineContent> [модель.obj | --code | --legacy | --reload]
./Engine/BuildSupport/Invoke-MSBuild.ps1 -Project ./Engine/tests/input/EditorReloadTests.vcxproj -Configuration Release -EnableAssimp
./Engine/build/x64/Release/EditorReloadTests.exe <Runtime> <пустая-тестовая-папка>
./Engine/BuildSupport/Invoke-MSBuild.ps1 -Project ./Game/Launcher/Tests/LauncherUiTests.vcxproj -Configuration Release
./Engine/build/x64/Release/LauncherUiTests.exe <preview.png>
```

UI-тесты изменяют свои фикстуры: используйте отдельные тестовые проекты, не рабочие сцены. Также доступны Engine/tests/input/run.ps1 -Sdk, Engine/tests/code-projects/run.ps1 и Engine/tests/compatibility/run.ps1.

Результаты проверки реализации: 1683 проверки редактора с моделями; 438 проверок C++ интерфейса; 350 проверок пути hot reload через Qt; 371 проверка редактора со старой DLL; 12 проверок прелоадера и ошибок запуска. Счётчики UI включают проверки кадров и могут немного меняться с частотой обновления. Пройдены отдельные проверки reload/камеры (35), workflow C++ (18), frozen compatibility и внешнего SDK-персонажа с собственным контроллером. Runtime подтвердил сигнал готовности первого кадра.

### Старый проект: замена геометрии модели (0.3.0)

Тип импортированной модели — `Engine.Model`, в том числе в проверенных сценах v1.
Замена создаёт одну точку Undo и сохраняет остальные данные. Для вызова
`Scene.ReplaceModel` из расширения редактора передавайте `objectId` явно; текущий
выбор не подставляется автоматически. Неизвестный тип получает отдельную ошибку,
а сообщение C-ABI относится к примитивам. Если ошибка повторяется на модели,
проверьте тип/id в сцене и фактически загруженный Editor.dll.
Исходный файл не меняется до Save. Сохранение непустого `projectData` требует v3
даже у загруженной v1: это существующее правило сериализации, а не alias модели.
