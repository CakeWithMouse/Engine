# Модели, текстуры и своя игровая логика

## Сборка

Из корня репозитория:

```powershell
./Engine/build.ps1 -Target EngineLauncher -EnableAssimp $true
```

Нужны Visual Studio C++, Windows SDK, Qt и Assimp через vcpkg. `Invoke-MSBuild.ps1` ищет vcpkg в установленной Visual Studio. Qt берётся из `QTDIR`, либо из `Editor/ThirdParty/Qt/6.7.3/msvc2019_64`, либо из прежней `Editor/ThirdParty/Qt6.7`. Сборка без Assimp поддерживает примитивы и текстуры, но импорт моделей возвращает явную ошибку.

Edit API обновлён до v6, Scene API — до v4 (материалы, см. [MATERIALS](MATERIALS.md)). Пересоберите runtime, Editor и игровые DLL вместе. Для ранее созданного проекта закройте редактор и обновите `Game.dll` и соседние DLL зависимостей из `Runtime/Templates/SceneProject`; папку `Content` и `Project.json` сохраняйте. Старые сцены v1 читаются; новые поля `assets` опциональны.

## Как работает пользователь

1. В лаунчере создайте проект либо откройте существующий, затем откройте редактор.
2. В панели **Files** нажмите **Импорт модели…**. Выберите GLB, glTF, OBJ или FBX. Файл копируется в `Content/Models/<имя>/`. Для glTF также копируются внешние buffers/images из его папки с сохранением относительных путей. Встроенные data URI остаются внутри glTF. Геометрия проверяется импортёром; при ошибке незавершённая копия удаляется.
3. Нажмите **Импорт текстуры…** и выберите PNG, JPG/JPEG, BMP или TGA. Файл проверяется и копируется в `Content/Textures/`. Совпадающие имена получают суффикс `_1`, `_2` и т. д.; существующие файлы не перезаписываются.
4. В левой панели сцены нажмите **+ Добавить модель…** и выберите импортированный файл из `Content/Models`. Рядом есть кнопка **Импорт модели в проект…**, если файл ещё не импортирован. Эти действия доступны также в меню **Сцена**. Альтернатива: в Files переключитесь на **Content**, раскройте Models и дважды щёлкните по модели. Объект появится в точке добавления X/Y/Z и будет выбран в иерархии. Его можно перемещать, вращать, масштабировать и дублировать. F фокусирует камеру на выбранном объекте. Выбор мышью использует геометрию начальной позы.
5. Выберите объект. Дважды щёлкните по импортированной текстуре либо нажмите **Выбрать текстуру…** в свойствах объекта. Поле **Текстура** показывает назначенный ресурс; **Убрать** сбрасывает его. Импорт модели сам по себе не создаёт объект; импорт текстуры сам по себе не меняет выделенный объект. Ниже в свойствах — поле **Материал**: собственный HLSL-материал объекта, его создание и редактирование описаны в [MATERIALS](MATERIALS.md).
6. **Ctrl+S** сохраняет сцену и делает её стартовой. Модель и текстура хранятся как `/Game/Models/...` и `/Game/Textures/...`, а не как абсолютные пути на компьютере. Можно закрыть редактор, перенести всю папку проекта и открыть её снова.
7. **Play** создаёт отдельную копию сцены с теми же ресурсами; скелетные модели проигрывают первый клип. **Pause** останавливает время, **Stop** возвращает исходную сцену. Импорт и редактирование материалов во время Play/Pause запрещены. **External** запускает сохранённую сцену в отдельном runtime.

Создание модели, назначение/снятие текстуры и дублирование участвуют в Undo/Redo. Импортированные файлы остаются в библиотеке проекта после Undo удаления объекта: их могут использовать другие объекты и сцены. Ошибка назначения текстуры сохраняет прежнюю текстуру. Ошибка открытия сцены с потерянным ресурсом сохраняет текущую сцену и показывает сообщение.

## Границы текущего материала

- На объект назначается одна цветовая текстура. У импортированных моделей используются UV из файла; у примитивов — локальная проекция на плоскость грани. Для точной авторской развёртки используйте модель с UV.
- Материалы исходного файла, embedded-текстуры GLB, normal/roughness/metallic-карты и отдельные материалы по submesh автоматически не назначаются. Цветовую текстуру импортируйте отдельно и назначьте объекту либо используйте в своём материале.
- Статические модели объединяют меши и применяют трансформации узлов. Скелетные используют существующий импортёр: до 64 костей, один совместимый mesh root, первый клип. Ограничения импортёра выводятся как ошибки, а не как пустые объекты.
- Скелетный компонент пока использует существующий forward-рендер без отбрасывания теней. Физика, коллизии и создание игрового поведения из GUI в эту функцию не входят.
- Внешние ресурсы glTF должны находиться внутри папки выбранной модели; ссылки `../`, абсолютные пути и сетевые URI не копируются. Изображения ограничены 16384 по стороне и 64 млн пикселей, отдельный файл — 256 MiB.

256 MiB (268435456 байт) — установленный в текущем импорте предел расхода памяти, а не ограничение форматов FBX/glTF. Пустой файл отклоняется с отдельной ошибкой. При превышении лимита сообщение показывает путь и фактический размер. Проверка размера модели/внешнего ресурса не загружает его целиком в память; чтение выполняется самим импортёром.

## Как добавить свою логику

Проект, созданный лаунчером, содержит готовый `Game.dll`, ресурсы и сцену. Это шаблон без исходников. Новое C++-поведение требует собственного игрового DLL; редактировать исходники Engine для этого не нужно.

Для поведения отдельного объекта наследуйтесь публично от `GameComponent` либо его наследника (например, `CubeComponent`). Заголовок разместите в `Source` своего C++-проекта и поставьте `ENGINE_COMPONENT` непосредственно над классом:

```cpp
#pragma once
#include <Engine/Components/SpecificComponents/CubeComponent.h>

namespace MyGame
{
    ENGINE_COMPONENT("Вращающийся куб")
    class RotatingCube final : public CubeComponent
    {
    public:
        RotatingCube() { InitCube(); }
        void Tick(float dt) override
        {
            CubeComponent::Tick(dt);
            auto rotation = GetRotation();
            rotation.y += 45.0f * dt;
            SetRotation(rotation);
        }
    };
}
```

Конструктор вызывается также в редакторе и при Undo/Play: он должен работать без окна, GPU и `GetGame()`. `Tick` вызывается в Play и standalone, не во время обычного редактирования. Пользовательские поля вроде скорости пока не сериализуются автоматически и не появляются в инспекторе; сохраняются имя, тип, трансформация, родитель и ссылки на визуальные ресурсы.

### Конкретный путь к своему DLL с сохранением примитивов

1. Создайте `Game/MyGame/Source` внутри репозитория. Скопируйте `Game/SceneProject/SceneProject.vcxproj` в `Game/MyGame/MyGame.vcxproj`. Задайте новый `ProjectGuid` и измените `OutDir` с `Runtime/Templates/SceneProject/` на `Runtime/Projects/MyGame/`. Оставьте `TargetName` равным `Game`.
2. Перед заключительным `</Project>` добавьте импорт генератора:

   ```xml
   <Import Project="../../Engine/BuildSupport/ComponentGeneration.targets" />
   ```

3. Положите приведённый выше класс в `Source/RotatingCube.h`. В `Source/Module.cpp` объедините сгенерированный каталог с примитивами:

   ```cpp
   #include "GeneratedComponents.h"
   #include "../../SceneProject/Source/Primitives.h"
   #include <vector>

   static ComponentTypeCatalog ProjectComponentTypes()
   {
       static const auto types = [] {
           std::vector<ComponentType> result;
           for (auto catalog : {SceneProject::GetComponentTypes(),
                                EngineGenerated::MyGame::GetComponentTypes()})
               for (size_t i = 0; i < catalog.size; ++i)
                   result.push_back(catalog.data[i]);
           return result;
       }();
       return {types.data(), types.size()};
   }
   #include "../../Common/SceneModule.inl"
   ```

   `MyGame` в `EngineGenerated::MyGame` берётся из имени `.vcxproj`. Генератор сам находит отмеченные классы в заголовках Source. Если методы вынесены в `.cpp`, добавьте этот `.cpp` в проект сборки.

4. Соберите:

   ```powershell
   ./Engine/BuildSupport/Invoke-MSBuild.ps1 -Project "$PWD/Game/MyGame/MyGame.vcxproj" -EnableAssimp
   ```

5. Закройте редактор проекта. Скопируйте собранный `Game.dll` и его соседние DLL зависимостей из `Game/build/x64/Debug/Runtime/Projects/MyGame/` в папку своего пользовательского проекта. `Content` и `Project.json` остаются прежними. Откройте проект: «Вращающийся куб» появится в списке типов; добавьте его и нажмите Play.

Для целой игры со своим главным циклом можно наследовать `Game`, как в `Game/SunGame`; это другой путь, чем компонентное поведение в редакторской сцене. Для текущего редактора используйте каталог компонентов и общий scene-модуль. Не переименовывайте namespace/класс уже сохранённых компонентов без миграции сцены: полное имя C++ служит ключом типа.

## Проверки

```powershell
./Engine/tests/assets/run.ps1 -EnableAssimp
./Editor/tests/run.ps1 -EnableAssimp
./Engine/tests/skeletal/run.ps1 -EnableAssimp
```

AssetTests использует настоящий игровой DLL и D3D viewport: импорт, ошибки, Unicode, конфликт имён, зависимости glTF, статические и скелетные модели, текстуры, Play, чтение/запись сцены, перенос проекта. Qt-тест проходит через интерфейс и очередь команд: импорт, назначение, дублирование, Undo/Redo, сохранение, Play и закрытие.
