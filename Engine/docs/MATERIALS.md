# Материалы: файлы, HLSL-поверхность, редактор и код игры

Этап 047, 28.10.2026. Материал — это пара файлов: `.mat` с настройками и `.hlsl` с функцией
поверхности. Освещение, тени, forward/deferred и инстансинг даёт общий шаблон движка; автор
материала пишет только то, как выглядит поверхность. Материал назначается объекту сцены в
редакторе или компоненту из кода игры, сохраняется в сцене ссылкой `/Game/...` и правится
во время работы без перезапуска.

## Что получает пользователь

1. Выберите объект в сцене. В свойствах объекта поле **Материал** показывает назначенный
   `.mat`; пустое поле с подсказкой «по умолчанию» означает встроенный материал движка.
2. **Редактировать** открывает окно материала. Если у объекта материал по умолчанию, кнопка
   сначала создаёт новый материал в `Content/Materials`, назначает его объекту и открывает
   редактор. Имя берётся из имени объекта, если оно годится для файла, иначе `Material`;
   занятые имена получают суффикс `_2`, `_3` и т. д.
3. **Выбрать…** назначает существующий `.mat` из проекта, **Убрать** возвращает материал по
   умолчанию. То же доступно в панели **Files**: двойной щелчок по `.mat` открывает редактор,
   контекстное меню — **Назначить материал**, **Редактировать материал**, **Новый материал…**.
   Новый материал создаётся в выбранном каталоге или рядом с выбранным файлом; вне `Content` —
   в `Content/Materials`. Имя: латинские буквы, цифры, `_`, `-` и `.`.
4. В окне материала слева превью (сфера, куб или плоскость; перетаскивание вращает камеру,
   колесо приближает), в центре текст HLSL с номерами строк, справа настройки и параметры.
   Параметры, цвета и текстуры применяются сразу во всех сценах, где виден материал, включая
   Play. Текст HLSL применяется при сохранении.
5. **Сохранить** / Ctrl+S записывает HLSL, перекомпилирует его и сохраняет `.mat`.
   Ошибки компиляции показываются списком под текстом, строки с ошибками подсвечены, двойной
   щелчок переходит к строке. Пока шейдер не компилируется, объект рисуется шахматкой
   пурпурного и чёрного цвета. **Откатить** возвращает материал и HLSL к файлам на диске.
6. Ctrl+S в основном окне сохраняет сцену со ссылкой на материал. Сам материал сохраняется только
   в его окне. При закрытии редактора окна с несохранёнными материалами спрашивают, сохранить ли
   изменения.

Назначение и снятие материала участвуют в Undo/Redo и запрещены во время Play/Pause, как
остальные правки сцены. Сами правки материала в Undo не входят: их отменяет **Откатить**.
Редактируются только материалы из `Content` проекта; текстуры для материала сначала
импортируйте кнопкой **Импорт текстуры…**.

## Файл .mat

JSON в UTF-8. Пример со всеми полями:

```json
{
  "version": 1,
  "shader": "Cutout.hlsl",
  "render": { "blend": "masked", "alphaClip": 0.5, "twoSided": true },
  "params": { "Tint": [0.3, 0.85, 0.4, 1.0], "HoleRadius": 0.32 },
  "textures": { "BaseMap": "../Textures/grid.png", "MaskMap": null }
}
```

| Поле | Правило |
|---|---|
| version | 1; необязательно |
| shader | Обязательно. Путь к `.hlsl` относительно `.mat` (абсолютный допускается) |
| render.blend | `opaque` (по умолчанию), `masked`, `translucent`, `additive` |
| render.alphaClip | Порог альфы для `masked`, 0–1, по умолчанию 0.5 |
| render.lighting | `lit` (по умолчанию) или `unlit` |
| render.twoSided | Рисовать обратные грани с перевёрнутой нормалью; по умолчанию false |
| render.castShadows | По умолчанию true |
| params | Имя переменной из `cbuffer MaterialParams` → число или массив из 1–4 чисел |
| textures | Имя `Texture2D` → путь относительно `.mat` либо null (белая текстура) |

Не указанные параметры берут значения из инициализаторов HLSL. Имена, которых нет в шейдере,
и нечитаемые текстуры пропускаются с предупреждением в журнале, материал всё равно рисуется.
Сохранение из редактора переписывает только известные поля: неизвестные ключи, их порядок и
параметры, удалённые из HLSL, сохраняются. Запись выполняется через временный файл и замену.

Режимы смешивания:

- `opaque` — пишет глубину, участвует в deferred G-buffer;
- `masked` — непрозрачный, пиксели с альфой ниже порога отбрасываются; тень тоже с дырами;
- `translucent` — альфа-смешивание, сортировка от дальних к ближним, без записи глубины;
- `additive` — цвет × альфа добавляется к кадру, без записи глубины.

Полупрозрачные, аддитивные, неосвещённые и излучающие материалы всегда рисуются forward-проходом,
в том числе в режиме Deferred: в G-buffer нет канала излучения и смешивания.

## HLSL-поверхность

Файл поверхности определяет одну функцию. Контракт описан в
`Engine/Content/Shaders/Material/MaterialCommon.hlsli`, шаблон — в `MaterialTemplate.hlsl` рядом.

```hlsl
// Металл: сильный блик и светлый край под скользящим углом.
cbuffer MaterialParams : register(b1)
{
    float4 Tint = float4(1.0f, 0.72f, 0.28f, 1.0f);
    float Gloss = 1.0f;
    float Rim = 0.45f;
};

void Surface(MaterialInput i, inout MaterialOutput o)
{
    float fresnel = pow(1.0f - saturate(dot(i.Normal, i.ViewDir)), 3.0f);
    o.Albedo = saturate(Tint.rgb + Rim * fresnel);
    o.SpecularWeight = Gloss;
    o.AmbientModel = 0.0f;
}
```

`o` приходит заполненным значениями по умолчанию: цвет компонента, умноженный на его текстуру,
интерполированная нормаль, умеренный блик, полусферическое окружение. Поверхность меняет только
нужное. Пустая функция — это материал по умолчанию (`Shaders/Material/DefaultSurface.hlsl`).

| MaterialInput | Значение |
|---|---|
| WorldPos | Мировая позиция пикселя |
| Normal | Мировая нормаль, нормализована; у двусторонних на обратной грани перевёрнута |
| UV | Текстурные координаты |
| ViewDir | Направление от поверхности к камере |
| Color | Цвет компонента (`SetColor`), у инстансов умножен на цвет копии |
| InstanceData | `MeshInstance::CustomData` копии; 0 без инстансинга и у анимированной толпы |
| Time | Реальные секунды с запуска, без масштаба времени сцены |
| FrontFace | Лицевая ли грань |

| MaterialOutput | Значение |
|---|---|
| Albedo | Базовый цвет |
| Normal | Мировая нормаль; шаблон нормализует её после `Surface` |
| SpecularWeight | 0 — матовый, 1 — сильный блик; размер блика задаётся настройкой сцены |
| AmbientModel | 0 — плоское окружение, 1 — полусферическое (светлее сверху) |
| Emissive | Добавляется после освещения; требует `#define MATERIAL_EMISSIVE` |
| Alpha | Для `masked`, `translucent` и `additive` |

Ресурсы поверхности:

- параметры — переменные `cbuffer MaterialParams : register(b1)`. Редактор находит их отражением
  шейдера и показывает поля: `float`–`float4`; `float3`/`float4` дополнительно получают выбор цвета.
  Остальные типы видны в списке, но не изменяются;
- текстуры — `Texture2D` на `register(t6)` и выше; t0–t5 заняты движком. Без назначения
  привязывается белая текстура 1×1;
- семплер `MaterialSampler` (s2): линейная фильтрация, повторение.

До функции `Surface` файл может объявить `#define MATERIAL_EMISSIVE` (поверхность пишет
`o.Emissive`) и `#define MATERIAL_UNLIT` (то же, что `"lighting": "unlit"`). Остальные макросы
(`MATERIAL_BLEND`, `MATERIAL_TWO_SIDED`, варианты инстансинга, скиннинга и теней) задаёт движок.

Примеры: `Game/BasicExamples/Content/Materials` — золото (блик и край), пульсирующее излучение,
стекло, вырез с двусторонними гранями, голограмма, толпа с фазой мерцания в `InstanceData`.
Сцена «Материалы» в BasicExamples показывает их рядом.

## Какие объекты принимают материал

- `MeshComponent` — один меш формата `VertexFormat::Mesh` (позиция, нормаль, UV). Примитивы шаблона
  SceneProject теперь рисуются им: куб, сфера, плоскость, цилиндр, конус, пирамида из
  `MeshPrimitives`. Без своей пары шейдеров рисуется материалом по умолчанию.
- Статические модели (`FBXComponent`) и скелетные (`SkeletalMeshComponent`).
- `InstancedMeshComponent` — все уровни LOD, тени masked-материалов; дальний уровень-спрайт
  запекается через материал и перезапекается при его изменении.

Точечный свет и прочие компоненты без меша материал не принимают: назначение возвращает ошибку,
кнопка **Редактировать** у света недоступна.

## Материал из кода игры

```cpp
#include <Engine/Components/SpecificComponents/MeshComponent.h>
#include <Engine/Render/Material.h>
#include <Engine/Render/MeshPrimitives.h>

std::string error;
std::shared_ptr<Material> gold = LoadMaterial((gameContent / "Materials/Gold.mat").generic_u8string(), &error);
if (!gold) throw std::runtime_error(error);

auto* sphere = new MeshComponent({0.0f, 1.0f, 0.0f}, glm::vec3(0.0f), glm::vec3(1.0f));
sphere->SetMesh(MeshPrimitives::Sphere(0.8f));
sphere->SetMaterial(gold);
```

| Метод | Назначение |
|---|---|
| `Game::LoadMaterial(path, &error)` | Читает `.mat` один раз и раздаёт общий `Material`. null — файл не прочитан; ошибка компиляции даёт материал с шахматкой |
| `Game::GetDefaultMaterial()` | Встроенный непрозрачный освещённый материал |
| `Game::FindMaterial` / `ReloadMaterial` | Найти загруженный / перечитать `.mat` в тот же объект |
| `GameComponent::SetMaterial(ptr)` | Рисовать этим материалом; null — вернуться к паре шейдеров компонента |
| `GameComponent::SetMaterialAsset("/Game/...mat")` | Ссылка, как в сцене; игра загрузит материал перед следующим кадром |
| `Material::SetParameter` / `SetTexture` | Изменить значение для всех, кто использует материал |
| `InstancedMeshComponent::SetInstanceCustomData` | Значения копии для `MaterialInput.InstanceData` |

`SetMaterial` возвращает false, если компонент не поддерживает материалы (`SupportsMaterials`).
Один `Material` разделяют все компоненты, которым он назначен: изменение параметра видно у всех.
Для разных значений создайте отдельные `.mat` с общим `.hlsl`. Материал живёт в кэше игры
дольше компонентов. Пример целиком — `Game/BasicExamples/Source/MaterialsScene.cpp`, техника
Battle — `Game/Battle/Source/BattleGame.cpp`.

## Перезагрузка с диска

В запущенной игре **F6** перекомпилирует все шейдеры и материалы с диска. Правьте копии рядом с
exe: `GameContent/Materials` и `EngineContent/Shaders`. Шейдеры карты теней компилируются один раз
при запуске и не перезагружаются. Редактор после сохранения HLSL перекомпилирует только
материалы и шейдеры, которые включают этот файл.

## Совместимость

- Edit API обновлён до v6, Scene API — до v4. Пересоберите runtime, Editor и игровые DLL вместе.
- Проект, созданный раньше, хранит свою копию `Game.dll`; новый редактор её отклонит. Закройте
  редактор и скопируйте `Game.dll` и соседние DLL из `Runtime/Templates/SceneProject` в папку
  проекта, сохранив старые как резервную копию. `Content`, сцены и `Project.json` не меняются.
  Собственные игровые DLL пересоберите.
- Сцена остаётся JSON v1: поле `assets.material` необязательное, старые сцены читаются как прежде.
  Сцену с назначенным материалом прежние сборки не откроют.
- Примитивы сохраняют прежние типы, размеры и цвета, но теперь освещаются материалом по
  умолчанию, поэтому выглядят иначе, чем в старых сборках. Battle тоже рисуется материалами.
- Регистр костей и анимаций перенесён с `b1` на `b3`, т. к. `b1` занят параметрами материала.
  Это касается только шейдеров движка; свои шейдеры скелетных моделей сверьте с `Skinning.hlsli`.
- `MeshInstance` вырос с 48 до 60 байт: добавлено поле `CustomData`. Инициализируйте копии по
  именам полей, а не позиционно.

## Границы текущего материала

- Один материал на объект; отдельные материалы по submesh и материалы из исходных файлов моделей
  не назначаются.
- Модель освещения одна: Albedo, блик, окружение, излучение. Карт нормалей, roughness/metallic и PBR
  в шаблоне нет; их можно вычислить в `Surface` из своих текстур.
- Параметры только `float`–`float4`. Матрицы, массивы и структуры видны редактору, но не задаются.
- Правка HLSL в редакторе — простой текст с подсветкой ошибок, без автодополнения.
- Анимированная толпа `InstancedMeshComponent` получает нулевой `InstanceData`.

## Проверки

```powershell
./Engine/tests/assets/run.ps1 -EnableAssimp
./Editor/tests/run.ps1 -EnableAssimp
./Engine/tests/project-workflow/run.ps1
```

EngineTests проверяет компиляцию через шаблон, отражение параметров, `.mat` (чтение, ошибки,
сохранение с неизвестными полями), шахматку при ошибке, режимы смешивания, тени masked,
инстансинг и скиннинг по пикселям D3D. AssetTests проверяет назначение материала в сцене, JSON,
Play и весь Edit API материалов: чтение, параметры, режимы, текстуры, сохранение, откат, ошибки
компиляции и превью. Qt-тест проходит через окно материала: создание из Files, параметры, ошибки
HLSL с переходом к строке, сохранение, отказ от правок и создание материала из материала по умолчанию.
