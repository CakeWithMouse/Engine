# HUD проекта и редактор UI

Начиная с 2026.10.31.3 новый проект запускается без HUD. В главном редакторе откройте **Запуск → HUD игры…** (или **UI → HUD игры…**), выберите существующий `.ui` из Content либо нажмите **Создать…**. Подтвердите выбор кнопкой OK. Значение **Нет** отключает HUD при следующем запуске.

Выбор хранится в `Content/ProjectHud.txt`: одна строка с путём относительно Content, например `UI/Hud.ui`. Отсутствующий или пустой файл означает «Нет». Абсолютные пути и выход за Content запрещены. Настройка относится к игре проекта, а не к отдельной сцене. При Play и обычном запуске `Game::InitializeGameplay` создаёт один UIComponent; он не сериализуется как объект сцены. Stop уничтожает игровую копию вместе с HUD. Изменение выбора применяется при следующем запуске; сохранение выбранной разметки подхватывается во время игры.

## Редактирование без запуска игры

Открыть окно можно через **UI → Открыть редактор UI…**, из настроек HUD либо двойным щелчком на `.ui` в Content.

- Слева — иерархия. Выделение на холсте и в дереве синхронизировано.
- В центре — предпросмотр. Элементы перемещаются левой кнопкой мыши. Масштаб холста подстраивается под окно; координаты инспектора остаются пикселями выбранного разрешения.
- Справа — имя, текст, X/Y, размеры, anchor, видимость и цвета. Диалог цвета включает прозрачность; у кнопки доступны отдельно фон, текст, наведение, нажатие и рамка.
- Панель инструментов добавляет Panel, Label, Button и Bar. Новый элемент помещается в выбранную Panel/Group или ближайший контейнер-родитель. Корневой контейнер удалить нельзя. Созданные элементы получают уникальные имена.
- **Сохранить** / Ctrl+S записывает UTF-8 XML атомарно. **Перечитать** загружает внешние изменения после решения о несохранённых правках. При закрытии редактор спрашивает о сохранении.

Предпросмотр использует `UIElement::Layout`, `UIElement::Build` и тот же FontAtlas, что игра; Qt композитит готовые прямоугольники и глифы. Доступны 1280×720, 1920×1080, 800×600 и 720×1280. Это предпросмотр на нейтральном фоне, без сцены и выполнения обработчиков кнопок. Проверять взаимодействие нужно в Play.

Все поддерживаемые свойства разметки, в том числе padding, interactive, border, align, fill, hoverColor и pressedColor, сохраняются сериализатором. Не все из них имеют отдельное поле инспектора. Неизвестные атрибуты не являются поддерживаемыми свойствами: загрузчик предупреждает о них, после сохранения они не сохраняются. Комментарии и исходное форматирование XML также не сохраняются.

## Проверка в игре и экспорт

Выберите HUD, запустите Play, сохраните изменение цвета или расположения в редакторе UI. Игра перечитает файл без сборки C++. При ошибке разбора останется предыдущий рабочий интерфейс; сообщение UIComponent содержит путь и, для синтаксических ошибок, строку. При неудачной первой загрузке выбранный компонент продолжает наблюдение: исправленный файл появится после сохранения.

Встроенный экспорт копирует Content вместе с `ProjectHud.txt` и `.ui`, а также EngineContent с `Shaders/UI.hlsl`. Экспорт отклоняет отсутствующий выбранный HUD и отсутствующий шейдер. Перенос папки экспортированной игры не требует менять пути. Для старого C++ проекта нужна пересборка актуальным SDK; обновление только Editor.dll не добавляет новый код в старую Game.dll.

## Поведение кнопок и C++

Визуальный редактор задаёт внешний вид. Сценарии игры, данные и действия кнопок по-прежнему задаёт C++. Получите автоматически созданный компонент через `Game::GetProjectHud()` в BeginPlay компонента или PreUpdate игры. Он создаётся при инициализации gameplay, после AfterInitialize.

```cpp
// Один раз на экземпляр Game, например при первом PreUpdate:
if (auto* hud = GetProjectHud()) {
    hud->BindClick("add", [this] { ++clicks_; });
}
// Во время обновления:
if (auto* hud = GetProjectHud()) {
    hud->SetLabelText("clicks", "Нажатий: " + std::to_string(clicks_));
    hud->SetBarFill("load", float(clicks_ % 11) / 10.0f);
}
```

`BindClick` хранит обработчик вне дерева и автоматически назначает его вновь после перезагрузки. Привязка переживает временное удаление элемента; `UnbindClick` удаляет её. SetLabelText/SetBarFill каждый раз разрешают имя и возвращают false для отсутствующего элемента. Обычному пользователю не нужно работать с MarkupRevision. Старый низкоуровневый Find/OnClick остаётся: сырые указатели всё ещё недействительны после замены дерева.

Игра обрабатывает UI до PreUpdate и игровых действий. Наведение на интерактивный элемент и захват кнопкой блокируют мышь для Input::System и стандартной камеры. Декоративные Panel/Label не блокируют ввод, если interactive не включён. Собственный код, читающий физическое состояние мыши напрямую или использующий низкоуровневые события ОС, сам отвечает за приоритет UI.

В Battle демонстрационный HUD включается явно флагом `--hud` (F7 скрывает его). Он продолжает загружать копию `GameContent/UI/Hud.ui` рядом с Battle.exe. Это пример программных показателей и не замена настройке HUD обычного проекта.

## Ограничения первой версии

Нет графа событий, анимаций, привязки данных без кода, изменения родителя перетаскиванием и отдельного Undo/Redo для UI. Атлас поддерживает ASCII и русские буквы; изображения, многострочный текст и произвольный Unicode текущая система не поддерживает. Размеры/отступы задаются в пикселях, anchor — относительно родителя. При перетаскивании растянутый элемент получает фиксированный текущий размер.
