# Визуальные скрипты

Визуальный скрипт — граф событий и действий в файле `.vscript`, привязанный к объекту сцены. Движок
интерпретирует граф сам, поэтому скрипты работают и в проектах без C++: компилятор и Hot Reload не нужны.

Работа по [плану 072](../../Agent/Tasks/072-visual-scripting-plan.md): движок, привязка в сцене, окно редактора и пример.

## Пример

В BasicExamples есть сцена «Скрипты» (`BasicExamples.exe --scene scripts` или кнопка в окне выбора). В ней нет игрового
кода C++, всё делают три скрипта из `Game/BasicExamples/Content/Scripts`:

| Скрипт | Что делает | Что показывает |
|---|---|---|
| `Spin.vscript` | Куб поворачивается на 90° в секунду. | «Каждый кадр», `DeltaTime`, значение входа без связи. |
| `Bob.vscript` | Шар плавает вверх-вниз от исходной точки. | Переменная `Start`, «Начало игры», время и синус. |
| `Move.vscript` | Стрелки ← → двигают куб, пробел возвращает его на место. | «Клавиша зажата», ветвление, последовательность, «Клавиша нажата», вывод в консоль. |

Скрипты можно открыть в окне редактора: скопируйте их в `Content/Scripts` своего проекта. В самом примере скрипты
назначены из C++ по пути к файлу (`ScriptsScene.cpp`), потому что у старой сцены BasicExamples нет проекта `/Game`.

## Как сделать скрипт в редакторе

1. **Создайте скрипт.** Выделите объект и в свойствах, в карточке «Скрипт», нажмите **Создать**. Появится
   `Content/Scripts/<имя объекта>.vscript`, он назначится объекту, и откроется окно скрипта. Другие способы:
   - в Files: ПКМ → **Новый скрипт…**;
   - назначить готовый скрипт: **Выбрать…** в карточке или ПКМ по файлу → **Назначить скрипт выделенному объекту**.
2. **Соберите граф.** Новый скрипт начинается с событий «Начало игры» и «Каждый кадр».
   - Ноды добавляются через **+ Нода**, Tab или ПКМ по холсту; работает поиск по-русски и по-английски.
   - Связь тянется от пина к пину. Белые пины — поток выполнения, цветные — значения: зелёный — число, жёлтый —
     вектор, красный — логическое, розовый — строка, голубой — объект.
   - Двойной щелчок по ноде открывает её свойства (клавиша, переменная, значение) и значения входов без связи.
   - Пустой вход «Target» — сам объект.
   - Связь выделяется щелчком; Del или ПКМ → **Удалить связь** удаляет её.
   - **Упорядочить** раскладывает граф слева направо по связям: события слева, константы — перед нодой, которой
     они нужны. Это один шаг отмены.
3. **Переменные** — на панели слева: имя, тип, начальное значение. Вектор пишется тремя числами через запятую.
   Переименование переменной переносится на её ноды.
4. **Сохранение не нужно.** Каждая правка сразу записывается в файл, и движок проверяет граф тем же компилятором, что
   и Play. Ошибки показываются красной рамкой на ноде и в списке под холстом; щелчок по строке показывает ноду.
   Ctrl+Z/Y отменяют и повторяют правки, включая переменные. Ctrl+C/V переносят ноды между окнами скриптов.
5. **Play** (Space) берёт файл при запуске. Если скрипт остановился на ошибке, окно показывает её с именем объекта
   («Play · Сфера · нода 8: деление на ноль»), и она остаётся видна после Stop. Та же ошибка один раз за Play
   попадает в Console редактора («[Скрипт] /Game/Scripts/Spin.vscript · Сфера · нода 8: деление на ноль»), даже если
   окно скрипта закрыто.
6. **Отладка в Play.** Открытое окно показывает, как выполняется скрипт у одного объекта (выбор — «Объект в Play» в
   строке состояния; по умолчанию первый объект с этим скриптом):
   - яркая зелёная рамка — нода работала за последние 12 кадров;
   - бледная зелёная — работала раньше («Начало игры»);
   - красная — на этой ноде скрипт остановился;
   - «×N» в углу ноды — сколько раз она выполнялась с начала Play. Событие считается один раз за запуск, даже если
     другие ноды читают его значение (`DeltaTime`).
   - справа от выходов данных — последнее значение, которое нода отдала (`Out (0, 1.44, 0)`, `DeltaTime 0.016`).
   После Stop рамки и значения снимаются. Ноды, вставленные из буфера обмена другого графа (материала), не вставляются:
   окно говорит, из какого они графа.
7. **Предупреждения** (жёлтая рамка и строка «Предупреждение» в списке) — граф собирается, но, скорее всего, делает не то:
   у «Случайного числа» Min = Max, деление на неподключённый 0, результат ноды никуда не идёт, к входу exec ничего не
   подключено, событие ни к чему не ведёт. Правила — `CodeGraphSchema::Warnings`.
8. **Комментарии.** «Комментарий» обводит выделенные ноды рамкой с подписью (без выделения — в центре вида).
   Перетаскивание рамки двигает ноды внутри, угол меняет размер, двойной щелчок — текст, Del удаляет. В файле —
   массив `comments`, только когда он есть; движок его не читает.

Движок пишет ошибки по-английски; редактор с русским интерфейсом переводит известные тексты
(`Editor/Core/ScriptMessages.cpp`). Новое сообщение движка без шаблона там показывается по-английски.

Окно открывается двойным щелчком по `.vscript` в Files или кнопкой **Открыть** в карточке «Скрипт». В проекте со старым
`Game.dll` скриптов нет: карточка скрыта, окно открывается только для чтения с подсказкой обновить модуль.

## Привязка к объекту

**Значения переменных у объекта.** В карточке «Скрипт» под путём — переменные скрипта. Пустое поле — значение из
скрипта (оно в подсказке), заполненное — своё у этого объекта; ↺ возвращает значение скрипта. Логическое выбирается
из списка. Значения хранятся в сцене как `assets.scriptVariables` (`{"Speed": 45}`, только когда заданы), идут через
Undo/Redo, копию для Play и «Создать копию». В Play они заменяют начальные значения переменных; имя, которого нет
в скрипте, и значение другого типа пропускаются. API: `getVariables`/`setVariables` в Engine.Scene.Script.


У объекта один скрипт. Путь хранится в сцене как `assets.script` ([SCENE-JSON](SCENE-JSON.md)) и проходит через
сохранение, Undo/Redo, смену модели, копию для Play и дублирование. Назначить можно только существующий
`.vscript` внутри `/Game`. Файл, сломанный или удалённый после назначения, сцене не мешает: ошибка появится в Play.

Переименовать или перенести скрипт: Files → ПКМ по `.vscript` → **Переместить / переименовать…** (только в Edit).
Ссылки `assets.script` обновляются во всех сценах проекта и в открытой сцене, открытое окно скрипта переоткрывается
по новому пути. Прежние файлы остаются в `.painengine/AssetBackups`, история Undo сцены очищается. Переименование
в проводнике ссылки не обновляет: окно такого скрипта сообщает, что файл не найден.

## API для редактора: Engine.Scene.Script v1

Именованное расширение (`EngineGetEditExtension`); runtime отдаёт его редактору сервисом `EngineScriptService`.
Описание — `Engine/Include/Engine/Runtime/EditExtensions.h`.

| Функция | Что делает |
|---|---|
| `describe` | Каталог нод в JSON: схема, ноды, пины, свойства, имена клавиш. |
| `get` | Путь скрипта объекта активной сцены (во время Play — копии). |
| `set` | Только в Edit. Пустая строка снимает скрипт. Иначе существующий `.vscript` внутри `/Game`. |
| `check` | Собирает файл тем же компилятором, что и Play; каждая ошибка — с id ноды. |
| `readProblems` | Ошибки скриптов в идущем Play: остановленные (`runtime = 1`) и не запущенные. `objectId` — id того же объекта в edit-сцене. |

Редактор: команда `EditorCommand::SetScript` (Undo через снимок сцены), путь в `SceneObject::scriptAsset`,
признак поддержки `Snapshot::scripts`.

## Отладка: Engine.Scene.GraphTrace v1

Отдельное расширение для живого состояния нод любого графа в идущем Play; сервис `EngineGraphTraceService`.
Сейчас его заполняют визуальные скрипты, позже — деревья поведения и автоматы ИИ (добавятся состояния нод).
В Edit расширение ничего не сообщает. Редактор без него просто не показывает рамки.

| Функция | Что делает |
|---|---|
| `listObjects` | Объекты Play-сцены, выполняющие граф-ассет: id того же объекта в edit-сцене, имя, остановлен ли граф. |
| `read` | Ноды, выполнявшиеся у объекта (0 — первый объект с этим ассетом): `state` (`Ran`, `Failed`), `framesAgo` (0 — в последнем кадре), `count`. |
| `readValues` | Для того же объекта — последнее значение каждого выхода данных, который кто-то читал: нода, имя выхода, текст. |

Источник — `Script::Instance::Trace()`: интерпретатор отмечает ноду при каждом выполнении или вычислении.
Окно скрипта опрашивает трассу раз в 200 мс.

## Когда скрипт работает

| Момент | Что происходит |
|---|---|
| Edit, Pause | Скрипт не выполняется. |
| Начало Play или игры | После `BeginPlay` объекта файл читается и собирается; запускаются ноды «Начало игры». |
| Каждый кадр | После `Tick` объекта: сначала «Клавиша нажата/отпущена», потом «Каждый кадр». |
| Объект добавлен во время игры | Его скрипт стартует в начале следующего кадра. |
| Файл изменён во время Play | Уже запущенные скрипты работают со старой версией; объекты, стартующие позже, и следующий Play берут новую. |

Собранная программа кэшируется в `Game` по пути файла и пересобирается, когда меняется время записи. F6 не нужен.

## Ошибки

- **Ошибки сборки.** Неизвестная нода, неизвестная клавиша или переменная, несовпадение типов, две связи в одном
  входе или из одного exec-выхода, цикл по данным, более новая версия файла. В консоль пишутся все ошибки, у каждой —
  id ноды; скрипт этого объекта не запускается. Остальная сцена работает.
- **Ошибки выполнения.** Деление на ноль, пустой или удалённый объект в «Цели», больше 10 000 шагов за одно событие
  (вероятно, бесконечный цикл). Сообщение `[Script] путь: node N (тип): текст` пишется в консоль, скрипт этого
  объекта останавливается до следующего Play.

## Формат файла

Общий формат графов редактора (`Editor/Core/Graph/GraphDocument`) со схемой `code`:

```json
{
  "format": "ITMOEngine.Graph", "version": 1,
  "schema": "code", "schemaVersion": 1,
  "variables": [{"name": "Speed", "type": "float", "value": 90}],
  "nodes": [
    {"id": 1, "type": "Event.Tick", "title": "", "x": 0, "y": 0, "properties": {}},
    {"id": 2, "type": "Action.Rotate", "title": "", "x": 240, "y": 0,
     "properties": {"inputs": {"Degrees": [0, 1, 0]}}}
  ],
  "connections": [{"fromNode": 1, "fromPin": "then", "toNode": 2, "toPin": "exec"}]
}
```

- **Типы значений:** `bool`, `float`, `vec3` (массив из трёх чисел), `string`, `object` (объект сцены).
  Переменные бывают первых четырёх типов.
- **Входы без связи.** Значение берётся из `properties.inputs.<пин>`, иначе ноль, пустая строка или `false`.
  Пустой вход «Цель» (`Target`) — сам объект.
- **Связи.** У exec-выхода (`exec`) одна связь, у входа данных одна. Exec-вход принимает много связей.
  Тип выхода данных должен совпадать с типом входа; вход `any` («Вывести в консоль») принимает любой.
- **Неизвестные поля** движок пропускает. Редактор их сохраняет.

## Ноды

Каталог — `Engine/Source/Script/ScriptCatalog.cpp`; редактор получает его как JSON (`Script::CatalogJson`).

| Группа | Ноды |
|---|---|
| События | Начало игры, Каждый кадр (`DeltaTime`), Клавиша нажата, Клавиша отпущена, Каждые N секунд (`seconds` > 0), Своё событие (`event` — имя) |
| Поток | Ветвление (`True`/`False`), Последовательность (`outputs` от 1 до 8), Задержка (`Seconds`), Один раз, Попеременно (`A`/`B`, `IsA`), Цикл (`First`…`Last` включительно, `Body`, `Index`, `Completed`) |
| Действия | Вывести в консоль, Задать позицию / поворот / масштаб, Сдвинуть, Повернуть, Вызвать событие (`event` у `Target`), Создать копию (`Template`, `Position` → `Object`), Удалить объект |
| Переменные | Переменная, Задать переменную |
| Объекты | Сам объект, Найти объект (по имени), Позиция, Поворот, Масштаб |
| Константы | Число, Логическое, Вектор, Строка |
| Векторы | Собрать, Разобрать, Сложение, Вычитание, Вектор × число, Длина, Направление, Смешивание векторов, Расстояние |
| Математика | Сложение, Вычитание, Умножение, Деление, Синус, Косинус, Модуль, Минимум, Максимум, Смешивание, Ограничение, Случайное число, Время |
| Логика | Меньше, Больше, Равно, И, Или, Не |
| Ввод | Клавиша зажата, Позиция мыши (`X`, `Y` в пикселях окна, `Valid`) |
| ИИ | Отправить событие ИИ, Записать в память ИИ (`memory` — ключ), Память ИИ: число / логическое / вектор / объект (`Value`, `Has`), Состояние ИИ (`State`, `Running`), ИИ в состоянии — у «ИИ-персонажа», см. [AI-FSM](AI-FSM.md#связь-с-визуальными-скриптами) |

Как работают ноды с состоянием (состояние своё у каждого объекта и сбрасывается каждым Play):
- **Задержка** продолжает поток через `Seconds` секунд игрового времени. Пока она ждёт, новый вход не учитывается.
  Отложенное продолжение выполняется в начале кадра, до остальных событий.
- **Каждые N секунд** срабатывает не чаще раза в кадр: длинный кадр не даёт пачку срабатываний.
- **Один раз** пропускает поток только в первый раз за Play; **Попеременно** чередует `A` и `B`.
- **Цикл** проходит `Body` для каждого целого `Index`; шаги тела считаются в общий лимит 10 000 за событие.
- **Вызвать событие** запускает все «Своё событие» с этим именем в скрипте `Target` сразу, внутри текущего события.
  События, вызывающие друг друга глубже 16 раз, останавливают скрипт с ошибкой. У объекта без скрипта ничего не происходит.
- **Создать копию** копирует тип объекта, модель, текстуру, материал, данные проекта, скрипт и значения его
  переменных, поворот и масштаб; копия встаёт в `Position` с именем `<образец>_N` и начинает работу со следующего кадра.
  Родитель, дети и настройки света не копируются. Тип должен быть известен игре (каталог проекта).
- **Удалить объект** убирает `Target` в конце кадра; объект может удалить и сам себя.

Новые «Случайное число», «Задержка» и «Цикл» получают полезные значения входов: `Max = 1`, `Seconds = 1`, `Last = 9`.

Позиция, поворот и масштаб — относительно родителя, поворот в градусах.

Клавиши задаются именем: `A`–`Z`, `D0`–`D9`, `F1`–`F12`, `NumPad0`–`NumPad9`, `Space`, `Enter`, `Escape`, `Tab`,
`Back`, стрелки `Left`/`Right`/`Up`/`Down`, `Shift`, `Control`, `Alt`, кнопки мыши `LeftButton`/`RightButton`/`MiddleButton` и др.

Ноды ввода смотрят на физическое состояние клавиши. Именованные действия `Input::System` не используются: в проекте
без C++ их негде объявить.

## Совместимость

- **Замороженные таблицы ABI не менялись:** Edit API v6, Scene API v4, модуль v5. Скрипты добавлены отдельным
  расширением. У старых `Game.dll` его нет: редактор не показывает скрипты, `SetScript` отвечает «только чтение».
- **Сцены.** Без скриптов файл прежний. Сцену со скриптом сборки до этапа 3 не откроют (поле `assets.script`).
- **`GameComponent` получил поле пути и экземпляр скрипта.** Engine — статическая библиотека, поэтому старые
  `Game.dll` с прежним SDK работают как раньше. Скрипты появляются в DLL, собранных с новым SDK, и в шаблоне
  проекта без кода.
- **Пользовательский `Game::TickComponents`.** Если он не вызывает `Game::TickComponents` или `Scene::Tick`, скрипты
  не получают «Каждый кадр» и события клавиш.

## Границы

- Один скрипт на объект. Значения переменных можно задать у объекта (карточка «Скрипт»); новые переменные в файле
  берут значение из скрипта.
- Нет функций и подграфов, массивов, событий столкновений; у своих событий нет параметров.
- Состояние скриптов (переменные, задержки, «Один раз») не попадает в SaveGame.
- Отладка — рамки выполнения и значения на выходах в Play; точек останова и пошагового выполнения нет.
- Нет reroute-нод; «Упорядочить» не двигает комментарии. История отмены не сохраняется между открытиями окна.
- Удалять файлы из Files нельзя (как и другие ресурсы). Карточка «Скрипт» не помечает пропавший файл.
- Окно не следит за правкой файла извне, пока открыто: последняя запись — его.
