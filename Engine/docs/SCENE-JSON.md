# Сцена в JSON и файловый API

Этап 041, 18.10.2026. Реализовано в Engine/runtime, без изменений Editor/Qt.
Основной контракт подключения DLL и viewport: [EDIT-SESSION-API.md](EDIT-SESSION-API.md).
Этот документ описывает формат, ошибки и действия будущего потребителя API.

## Что сохраняется

JSON — начальные данные сцены. В него входят имя сцены, имена и типы объектов,
локальные transforms, родители и наследование масштаба. Фабрика типа создаёт
настоящий пользовательский класс, скомпилированный в игровом DLL.
Сам код, Tick, произвольные поля C++, EngineProperty, GPU-ресурсы, геометрия,
материал, камера, таймеры, выделение и undo-история не сериализуются.
Геометрия/материал пока остаются теми, которые создаёт конструктор класса.
Каталожные visualDefaults остаются прежней заготовкой.

## Формат версии 1

Рекомендуемое расширение `.scene.json`; API не ограничивает расширение.
UTF-8; запись без BOM, чтение допускает UTF-8 BOM. Пример:

```json
{
  "version": 1,
  "name": "Example",
  "objects": [
    {
      "id": 10,
      "type": "RuntimeExample::Mover",
      "name": "Root",
      "parent": 0,
      "inheritParentScale": true,
      "transform": {
        "position": [0, 0, 0],
        "rotation": [0, 0, 0, 1],
        "scale": [1, 1, 1]
      }
    },
    {
      "id": 20,
      "type": "RuntimeExample::Mover",
      "name": "Child",
      "parent": 10,
      "inheritParentScale": false,
      "transform": {
        "position": [2, 0, 0],
        "rotation": [0, 0, 0, 1],
        "scale": [1, 1, 1]
      }
    }
  ]
}
```

Все показанные поля обязательны. Неизвестные поля и повторяющиеся JSON-ключи
считаются ошибкой: редактор не должен незаметно удалять неподдерживаемые данные.
Комментарии и завершающие запятые не разрешены. Порядок полей и объектов при чтении
не важен. Пустой массив objects допустим.

| Поле | Правило |
|---|---|
| version | Целое без знака, сейчас только 1; другая версия — UnsupportedVersion |
| name сцены | Непустая UTF-8 строка без NUL |
| id | Уникальное ненулевое целое uint64 внутри документа |
| type | Точный qualified C++ key из listTypes, регистр важен; это не displayName |
| name объекта | Непустая UTF-8 строка без NUL, уникальная в сцене |
| parent | 0 или существующий id этого документа; циклы запрещены |
| inheritParentScale | JSON boolean; false исключает масштаб родителя |
| position | Три конечных float, локальные координаты |
| rotation | Четыре конечных float, quaternion **x,y,z,w**, нормализуется Scene при восстановлении |
| scale | Три конечных float; abs каждой компоненты >= 1e-6, отрицательные допустимы |

Длина quaternion в квадрате должна быть конечной и >= 1e-12.
Ограничения: 16 MiB на файл, до 100000 объектов, глубина JSON до 16.
ID не проходит через double: значения uint64 читаются точно. Если сторонний
инструмент редактирует JSON через JavaScript, нужен парсер с точными большими целыми.

**ID файла — локальная ссылка, а не постоянный идентификатор объекта.** Загрузчик
создаёт новые runtime-ID и переназначает родителей вторым проходом. При следующем
сохранении числа могут измениться. SceneId и revision в JSON не записываются.
Нельзя хранить ссылки между файлами через эти ID. Переименование C++ класса меняет
type key: миграция старых файлов пока выполняется явно, автоматических aliases нет.

## ABI и совместимость

Публичные заголовки: `Engine/Runtime/EditSessionApi.h`,
`Engine/Runtime/SceneModuleApi.h`. **ENGINE_EDIT_API_VERSION теперь 2**:
в конец EngineEditSessionApi добавлены saveScene/loadScene. Игровой DLL, runtime
и потребителя edit API нужно пересобрать вместе. Версия 1 не поддерживается новым
edit export; проверка version/size отклоняет несовместимую таблицу до create/bind.
Основной ModuleApi остаётся v4; layout SceneModuleApi остаётся v1.

```cpp
uint32_t saveScene(void* context, const char* absolutePathUtf8,
                   char* error, uint32_t capacity);
uint32_t loadScene(void* context, const char* absolutePathUtf8,
                   uint64_t* newSceneId, char* error, uint32_t capacity);
```

Это указатели функций в полученной таблице `EngineEditSessionApi`.
Путь — абсолютный файловый путь UTF-8, не VFS alias. Родительский каталог должен
существовать. Save As — тот же saveScene с другим путём. Сессия не хранит текущий путь
и не открывает диалоги. Относительные пути отклоняются.

`newSceneId` обязателен: ноль при ошибке, новый SceneId при успехе.
`error` — необязательный буфер вызывающей стороны: используйте nullptr/0 или
действительный буфер с capacity, включающей место для NUL. При capacity > 0 буфер
обнуляется перед операцией. Текст ошибки ограничен размером буфера и может быть
обрезан; машинная обработка должна опираться на status, а не текст. При ранних
отказах Busy/ReadOnly/WrongThread текст может быть пустым.
Никакая выделенная память или C++ exception не пересекает DLL-границу.

Обе операции синхронны и выполняются на потоке создания сессии, между кадрами.
Не вызывайте их из callback listTypes/readScene, Tick или параллельно с frame.
Вложенный вызов возвращает Busy, чужой поток — WrongThread. Фоновый файловый ввод
и асинхронное создание объектов в этом этапе не реализованы.

## Загрузка как транзакция

1. Прочитать файл, разобрать JSON и проверить поля, ID, transforms и иерархию.
2. Проверить **все** type keys по текущему каталогу до вызова первого конструктора.
3. В отдельном Game/Scene вызвать фабрики, назначить данные и восстановить родителей.
4. Если viewport подключён, подготовить новую сцену на том же device/swapchain/HWND,
   сохранив положение камеры. При отказе освободить кандидата и восстановить targets старой сцены.
5. Только после успеха переключить SceneCommands и владение edit-сценой; удалить старую.

Ошибка файла, неизвестный тип, некорректная иерархия или исключение конструктора
не меняют старые SceneId, revision и объекты. Частичная загрузка/пропуск неизвестных
типов не допускаются. Внешние побочные действия пользовательского конструктора
движок отменить не может: конструктор должен оставаться edit-safe.
При отказе самого GPU восстановление отображения не гарантируется, но данные
старой сцены сохраняются. При скрытом viewport (нулевой размер) loadScene возвращает
Busy: повторить после ненулевого resize. Без viewport загрузка доступна сразу.

Полученные ранее таблицы `api` и `api.scene` **остаются действительными** после загрузки:
их context стабилен, команды переключаются на новую сцену. Все ссылки на прежние
объекты нужно считать недействительными, даже если числовой ObjectId совпал.
Используйте пару (SceneId, ObjectId). Revision имеет смысл только внутри одной сцены.

## Порядок подключения редактора

1. Получить/скопировать API через EngineBindEditSession v2 и заполнить список типов.
2. Для открытия выбранного документа отправить loadScene на поток движка. Можно
   загрузить до attachViewport; тогда первый кадр покажет уже загруженную сцену.
3. При ошибке показать status/текст; сохранить текущие дерево, выделение, путь и undo.
4. При успехе записать новый SceneId и путь, сбросить выделение, кеши объектов и undo,
   заново вызвать api.scene.readScene и построить дерево. Документ считать чистым.
5. Правки продолжать через прежние create/remove/rename/setTransform/setParent.
6. При Save отправить saveScene. Только при Ok обновить путь Save As и снять dirty.

```cpp
// Уже на потоке движка, вне callback API:
char error[1024]{};
uint64_t sceneId = 0;
auto status = api.loadScene(api.context, absolutePath.c_str(),
                           &sceneId, error, sizeof(error));
if (status == EngineSceneOk) {
    // Передать UI: документ заменён, sceneId, новый скопированный snapshot.
    // api.scene.readScene(api.scene.context, &info, visitor, &copiedRows);
} else {
    // Передать UI status и копию error; оставить текущий документ.
}
```

Реализация этих действий UI оставлена разработчику редактора. В этапе 041 runtime автоматически
не выбирает startupScene, не открывает диалог и не загружает Project.json-сцену.
Отдельного ABI setter/getter имени сцены пока нет; имя сохраняется из документа.

## Play, Pause, Stop и Save

| Операция | Edit | Play | Pause |
|---|---|---|---|
| loadScene | Заменяет edit при успехе | ReadOnly | ReadOnly |
| saveScene | Сохраняет edit | Сохраняет исходную edit | Сохраняет исходную edit |
| frame | Только изображение | Tick копии и изображение | Только изображение |

Play берёт актуальный snapshot edit, включая несохранённые правки, и вызывает тот же
SceneDocument::Restore, что загрузчик JSON. Дисковый файл для Play не нужен.
Pause сохраняет игровые объекты на месте; Stop уничтожает только игровую копию.
После загрузки → Play → Stop возвращается именно загруженная и отредактированная сцена.
Save не сбрасывает Pause, не останавливает игру и не записывает её текущие координаты.

## Безопасная запись и ошибки

Сначала полностью сериализуется и проверяется snapshot edit. Затем рядом с целевым
файлом создаётся уникальный временный файл через CREATE_NEW, записывается и flush-ится.
MoveFileExW с REPLACE_EXISTING/WRITE_THROUGH заменяет назначение только после успешной
записи и закрытия. При обычном отказе temp удаляется, прежний файл остаётся; при
аварийном завершении процесса temp может остаться. Это не резервное копирование и
не гарантия сохранности при аппаратном отказе накопителя.

| Status | Значение |
|---|---|
| Ok = 0 | Операция завершена |
| InvalidArgument = 1 | Путь/обязательный указатель/буфер некорректен |
| UnknownType = 2 | Каталог не содержит type из сцены |
| Busy = 5 | Вложенный вызов либо загрузка при нулевом размере viewport |
| Failure = 6 | Исключение фабрики, отказ подготовки viewport, другая внутренняя ошибка |
| WrongThread = 7 | Вызов с чужого потока |
| ReadOnly = 8 | Попытка загрузки во время Play/Pause |
| InvalidDocument = 10 | JSON, поля, UTF-8, лимиты, transforms или граф некорректны |
| IoError = 11 | Открытие, чтение, временная запись или замена файла не удались |
| UnsupportedVersion = 12 | Версия формата пока не поддержана |

## C++ API ядра и расширение

`Engine/Scene/SceneDocument.h` содержит Parse/Serialize (строка ↔ SceneSnapshot),
Read/Write (файл), Validate (структура и каталог), Restore (фабрики и иерархия).
Это внутримодульный C++ API, не DLL ABI. Ошибки документа — SceneDocumentError со
status; ошибки фабрики могут выбрасывать другие исключения. Restore требует пустую
сцену и **не обеспечивает транзакцию сам**: при отказе кандидат должен быть уничтожен.
SceneEditSession обеспечивает транзакцию владением отдельным кандидатом.
Standalone-загрузчик впоследствии может использовать тот же механизм.

Свойства и ссылки на ресурсы потребуют явно согласованной версии формата и миграции.
Несколько документов возможны через отдельные сессии, но UI вкладок, additive-сцены,
cross-scene ссылки, hot reload и Apply Play Changes этим этапом не реализуются.
Парсер — vendored nlohmann/json 3.11.3 (MIT), приватная зависимость реализации;
для сборки не нужны скачивания или новый пакетный менеджер.
