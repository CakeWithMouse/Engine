# Сохранение, совместимость, экспорт и группы — 2026.10.31.0

## Сцены и восстановление

**Сцена → Сохранить сцену** / Ctrl+S записывает только текущую сцену.
**Сцена → Сделать стартовой сценой** сначала сохраняет её, затем отдельно меняет
`startupScene` в Project.json. Встроенный Play использует текущую редакторскую
копию; отдельная игра и экспорт используют сохранённую стартовую сцену.

Каждые 30 секунд изменённая сцена в Edit записывается в `.painengine/Recovery`
проекта. Основной файл сцены не перезаписывается. Снимок содержит время,
исходный путь, версию runtime и идентификатор DLL. Каждый процесс использует
собственный файл блокировки, поэтому работающий редактор не предлагается как
аварийная сессия. После успешного сохранения или явного отказа от изменений
снимок текущей сессии удаляется.

После аварийного завершения при открытии предлагается восстановить отдельную
несохранённую копию. Команда восстановления также находится в меню «Сцена».
Сохраните восстановленную копию через «Сохранить как». Исходный документ и
стартовая сцена автоматически не заменяются. Если игровой кодек или ресурс
больше не совместимы, загрузка отклоняется, а восстановительный файл остаётся.
Текст HLSL и несохранённые правки отдельных материалов в снимок сцены не входят.

## Старый проект на новом движке

Нажмите обычную кнопку **Играть** или **Редактировать**. Если проект закреплён
за более старой версией, лаунчер покажет обе версии и предложит переход:

- **Обновить копию и запустить** — создать соседнюю папку с номером новой версии,
  проверить и обновить сцены, закрепить новую версию и запустить копию в выбранном режиме.
  Известная штатная DLL заменяется актуальным шаблоном; пользовательская DLL сохраняется.
- **Открыть на прежней версии** — запустить исходный проект на закреплённом runtime.
  Если он не установлен, этот вариант недоступен.
- **Отмена** — ничего не обновлять и не запускать.

Исходная папка сохраняется. Путь копии показан до подтверждения; существующие
папки не перезаписываются. После успеха копия выбирается в библиотеке проектов;
при её следующем запуске повторного вопроса нет. Ошибка обновления не публикует
частичную копию. Для более новой версии проекта автоматическое понижение не предлагается.
Номер без закрепления или с нестандартным текстовым обозначением не угадывается.

Отдельных кнопок запуска на текущем движке в интерфейсе нет. Для диагностики
совместимости без миграции остаётся явный параметр командной строки; он запускает
исходную DLL, не меняя Engine.lock.json и формат сцены:

Из командной строки:

```powershell
./EngineRuntime.exe --project 'D:/MyGame/Project.json' --mode editor --scene-api --compatible-engine
./EngineRuntime.exe --project 'D:/MyGame/Project.json' --mode game --compatible-engine
```

Поддерживается согласование существующих Edit API 4, 5, 6 и Module API 5.
Проверяются настоящие сохранённые DLL выпусков до света и со светом, а не их
пересобранные аналоги. Неизвестный ABI, отсутствующие зависимости или неизвестные
данные дают ошибку; старый проект при этом сохраняется. Возможности самого
старого игрового модуля остаются прежними: новая версия интерфейса не добавляет
старой DLL новые типы или API группового редактирования.

Для новых возможностей штатного шаблона используйте «Обновить копию проекта».
Для своего C++-модуля нужна пересборка копии проекта актуальным SDK. В выпуске
2026.10.31.0 изменён внутренний C++ layout Game; смешивать старые заголовки с
новой Engine.lib нельзя. Базовые таблицы C API не изменены.

## Экспорт игры

Используйте **Экспорт игры…** в Release-редакторе либо **Проект → Экспорт игры
на текущем движке…** в лаунчере. Редактор сначала предлагает сохранить сцену
и завершить редактирование материалов. Экспортируется назначенная стартовая сцена.
Укажите новую папку вне проекта и runtime; существующая папка не заменяется.

```powershell
./Engine/BuildSupport/Export-Project.ps1 -Project 'D:/MyGame/Project.json' -Destination 'D:/Exports/MyGame'
```

Экспорт включает текущий Release runtime, DLL игры и соседние DLL-зависимости,
EngineContent, распространяемые DLL Visual C++ и весь Content проекта. SDK, инструменты импорта, исходники проекта и его Binaries-
история не нужны получателю. `Start.cmd` запускает игру относительно своей папки;
глобальная установка движка и Visual Studio не используются для выбора runtime.
Перенос проверен на этой машине с недоступным исходным проектом. Проверка на
чистой Windows-машине с другой видеокартой остаётся отдельной проверкой перед выпуском игры.

Перед публикацией проверяются сцены через игровую DLL и отдельный запуск на
три кадра. Абсолютные/выходящие за Content ссылки материалов и отсутствующие
ресурсы отклоняются. При отказе опубликованной папки нет, временная папка с
Validation.log/GameSmoke.log остаётся для диагностики. Состав пакета и версии
записаны в ExportReport.json. Hardcoded пути и дополнительные файлы, которые
произвольная игровая логика открывает вне Content, автор должен перенести в Content.

## Групповое редактирование

Для актуальной игровой DLL поддержаны Ctrl/Shift-выделение в иерархии и
Ctrl/Shift-клик в viewport. Обычный клик по уже выбранному объекту сохраняет
группу для перетаскивания и делает объект активным. Инспектор сообщает размер
группы. Трансформация рассчитывается относительно активного объекта; прочие
свойства инспектора относятся к активному объекту.

Перемещение, поворот и масштаб применяются к группе. Если выбраны родитель и
ребёнок, перемещается корень: ребёнок не получает преобразование дважды.
Выбранный предок становится активной точкой преобразования такой группы.
Сдвиг, который невозможно представить обычными position/rotation/scale без
shear, отклоняется с пояснением. На панели «Привязки» задаются шаг перемещения
и угла для мыши; 0 отключает привязку. Один drag — один Undo.

Ctrl+D и удаление группы выполняются целиком. В групповую операцию входят
поддеревья выбранных родителей; копируются модели, материалы, свет и пользовательские
данные. Объявленные автором ссылки перенаправляются через RemapProjectReferences.
Ошибка не публикует частично изменённую сцену. Undo/Redo работают со всей операцией.

Расширение `Engine.Editor.Batch` v1 является необязательным. В старой DLL без
этого расширения иерархия остаётся с одиночным выделением. После Hot Reload
runtime заново предоставляет API активного модуля; старые указатели не кэшируются.

## Проверки

- `Engine/tests/run.ps1 -Configuration Release -PlatformToolset auto`: ядро и группы из 100 объектов.
- `Engine/tests/workflow-delivery/run.ps1`: Qt-группа/Undo, сохранение без смены startupScene,
  реальное завершение тестового процесса, восстановление в новом процессе, переносимый экспорт и отказы.
- `Engine/tests/compatibility/run.ps1 -IncludeUi`: исторические DLL, адаптеры, старые закреплённые проекты на новом runtime.
- `Engine/tests/compatibility/upgrade-prompt.ps1`: реальный диалог обновления при запуске, отмена, игра/редактор, сохранность оригинала, отказ миграции и отсутствие повторного вопроса.
- `Editor/tests/run.ps1 -Configuration Release -EnableAssimp`: полный обычный сценарий интерфейса.

Qt создаёт приватные временные каталоги. В ограниченном sandbox тест может получить
Windows error 5; для проверки обычной работы запускайте его с правами текущего пользователя.
