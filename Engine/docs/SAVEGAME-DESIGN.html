SaveGame

Продолжить игровую партию после закрытия игры.

Архив первоначального предложения. Контракт изменён: сцена и базовые классы сохраняются движком, наследники дописывают поля. Актуальная схема реализации. Шаги ниже описывают старый проект.

Кто хранит данные и кто управляет жизненным циклом

Уже существуетПредлагается добавить
1 / Код конкретной игры
↓ RequestSave / RequestLoad
↓ DTO → версионированный payload
2 / Engine внутри игровой DLL
↓ безопасная граница кадра
↔ только versioned C ABI
3 / Runtime host, вне заменяемой сессии
↓ host-owned байты, без Game*
↓ temp → flush → replace

Связь колонок: игра вызывает facade; facade и module adapter общаются с координатором через необязательный C ABI extension и host service. STL, указатели и владение игровыми объектами границу DLL не пересекают.

      Порядок внедрения

      1. Контейнер + stable gameId + атомарное хранилище слотов.
      2. Codec и захват на границе кадра, пример экономики.
      3. Загрузка из меню в новую сессию с remap ссылок.
      4. Подготовка кандидата и безопасная загрузка из живой игры.
      5. Совместимость старых DLL, SDK-пример, проверки editor и export.
      Полный план: формат, ABI, ограничения и критерии тестов

      Текущие опоры: GameSession, GameSubsystem, SceneModule, SceneDocument, Scene, host.getService. SaveGame не заменяет сохранение проекта или recovery редактора.
