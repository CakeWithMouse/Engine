# SaveGame: сохранение сцены и состояния игры

Реализовано в 2026.11.05.0. API находится в `Engine/SaveGame/SaveGame.h` и
`Engine/SaveGame/SaveArchive.h`. Это module-local C++ API нового SDK: STL и JSON не
пересекают границу DLL. Существующие Module/Edit API не изменены.

[HTML-схема архитектуры и действий разработчика](SAVEGAME.html).

## Подключение

В конструкторе своей Game или один раз при старте:

```cpp
#include <Engine/SaveGame/SaveGame.h>
Saves().Configure("my-stable-game-id");
```

ID — стабильная строка из ASCII букв, цифр, `-` и `_`, длиной до 64 символов.
Не меняйте её при переименовании проекта или выпуске обновления. Каталог компонентов
подключается автоматически в SceneModule и Play редактора. Standalone-приложение
дополнительно вызывает `Saves().SetCatalog(catalog)` с каталогом своих типов.
Массив каталога должен жить дольше экземпляра Game.

Файлы: `%LOCALAPPDATA%/PainEngine/Saves/<gameId>/default/<slot>.save.json`.
Для тестов второй аргумент `Configure` задаёт отдельный абсолютный корень.
Слоты имеют такие же ограничения имён. Сохранения не изменяют исходную сцену и ассеты.

```cpp
auto request = GetGame()->Saves().RequestSave("manual-1");
// Accepted означает постановку в очередь. Busy — другая операция уже выполняется.
const auto& result = GetGame()->Saves().LastResult();
// Проверяйте ticket и status: Saved / Loaded / Failed. message содержит диагностику.
GetGame()->Saves().RequestLoad("manual-1");
auto slots = GetGame()->Saves().ListSlots();
GetGame()->Saves().DeleteSlot("manual-1");
```

Запрос выполняется в потоке игры после завершения обновления сцены и применения
отложенных Add/Remove. В безоконном host после завершения своего update можно вызвать
`ProcessPending()`. Внутри обхода сцены этот метод откладывает операцию. Прямые
`Capture()`/`Restore(bytes)` предназначены для host/тестов вне update; файл по-прежнему
можно записать через `WriteSlot`, прочитать через `ReadSlot`. Первый формат — UTF-8 JSON,
максимум 16 MiB; запись синхронная. Не вызывайте API из рабочего потока.

## Что сохраняет движок

| Владелец | Состояние |
|---|---|
| Scene | Имя, состав объектов, типы, имена, локальные transform, иерархия, наследование масштаба, ссылки на ассеты, project properties |
| GameComponent | Цвет, collision/opacity, UV, trace channels, reflection, static-shadow, скорости базового класса, shader names, простые экземпляры, назначенная процедурная геометрия |
| MeshComponent / InstancedMeshComponent | CPU mesh, LOD-геометрия и параметры, экземпляры с положением, цветом и фазой анимации |
| SkeletalMeshComponent | Ассет из сцены, клип, время и скорость анимации, флаг проигрывания, yaw |
| ParticleSystemComponent | Параметры эмиттера и время; GPU-частицы создаются заново |
| Character / Camera / Light | Существующие сериализуемые свойства и ссылки, плюс базовое состояние компонента |
| UIComponent | Дерево разметки, текст, видимость и поддерживаемые UI-свойства; обработчики назначает код |
| Game / Player / CharacterController | Время, масштаб времени, simulation enabled, настройки рендера, камера, управление и ссылки контроллера |
| GameSubsystem | Включённость Tick; дополнительные поля задаёт наследник |

Состояние UI-кнопки «Pause» редактора остаётся состоянием editor host; файл содержит
флаг симуляции Game. Ресурсы GPU, внешние callback, указатели и файловые/сетевые операции
не сериализуются. Изменение исходного `.mat` остаётся изменением ассета: snapshot хранит
назначение материала, а не копию всех ресурсов проекта. Процедурные GPU animation textures
и cubemap cache воссоздаются конструктором/инициализацией класса.

Каждый создаваемый объект должен иметь фабрику в каталоге. Лучше передавать type ID
в `Scene::AddComponent`. Для старого `RegisterComponent` движок ищет точное совпадение
типа с фабрикой; неизвестный наследник вызывает ошибку, а не превращается в базовый класс.
Производные классы используют `ENGINE_COMPONENT` и конструктор без аргументов.

## Наследование

Движок не содержит правил конкретной игры. Наследник записывает только свои поля:

```cpp
void Car::SerializeSaveGame(SaveArchive& archive) {
    CubeComponent::SerializeSaveGame(archive);
    archive.Section("MyGame.Car", [&](SaveArchive& state) {
        state.Version(1);
        state.Field("routeTime", routeTime);
        state.Field("moving", moving);
        state.Reference("target", targetComponentId);
    });
}
```

Тот же override доступен у Game, GameSubsystem и CharacterController. Вызывайте
непосредственного родителя и используйте уникальную секцию. Field поддерживает числа,
bool, строки, GLM-векторы и JSON-совместимые контейнеры. Отсутствующее новое поле оставляет
значение по умолчанию, будущая версия секции отклоняется. Для существенной смены схемы
нужна явная миграция своего класса; не переиспользуйте имя старого поля с другим смыслом.

`SerializeSaveGame` только читает/записывает состояние: никаких спавнов, IO, подписок или
других внешних действий. Чтение может происходить при подготовке или откате неудачной
загрузки. Выбрасывайте исключение для некорректных значений; собственное корректное
сохранённое состояние должно всегда восстанавливаться.

ComponentId не постоянен: `Reference` переназначает его по таблице сохранённых объектов
после создания всей сцены. Не сохраняйте адреса объектов. Подсистема может обновить
кэшированные указатели в `OnSaveGameLoaded(Scene&)`.

Восстановленные компоненты заново получают BeginPlay, чтобы создать подписки на ввод.
`WasLoadedFromSaveGame()` позволяет отделить эту настройку от начального спавна или
обнуления прогресса. После загрузки старые указатели на компоненты недействительны.
Game и подсистемы сохраняют свой экземпляр; AfterInitialize повторно не вызывается.
При загрузке до первого запуска уведомления OnSaveGameLoaded откладываются до SceneReady.
Камера и HUD восстанавливаются заранее и сохраняются при инициализации. В первом
AfterInitialize проверяйте WasLoadedFromSaveGame перед созданием стартовых объектов.
Остановка сессии отменяет ещё не выполненный запрос сохранения или загрузки.

## Ошибки и загрузка

До смены активной сцены полностью создаётся отдельная CPU-сцена, проверяются типы,
свойства и ссылки, восстанавливаются поля компонентов. Некорректный файл не уничтожает
текущий мир. Изменение полей Game/подсистем имеет резерв для отката. После подготовки
меняется содержимое сцены, сбрасываются старые input bindings и переназначается контроллер.
Ошибки post-load уведомлений уже после смены мира оставляют загруженный мир на паузе и
возвращают Loaded с диагностикой; это не Failed с обещанием сохранить прежний мир.

Запись идёт во временный файл рядом со слотом, затем Flush и атомарная замена. Отказ
замены сохраняет прежний слот, временный файл удаляется. Запрещены traversal и reparse
points внутри выбранного пути. Удаление слота отсутствует в очереди: это явная операция.

## Проверка без редактора

`Engine/tests/savegame/run.ps1 -Configuration Release` собирает и запускает реальные
проверки, включая запись и чтение разными процессами. Команды EngineCommandlets:
`savegame.save`, `load`, `validate`, `list`, `delete` — см. COMMANDLETS.md.
Commandlet использует встроенные типы; пользовательская DLL проверяется своим игровым
проектом или host, подключающим его каталог. Команды не подменяют код игры.
