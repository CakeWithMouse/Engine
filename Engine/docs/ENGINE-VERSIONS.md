# Версии движка и совместимость проектов

Каждый выпуск имеет собственный номер в `Engine/Version.json`. Текущий выпуск —
`2026.10.26.0`. В дистрибутиве номер находится в `Runtime/EngineVersion.json`,
конфигурация — в `Runtime/EngineConfiguration.txt`.

Для двух ранее выданных архивов назначены номера:

| Версия | Содержимое |
|---|---|
| 2026.10.24.0 | Исходный выпуск до добавления света, Edit API 4 / Scene API 2 |
| 2026.10.24.1 | Выпуск со светом, Edit API 5 / Scene API 3 |
| 2026.10.24.2 | Версии проектов, адаптер старых DLL, расширения и миграции |
| 2026.10.25.0 | C++ SDK, пользовательские Game / Component / Object, projectData и формат сцены 3 |
| 2026.10.26.0 | Искры, дым, процедурное небо, категории размещения и расширение Engine.Editor.Selection v1 |

Старые runtime поставляются в `Engines/<версия>/Release`, с исходными DLL и
зависимостями. Новые метаданные не меняют их двоичные файлы.

## Как пользоваться

Запускайте проекты через `EngineLauncher.exe`. Новый проект содержит
`Engine.lock.json` с версией движка и конфигурацией. Лаунчер выбирает именно эту
версию: сначала из `%LOCALAPPDATA%/PainEngine/Engines`, затем из каталога `Engines`
рядом с лаунчером, затем текущий runtime, если номер совпадает. Отсутствующая
версия вызывает понятную ошибку; другой движок автоматически не подставляется.

При обычном запуске лаунчер сохраняет текущий runtime в хранилище версий.
**Добавить версию…** устанавливает другой распакованный выпуск: выберите корень
пакета или его папку Runtime. Уже установленный выпуск не заменяется новыми
бинарниками под тем же номером.

Для старого проекта без номера есть два варианта:

- Открыть сразу: новый редактор согласует API с исходной Game.dll. Модуль без
  поддержки света продолжает работать со своим прежним набором объектов.
- **Закрепить версию…**: выбрать соответствующий Runtime. Для самого первого
  архива это `Engines/2026.10.24.0/Release`. Лаунчер установит выбранный runtime
  и запишет привязку в проект. Существующий lock сохраняется в резервную копию.

**Обновить копию…** создаёт новую папку проекта на текущем выпуске. Оригинал
остаётся на месте. Штатная Game.dll обновляется только при совпадении SHA-256
с известным шаблоном. Пользовательская DLL со своим кодом сохраняется.
Отчёт записывается в `UpgradeReport.json`. Это явное обновление; обычное открытие
и сохранение не переводят сцену на другую версию формата.

При переносе на другой компьютер копируйте весь проект и нужный дистрибутив
движка. В проекте по-прежнему находится собственная Game.dll. Изменение только
Engine.lock.json не выполняет миграцию сцен и игрового кода.

## Форматы и API

Выпуск 2026.10.27.0 добавляет Input::System, Character/SceneCamera/PlaySettings,
CharacterController и BeginPlay компонентов. C++ ABI изменён: пересоберите
пользовательскую DLL через SDK нового выпуска в обновлённой копии проекта.
Сцены остаются в форматах 1–3. C API не менялись; ввод редактора использует
необязательное расширение Engine.Viewport.Input v1. См. [руководство](INPUT-CHARACTER.md).

Project.json сохраняет прежний набор полей. Версия хранится в отдельном файле,
чтобы старые runtime могли читать исходный проект. Формат lock:

```json
{"format":1,"engineVersion":"2026.10.24.2","engineConfiguration":"Release","templateId":"SceneProject"}
```

Текущие базовые C API фиксированы: Module 5, Edit 5, Scene 3. Адаптер отдельно
описывает исторические Edit 4 / Scene 2 и переводит снимки объектов. Старые
структуры не приводятся к новым типам указателей. Новые возможности следует
добавлять через `EngineGetEditExtension`, с отдельным именем, версией и размером
выходной таблицы. Неизвестное расширение возвращает false без изменения буфера.
Сейчас доступны `Engine.Scene.PointLight`, `Engine.Scene.Document`, `Engine.Project.Data` и `Engine.Editor.Selection` версии 1.
Заголовок: `Engine/Include/Engine/Runtime/EditExtensions.h`.

Данные пользовательских классов описаны отдельно в `ProjectDataApi.h`; базовые C API не менялись. C++ SDK требует совпадения выпуска, конфигурации, архитектуры и toolset. Пересборка игры меняет build ID и путь DLL, но не версию движка. Подробности: [проекты с C++](CODE-PROJECTS.md).

Сцены v1 продолжают читаться и сохраняться как v1. Явное обновление штатного
проекта переводит их в v2: свет хранится в `properties/Engine.PointLight` с
собственной версией 1. Миграция сначала работает во временной копии, затем
проверяет каждую сцену через целевую DLL и только после успеха публикует папку.
Неизвестные поля, типы и версии вызывают отказ, а не потерю данных. Обратного
автоматического преобразования нет. Для старой пользовательской DLL без
расширения Document остаётся формат v1.

Закреплённый выпуск сохраняет прежнее поведение проекта даже при дальнейшем
изменении движка. Это не обещание совместимости произвольных новых C++ классов
с любой старой DLL: такой код обновляется отдельно и проверяется в копии проекта.

## Правила выпуска и регрессии

1. Перед выпуском меняйте номер в Engine/Version.json. Номер опубликованного
   выпуска неизменяем; исправления получают новый номер.
2. Не меняйте размеры и смысл существующих базовых API. Добавляйте независимое
   расширение или новый явно согласуемый интерфейс, сохраняя старый адаптер.
3. Для нового формата добавляйте явную миграцию и тест сохранности исходника.
4. Добавляйте реальные опубликованные DLL в `Engine/tests/compatibility/fixtures`
   вместе с зависимостями, лицензиями и SHA-256. Не пересобирайте эти эталоны.
5. Выпускайте через `Engine/BuildSupport/New-Release.ps1`. Скрипт собирает Release,
   запускает тесты старых DLL и Qt, проверяет приложения из пакета и оба старых
   runtime, создаёт SHA256SUMS.txt и проверяет целостность RAR.

Отдельная проверка: `Engine/tests/compatibility/run.ps1 -IncludeUi`.
Она использует временные проекты и отдельное хранилище движков; проекты
пользователя не затрагиваются. Для автоматизации доступна переменная
`PAINENGINE_ENGINE_STORE` с абсолютным путём.

CLI лаунчера: `--install-engine <runtime>` и
`--upgrade-project <Project.json> <новая-папка>`. Вторая команда не перезаписывает
существующую папку назначения.
