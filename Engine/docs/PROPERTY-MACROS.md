# Свойства C++ без ручного JSON

Аннотация ставится непосредственно над полем. Имя поля и его тип генератор читает из объявления; повторять имя в макросе не нужно.

```cpp
#include <Engine/Components/SpecificComponents/CubeComponent.h>
#include <Engine/Components/PropertyMacros.h>

ENGINE_COMPONENT("Вращающийся куб")
class Rotator : public CubeComponent
{
public:
    ENGINE_GENERATED_PROPERTIES(CubeComponent)

    Rotator() { }
    void Tick(float dt) override {
        if (enabled) SetRotation(GetRotation() + glm::vec3(0, speed * dt, 0));
    }

private:
    ENGINE_PROPERTY("Скорость, градусов/с", -720, 720)
    float speed = 90;

    ENGINE_PROPERTY("Вращение включено")
    bool enabled = true;

    ENGINE_ENUM_PROPERTY("Режим", {0, "Обычный"}, {1, "Обратный"})
    int mode = 0;
};
```

`ENGINE_GENERATED_PROPERTIES(Base)` указывается один раз в public-секции; Base — непосредственный базовый класс. Макрос объявляет методы описания, сохранения и загрузки. ComponentGenerator реализует их в GeneratedComponents.cpp при сборке проекта. Ручной JSON и отдельный список полей не нужны. Работают public, protected и private-поля, а также final-классы и namespace.

Метод DescribeEditorProperties уже есть у GameComponent: дополнительное наследование не нужно. Старый EditorPropertyProvider сохранён для совместимости исходников; существующие классы с ним можно пересобрать без изменений. Базовые данные и описание полей наследуются. Не объявляйте повторно SaveProjectData, LoadProjectData или DescribeEditorProperties в классе с этим макросом. Ручные кодеки по-прежнему поддерживаются.

Поддержаны `bool`, `int`, `float`, `double`, `std::string`, `int32_t`, `uint32_t`, `int64_t`, `uint64_t`. На одну аннотацию — одно изменяемое поле. Инициализация через `=` и `{}` допустима. Указатели, ссылки, массивы, const/static-поля, условные объявления через #if и свойства в неотмеченных классах отклоняются с диагностикой файла и строки. Для выбора из списка используйте ENGINE_ENUM_PROPERTY с целочисленным или логическим полем.

Имя C++-поля — ключ сохранённых данных. Подпись можно менять свободно; переименование самого поля требует миграции старых сцен. Отсутствующее в старой сцене поле сохраняет текущее значение (для нового объекта — значение конструктора). Числа проверяются по типу, диапазону и конечности; строки ограничены 4096 байтами. Формат данных — версия 1.

Поля попадают в сцену, Undo/Redo, дублирование и копию для Play. Для зависимых настроек и немедленного обновления внешнего вида можно добавить публичный `void OnPropertiesChanged()`. Он вызывается после загрузки полей; исключение отменяет изменения. Hook должен быть детерминированным и не выполнять необратимые внешние действия.

После обновления SDK пересоберите проект: новый синтаксис требует обновлённого ComponentGenerator. Внутренние типы движка, которые не проходят генерацию проекта, используют служебные ENGINE_PROPERTY_FIELD / ENGINE_ENUM_PROPERTY_FIELD внутри явного кодека; автору проекта они не нужны.

## Перенос существующих проектов

Обновляйте проект штатной командой переноса в новую папку: исходник остаётся на прежней версии. Формат projectData и API обмена с DLL не меняются. Известный стандартный модуль заменяется модулем нового выпуска; пользовательский DLL сохраняется и работает через прежний API. Новые возможности базового C++-класса доступны после пересборки с SDK целевого выпуска. Не смешивайте заголовки нового SDK со старым Engine.lib.

Старое явное наследование от EditorPropertyProvider и ручные DescribeEditorProperties / SaveProjectData / LoadProjectData продолжают компилироваться. Удалять наследование можно постепенно. Имена полей в projectData не меняются; отсутствующие в старой сцене новые поля получают значения конструктора.
