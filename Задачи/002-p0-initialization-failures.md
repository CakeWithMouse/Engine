# P0. Ошибки инициализации не останавливают дальнейшую работу

## Где

`Game::Initialize`, `CreateDeviceAndSwapChain`, `CreateDepthBuffer`, `CreateBackBuffer`, `InitShaderBuffers`.

## Проблема

После неудачи `CreateDeviceAndSwapChain` печатается сообщение, но затем вызывается `InitRenderTarget`, использующий `SwapChain`. Ошибки depth texture/DSV не прекращают последовательность создания ресурсов. `Initialize` возвращает `void`, поэтому вызывающая сторона не получает признак готовности. `InitShaderBuffers` объявлена возвращающей `HRESULT`, но в конце успешного пути нет `return`; результат создания input layout также не проверяется. `CreateBackBuffer` скрывает неудачу от своего вызывающего кода.

Список feature levels доходит до 9.x, хотя используемые shaders требуют SM5 и GPU-частицы используют compute.

## Исправление

Возвращать результат всей инициализации и не входить в `Run` при неудаче. Передавать ошибки вверх, создавать ресурсы во временных RAII-объектах и публиковать их только после успеха. У `InitShaderBuffers` должны быть определенные return values на всех путях. Минимальный feature level согласовать с возможностями renderer.

## Критерий приемки

Отсутствие HLSL/ошибка shader/device creation дает понятный отказ и освобождение уже созданных ресурсов, без перехода к невалидным draw.
