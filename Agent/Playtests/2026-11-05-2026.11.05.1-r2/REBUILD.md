# Как продолжить проекты этого круга

Архивы содержат исходники и контент, без SDK, DLL и промежуточных файлов.
Их `Project.json` может ссылаться на DLL исторической сборки: это свидетельство
прогона, а не готовая двоичная поставка. Smoke или Upgrade до сборки такого
архива не подтверждает совместимость и может закономерно завершиться отказом.

Проверенные локальные Runtime находятся в `Engine/build/playtests/20261105-r2`:
`Runtime` — исходная .1, `fixed/Runtime` — .2, `final/Runtime` — .3.
`final4/Runtime` — исправленная .4, включая обычные primitive CreateInstance.
`final5/Runtime` — итоговая .5, также исправлена загрузка отложенных текстур.
Соседний `EngineLauncher.exe` создаёт проект, закреплённый за своей версией.
Основная рабочая поставка — `Game/build/x64/Release/Runtime`.

Для продолжения на текущем SDK:

1. Распаковать выбранный архив в новый каталог с исходниками, сохранив пути.
2. Создать **другой новый** проект штатными `--create-project` и `--enable-code`.
   Дождаться обоих процессов, проверить exit code и `CodeBuild.log`.
3. В новый проект перенести `Source` и `Content` из архива. У всех четырёх
   проектов есть собственный `Module.cpp`; заменить соответствующие файлы
   шаблона. Сохранить свежие `Engine.lock.json`, `Build.ps1`, `Game.vcxproj`
   и метаданные сборки. Если в архиве другая стартовая сцена, перенести её
   относительный путь в `startupScene` свежего `Project.json`.
4. Выполнить `Build.ps1 -Runtime '<абсолютный путь к Runtime>'` в новом проекте.
   Генератор пересоздаст каталог игровых типов, сборка активирует новую DLL.
5. Запустить игру и проверить описанный в дневнике эффект, затем Save/Load в
   новом процессе. Одного exit 0 недостаточно для визуальной проверки.

Точные команды создания и ожидания GUI launcher:
[`LAUNCHER-CLI.md`](../../../Engine/docs/LAUNCHER-CLI.md).
Контракты игровых проверок: [`COMMANDLETS.md`](../../../Engine/docs/COMMANDLETS.md).
Пути этих двух ссылок от корня репозитория: `Engine/docs/...`.

Нужны Windows, MSVC C++/Windows SDK, соответствующий Runtime SDK и D3D11.
Для `.blend` также нужен установленный Blender; Assimp входит в проверенную
поставку. При ограниченном sandbox сборки этого прогона требовали обычного
MSVC-окружения вне sandbox (зафиксированный LNK1101/MSPDB не был дефектом SDK).
Проверки редактора используют writable scratch TEMP/TMP.

Не копировать экспериментальные сохранения поверх собственных слотов игры.
Переменные окружения и параметры конкретных опытов перечислены в дневниках;
они включают и намеренные отрицательные сценарии.
