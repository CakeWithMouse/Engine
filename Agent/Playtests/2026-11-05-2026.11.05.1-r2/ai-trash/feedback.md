# Итоговый отзыв — роль 4, «AI Trash»

В текущем C++ сценарии бросок уже считает попадания/промахи и точность, держит состояние раунда в SaveGame, восстанавливает полёт в новом процессе, принимает настоящий held T и HUD click, а также переживает hot reload. В завершение я проверил тот же игровой проект на отдельной копии frozen SDK `.4`, не меняя `TrashGameDev`.

Попадание теперь создаёт маленький одноразовый Spark burst у ведра. В реальном D3D кадре после броска HUD показывает 1/1 и 100% точности, а частицы видны вокруг ведра. Включение/отключение depth collision и сортировки было измерено на серии кадров одной фазы. Разница сортировки на замороженном наборе пикселей небольшая, а пара collision кадров сдвинута на один sim tick; поэтому collision/sorting оставлены `partial`, без заявления, что сравнение доказывает их эффект.

Forward, Deferred и Deferred с G-buffer overlay реально отрисовали один и тот же Trash HUD. G-buffer кадр показывает четыре диагностические области. Публичный `OnWindowResized` перевёл backbuffer с 640×480 на 320×240; размеры подтверждены BMP header, а HUD сохранился на обоих кадрах.

Отдельный native Windows Qt запуск уже содержал CodeClassDialog проверки: запрещённые имена, сохранение отклонённого ввода, Character default/header, запрет self-inheritance/duplicate и корректные Object arguments. Это частичная проверка мастера; UI создание всех четырёх class kinds не заявляю.

Основные оставшиеся ограничения — глубже измерить причинный эффект depth collision на одних и тех же частицах и сделать эффект sorting визуально различимым для многослойной прозрачности. GUI ручной сценарий по-прежнему не проверялся CUA; приложенные UI результаты пришли из автоматизированного native-window suite.
