## BUG-VIS-001: скачки сетки каскадов

Световой AABB среза frustum менял ширину при yaw, ступенчатый `ceil` в
`SnapShadowBounds` перескакивал между размерами. World-anchored origin
устранял только движение начала, но не масштабирование всей сетки.

Воспроизведение — поддерживаемый Battle CLI, 1000 статичных машин, camera 120,
без точечной лампы, 121 кадр на сценарий. Движение задаётся номером кадра,
не wall time: orbit 0.0005 rad/кадр, pan/dolly 0.01 единицы/кадр.
Матрицы берутся из завершённого рендера, парного BMP.

| Сценарий | Изменения XY-масштаба до, каскады 0/1/2 | После | Максимальный дробный сдвиг сетки до → после |
|---|---:|---:|---:|
| orbit | 2 / 3 / 3 | 0 / 0 / 0 | 0.4373 → <0.000001 texel |
| pan | 0 / 0 / 0 | 0 / 0 / 0 | <0.000004 → <0.000001 texel |
| dolly | 0 / 1 / 0 | 0 / 0 / 0 | 0.4088 → <0.000001 texel |

`AnalyzeShadowCameraSequence.py --check` отвергает исходный orbit (exit 1)
и принимает исправленные три сценария. Целые шаги сетки исключаются из
измерения: это необходимое перемещение карты, не изменение её фазы.
`baseline-*.csv`, `baseline-metrics.json`, `stable-metrics.json` сохраняют
сырые данные; все кадры остаются в рабочем каталоге.

Исправление: аналитическая sphere-fit проекция, целочисленный origin,
сохранение точного extent при построении матрицы. Для адаптивных splits
радиус сохраняется с запасом 10%, уменьшается только ниже порога 75%.
Полный yaw sweep проверяет покрытие углов, переходы по сетке и постоянный
масштаб; отдельная регрессия проверяет growth/shrink и изменение FOV.

## BUG-VIS-002: выбор соседнего каскада у края экрана

CPU строит срезы по глубине вдоль взгляда, а Common/BaseSphereFigure использовали
радиальное расстояние. При split=100 точка camera-space (60,0,90) попадала
в каскад 1 вместо 0. Реальный WARP shader test включал production helper:
исходная формула прошла on-axis и провалила off-axis проверку
(`selection-before3.log`, 62/63). Исправление использует view-space Z;
добавлен также случай перенесённой и повёрнутой камеры. Полная компиляция
вариантов шейдеров проверяется существующими EngineTests.

Первые два запуска нового теста выявили ошибку самой HLSL-вставки (`point`
является зарезервированным словом), они не считаются воспроизведением дефекта.
Поведенческий baseline записан только после переименования и перекомпиляции.

## Ограничения

Проверены малые движения при фиксированных солнце, FOV и aspect.
Большой zoom, смена проекции, размера viewport или света могут менять
масштаб сетки. Sphere-fit занимает больше карты, чем тесный AABB:
устойчивость получена ценой пространственной плотности теней.
Тест не обещает отсутствие aliasing геометрии, LOD-переходов и любого шума
shadow bias. Другие GPU, все point-shadow casters и их анимации,
аудио и экспорт каждой игры не проверялись в этой порции.
