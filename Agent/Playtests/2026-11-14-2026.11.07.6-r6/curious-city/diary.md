# Curious City r6 — дневник

## Сборка и перенос

- Версия проекта: `2026.11.07.6`, EngineVersion/SDK `Release x64`, Module API 5, Edit API 6. HEAD при проверке: `d74aebbc0f450a7cc791255423a37d5df89cfb54`. Текущие Runtime/SDK и Commandlets: `E:/Engine/Game/build/x64/Release/Runtime`.
- Свежий scaffold создан Launcher из текущего релиза в `Engine/build/playtests/20261114-r6/curious-city/fresh-city`. В него перенесены 15 файлов Source и 12 файлов Content из r5-source; свежий `--check-project` прошёл, exit 0.
- Из реального проекта r5 `Engine/build/playtests/20261107-r5/curious-city/final-city` сделана копия `upgraded-city`; upgrade завершился exit 0. Старая папка не менялась. Установлен старый runtime только в собственный EngineStore для совместимости.
- Модуль `upgraded-city` пересобран свежим `ProjectTools.ps1 -Action Build -Runtime E:/Engine/Game/build/x64/Release/Runtime`; последующий `--check-project` завершился exit 0. После небольшой правки HUD модуль снова собран на том же SDK, затем повторены игра и SaveGame.
- Первые sandbox builds показали `LNK1101: неправильная версия MSPDB140.DLL`; первая эскалированная попытка пользовательского модуля тоже не прошла. Повтор сборки завершился сообщением `Build validated and activated`. Это средовой сбой PDB/linker, не дефект игрового кода. Логи первой и успешной попыток приложены.
- В каталоге скопированного r5-проекта был старый `.project-build.lock`. После проверки отсутствия активной сборки удалил только этот скопированный файл в собственной r6-копии. Сборка позже прошла; причинную связь не считаю доказанной.

## Практические сценарии

- Финальный direct SaveGame cycle через `project.input`: 500 → покупка дома → 400/1 и сохранение; после дохода второй дом → 300/2; загрузка вернула 400/1; после загрузки доход дошёл до 410/1. exit 0. Слот сохранён в отдельном `SaveGameHudFinal` внутри playtest-каталога.
- Финальный HUD input cycle: лучевой клик по земле поставил первый дом; кнопка построила второй; сохранение; временная постройка третьего; загрузка вернула баланс 300 и два дома. Все события `ground_raycast_place_click`, `build_ui_click`, `save_ui_click`, `load_ui_click` записаны. exit 0.
- Импорт через текущий `project.import` commandlet: `Hero..v2.obj`, scale 0.01, sidecar, повторный импорт и перенос в `/Game/Models/Moved/` сохранили масштаб 0.01 у всех трёх размещённых объектов. Диалоги не показаны, `accepted=true`, exit 0. Отдельный `MarketHouse.obj` проверил scale 0.1; sidecar и поставленный объект показывают 0.1.
- Point shadows: собственный шестикадровый `render.point-shadows` ввод. Две активные лампы заняли слоты 0/1, третья без слота. При нулевой intensity первой лампы слоты стали `[-1,0,1]`, а при нулевой интенсивности третьей — `[0,1,-1]`. LOD на расстояниях камеры 6/14/24 м выбрал уровни 0/1/2; возврат к исходному ракурсу дал совпавший hash первой грани. exit 0, кадры D3D сохранены.
- Прозрачность: собственные translucent HLSL/material inputs, пересекающиеся плоскости, самопересекающаяся cross-геометрия, четыре orbit ракурса, затем кадр 640×360. Все вызовы `render.transparency` завершились exit 0; BMP показывают цветовые перекрытия при изменении ракурса. Запрос resize дал BMP ожидаемого размера (691254 байта). Командлет сообщил нефатальное предупреждение о dynamic VFS mount для внешнего HLSL; кадры сформированы.
- Материал WarmStone: `material.graph` подтвердил enable → save → preset → apply → undo → redo → revert. Все шаги accepted; graph/HLSL менялись после preset и вернулись к сохранённому hash, `dirty=false`; `nativePreviewWindow=true`. Снимок Qt показывает граф и настройки, но окно нативного D3D preview в PNG чёрное: Qt grab не захватывает swapchain, поэтому пиксели самого preview не подтверждены.

## Маленькое улучшение игры

В `upgraded-city` HUD был смешанным (английские показатели и кнопки, русская цена дома) и не объяснял размещение по земле. Поля стали русскими с ₽/сек, добавлена подсказка «Кликните по земле, чтобы поставить дом», кнопки получили названия «Построить», «Сохранить», «Загрузить», панели расширены под текст. После этого C++ модуль пересобран актуальным SDK; direct и HUD SaveGame циклы повторены успешно.

## Ограничения наблюдения

Пользовательский путь проверен скрытыми MainWindow/GPU commandlets, без занятого рабочего стола. UI снапшот импорта 800×500 показывает три объекта и Scale 0.010 в инспекторе, но viewport чёрный, поэтому это доказательство раскладки/свойства, а не игрового кадра. Game HUD проверен по входам, логам и снимкам состояния объектов; его видимый кадр не снимался.

## Подготовка артефактов

Исходный архив `CuriousCity-r6-source.zip` включает только `Source/` и `Content/` финальной копии. В архиве 98 записей; наличие SDK, Intermediate, Game.dll и PDB проверено — ничего из этого в архив не попало. Выбранные запросы, результаты, логи и снимки сложены в `evidence/`.

## Дополнительные animated feature experiences

- Собственный skeletal point-shadow request использовал scene lighting, Deferred и четыре состояния времени `0 → 0.5 → 1 → 0`. Hash всех шести граней на time 0, time 1 и возврате одинаковый; на 0.5 два face hash меняются, а probe отражает изменившуюся тень. Логи и кадры сохранены в `evidence/animated-point-shadow-skeletal.*`.
- Собственный translucent request включал skeletal и crowd cross-геометрию, орбиту, near/far дистанции, LOD thresholds 160/80 px и размеры 320×256 / 640×360. Дальний LOD отличается; финальный кадр time 0 полностью совпал с исходным по hash. Все пять кадров собраны и просмотрены. Результаты — `evidence/animated-transparency-skeletal-crowd.*`.
