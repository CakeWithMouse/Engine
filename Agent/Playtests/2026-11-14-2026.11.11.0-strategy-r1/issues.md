# Находки автора стратегии

Подтверждён один дефект Engine (STRATEGY-003). Каждый случай классифицируется как
дефект Engine, ошибка проекта, ограничение окружения, документированная граница
или запрос новой возможности. Исправление требует повтора исходного сценария.

## STRATEGY-001 — проект запускает базовый Game вместо игровой логики

- Категория: ошибка организации игрового проекта / затруднение API.
- При переписывании ProjectGame.h удалена аннотация ENGINE_GAME("ProjectGame").
  SelectProjectGame при пустом каталоге создавал базовый Game. И standalone,
  и Editor Play показывали шаблон, игровой код не исполнялся. Первоначальное
  предположение о работающем standalone коридоре опровергнуто исходником.
- Исправление проекта: вернуть аннотацию и include ComponentAnnotations.h,
  проверить GetGameTypes в сгенерированном коде, явный выбор ProjectGame и
  фактические игровые объекты/вызов PreUpdate. Exit 0 шаблона не засчитывается.
- Отдельно проверен контракт `SceneEditSession::CopyForPlay/Control`: Play создаёт
  ProjectGame, восстанавливает сцену, вызывает InitializeGameplay/BeginPlay;
  AfterInitialize не является общим callback начала игровой сессии.
- Игровые доказательства первых запусков не засчитаны. После восстановления
  регистрации агент проверит подготовку проекта в обоих режимах. Engine не менялся.
- Статус: исправлено в игровом проекте; после восстановления регистрации
  настоящие коридор, HUD и FSM наблюдались, архивный игровой повтор прошёл.

## STRATEGY-002 — standalone не сохраняет диагностический BMP

- Категория: ограничение диагностической обвязки.
- `PAINENGINE_D3D_SCREENSHOT` обслуживается в RenderViewportFrame;
  обычный standalone Run не использует этот hook.
- Это не доказательство неисправности D3D. Для кадров Play доступен project.input;
  самостоятельное окно проверяется отдельно. Ошибка рендера не заведена.

## STRATEGY-003 — плотность не влияет на массу физического тела

- Категория: defect, P2, Engine 2026.11.11.0 / main 388d7e9 / Release-v143-Jolt.
- Игра: контейнер 1.8×1.4×1.4, density=12, импульс (-150,3,0).
  После прогрева и 60 кадров x изменился лишь с 0 до -0.0209861;
  проход оставался закрыт. Ожидалась масса из заданной плотности, а не default1000.
- Причина: GameComponent передавал desc.density, но PhysicsWorld::CreateBody
  создавал Jolt convex shape без установки плотности. Jolt рассчитывал массу
  и инерцию со значением 1000 независимо от поля.
- Минимальная регрессия: одинаковый импульс (100,0,0) для единичных кубов
  density10/100 до исправления даёт скорости 0.1/0.1 вместо 10/1. EngineTests:
  82/83, exit1, `dynamic body mass must use requested density`.
- Исправление: задать плотность convex shape до BodyCreationSettings; значения
  density <=0 и нечисловые отклонять. Публичные размеры и типы API не меняются.
- После: куб 10/1, сфера 19.0986/1.90986, капсула 7.63944/0.763944;
  значения совпали с impulse/(volume*density). EngineTests 83/83, exit0.
- Доказательства координатора: fixes/density-before.log, density-after.log;
  игровой исход до правки — strategy/impulse-request.json, impulse-result.json,
  impulse-telemetry.log и снимки. Сила импульса для повтора не увеличивается.
- Повтор автором: тот же запрос ввода, density12 и импульс -150 после пересборки
  проекта дал x=-2.22254 за 60 кадров вместо -0.0209861. Проход открылся;
  реальный D3D-кадр и telemetry сохранены в strategy/impulse-after-*.
  SDK Engine.lib: `6846D88DEE3BAF892E3A4A06C1C965E7FC71966B78A1E5620972178FE7EE0C5D`.
- Статус: исправлен, регрессия и повтор исходного игрового сценария агентом прошли.
