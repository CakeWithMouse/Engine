# Обратная связь r5

- Новый `Engine.Scene.AiDiagnostics` v1 полезен на живом игровом мире: с одного paused snapshot получены группы/serial, состояние flow field, A→B, clearance выбранного радиуса, formation slots и отдельно FSM/perception охранника. Командлетский вызов того же optional API дал данные, не fixture.
- AUTO радиус группы должен быть вычислен по максимальному радиусу живых участников. В r5 результат .4 м согласуется с группой; вручную заданный 1.0 м хорошо показывает почему виртуальный центр группы не заменяет физический радиус бойца. Ошибка STRATEGY-019 исправлена и перепроверена.
- `kind:diagnostics` в project.input оказался достаточным поддерживаемым путём к API при невозможности захватить Editor UI. Если понадобится сравнение именно UI layout/checkbox usability, это отдельная ручная проверка: r5 не утверждает, что кнопку AI и Qt панель на своей игре видел.
- Простая клавиша F и подпись HUD позволили выбрать строй самому. Важная деталь UX — состояние на HUD подписано как строй следующего хода; текущие slots остаются до следующего приказа. Сравнение AUTO .4 / manual 1.0 объясняет ограничения clearance, но само по себе не доказывает пригодность строя. Длительный игровой повтор проверил колонну как фактическую цель группы; прохождение и `Arrived` подтверждены только по статусу/позициям на финальной SDK020b.
- Неудачи CUA и некорректный input step сохранены; они не приписываются движку.

- Длительный игровой путь выявил зависание группового приказа при проекции слотов на барьер; STRATEGY-020 исправлен в SDK020b и повторен на том же свежем проекте. На итоговом движении нарушения барьера отсутствовали. Отдельные неверные выводы из ранних прогонов не переносить на финальный статус.
