# STRATEGY-020 — конфликт мест после смены строя у барьера

Длительный повтор r5 line→column показал: второй боец стоит около
(1.263,-1.209), его место (-.125,-.925); группа остаётся Moving. Остановка
началась до поражения. Исходный запрос и телеметрия сохранены в strategy под
именами r5-fresh-long-column-extended-* и r5-fresh-long-column-telemetry-*.

Отдельная SmallGroupFormationChangeTests воспроизвела незавершённый приказ
за 1800 кадров без охранника, боя и поражения. Причина: независимая проекция
мест через NearestWalkable сближает два места до .57 м при сумме радиусов .8 м.
Боец физически не может занять место рядом с уже стоящим соседом.

Group::AssignSlots теперь резервирует места по мере назначения. Если проекция
создаёт пересечение, ограниченный локальный поиск выбирает свободную клетку,
доступную по прямой от исходной проекции. Пространственные buckets позволяют
сравнивать только соседние места, без полного попарного перебора большой группы.
Исходная формация сохраняется там, где места уже свободны.

До исправления: formation-before.log, 0/1, позиции и места в сообщении ошибки.
После: formation-after.log, 1/1; ai-all-after-formation.log, 58/58.
Регрессия проверяет настоящее прибытие, расстояние между бойцами и отсутствие
пересечения барьера; смена числа columns сама по себе не считается результатом.

передан тому же автору для повтора исходного игрового сценария.

Новая фаза CPU-теста с этой точной позицией также упала. Подробный вывод:
fieldReaches=0, fieldRadius=.5, memberWalkable=1 (corner-detail.log).
Поле округляет .4 до .5; после движения/avoidance боец может оказаться в клетке,
которую допускает его собственный радиус, но не поле. Нулевой вектор поля

Дополнение: если прямой путь к месту закрыт и поле не даёт направления,
выбирается ближайшая доступная соседняя клетка поля, видимая для реального
