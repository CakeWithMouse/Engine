## Ревью изменений и сценарий после READY

Документы обещают: три каскада получают границы из видимой части объявленной shadow area; крайние 10% смешиваются; проекция округляется до сетки texel. Для point shadows действует предел двух теневых ламп; новые лампы за пределом должны освещать без тени. Point caster использует тот же LOD, что видимая геометрия, без ShadowLodBias. Тангентный базис хранится в вершине, а `w=0` означает запасной путь.

Проверить их manifest/hash, затем штатным CLI создать новый проект из пустого каталога; сохранить stdout/stderr, exit codes и логи генерации. Только после успешного scaffold перенести `Source`/`Content` r3 и собрать проектный модуль. Не копировать старый `Game.dll`.
2. Перенести небольшой игровой эффект r3 без смены концепции: поставить дом raycast-ом, списать цену, показать баланс/число домов, дождаться начисления; сохранить/загрузить и после загрузки поставить следующий дом. Это контролирует, что новый чистый проект и базовая экономика живы.

Ожидание: центр направлен по forward; при ортографике направления равны и origins различны; перспективные направления расходятся. Для каждой пары зафиксировать JSON, viewport, снимок при доступном UI.
4. Точечная тень в настоящем runtime-проекте: земля и простой дом/колонна, лампа сбоку на близком расстоянии с `SetCastShadows(true)`. Зафиксировать обычный кадр и `DumpShadowMaps`. Увеличить/уменьшить shadow distance и FOV; ожидание — границы покрывают видимую область по документации без провала на дальнем крае. Скриншоты сравнивать только на зафиксированных кадрах.
