## Ревью изменений

- `MeshData.cpp:87-88` пропускает вырожденное UV отображение; `:133-147` строит конечный перпендикулярный tangent fallback и маркирует отсутствие полноценного UV базиса `w=0`. При чтении SaveGame `SaveState.cpp:12-21` восстанавливает position/normal/UV, затем повторно запускает `GenerateTangents`; это осознанно derived data, а не сохранённая колонка.
- `MaterialTemplate.hlsl:108-111` корректно разделяет normal matrix для нормали и world matrix для направления касательной при обычном/неравномерном масштабе. Но w ориентации не меняется при отражении (отрицательном determinant). `MaterialCommon.hlsli:89` использует этот знак при построении bitangent. Для исходного базиса `N=+Z,T=+X,B=+Y,w=+1`, scale `(-2,3,1)` даёт `T'=-X`, `N'=+Z`; `cross(N',T')=-Y`, тогда как преобразованный `B'=+Y`. Значит w должен стать -1. Шейдер оставляет +1 — подтверждённая кодовая гипотеза, которая проявится с normal map. Координатор готовит независимый GPU-pixel regression; мой проектный A/B пока ожидает новую сборку.
- Для nonuniform positive scale ожидаемый базис остаётся правильным после ортогонализации: scale `(2,3,1)` переносит `T` вдоль +X; inverse-transpose normal остаётся перпендикулярен перенесённой tangent после Gram-Schmidt. Нужно подтвердить интеграционный кадр.

## Финальный проектный путь

- Создан новый `CalmCity` через CLI, код включён, исходный `Source/Content` из r3 перенесён после создания проекта. Первая попытка `--create-project` с `Start-Process -ArgumentList` неверно разбила имя с пробелами и вернула 2; воспроизводимая повторная команда через `ProcessStartInfo.ArgumentList` завершилась 0. Это была ошибка командного quoting.
- Чистый `--enable-code` сначала завершился LINK LNK1101 `неправильная версия MSPDB140.DLL`. По просьбе координатора та же команда повторена вне sandbox и прошла с exit 0. Затем `--build-project` перенесённого проекта прошёл с exit 0.
- Runtime .06.1 запустил игру на 30 кадров: exit 0, в логе подтверждены модуль, сцена, выбранный RTX 4070 Laptop GPU и 30 обновлений. Запрошенный `CALM_FRAME_DUMP` при этом не сохранил BMP. UI-кадры не снимались.
- К моменту SaveGame прохода Runtime был обновлён до .07.0; прямой запуск project lock .06.1 корректно отказал `LaunchError: Project is pinned to another engine release`. По указанию координатора создана новая `CalmCityFinal` через `--upgrade-project` и она пересобрана на .07.0, обе операции exit 0.
- На финальной копии отдельные `CALM_SAVE_TEST=save` и `=load` процессы по 180 кадров завершились exit 0. `SaveGameSelfTest.log` содержит `process=new result=loaded loadedX=5.600000 continuedX=5.350000 PASS`. BMP `save-load-new-process.bmp` просмотрен: изображены квартал, движущаяся машина, освещённая сцена, тени и LOD overlay. Это не подтверждает tangent-space normal mapping.

К финалу роли подтверждены: повторное CLI создание проекта, сборка и upgrade на .07.0, запуск игрового фрагмента и межпроцессный roundtrip сохранения позиции. Тангенты при сохранении и negative-scale normal map остаются отдельными частичными проверками; их GPU интеграцию выполняет координатор. Полные каскадные A/B и UI редактора не проверялись.
