# Дневник r4 — Ремонтный коридор

## Цель

Добавить к r3 выбор группы рамкой и приказ атаки движущегося охранника с настоящим преследованием, уроном и условием победы. Основа — Physics/Jolt, AI FSM, NavGrid/Group, Trace, Input, Camera и HUD публичного SDK. Новых подсистем движка не запрашивал.

## Изменения

- В `ProjectGame.cpp` добавлены прямоугольный выбор screen-space через `ScreenPointToRay` и плоскость пола; рамка видна во время протяжки. ЛКМ без drag выбирает бойца, Shift+клик переключает выделение, Shift+drag добавляет, потеря фокуса отменяет рамку. Бойцы и маркеры приказов показывают выбранное состояние золотым цветом.
- ПКМ по полу выдаёт `Group::MoveTo(point)`, ПКМ по охраннику — один `Group::MoveTo(ObjectRef)` для преследования. Обычный приказ заменяет атаку.
- Урон игрового правила: 4 HP у охранника, попадания группы на ближней дистанции с LOS по NavGrid, доставка через `World::ReportDamage`. После смерти цель снимается, группа останавливается; поражение не может одновременно отображаться победой.
- Для баланса охранник захватывает только бойца без активного приказа атаки; атакующий отряд может добраться до цели и уничтожить её. Физический контейнер по-прежнему двигается импульсом E и открывает проход.

## Ошибки и найденные проблемы

- `r4-build-first.log`: C2065 `selectionRectTests_` — собственная ошибка игрового кода, исправлена добавлением поля; успешная пересборка подтверждена отдельно. Root учитывает её как STRATEGY-017, это не дефект Engine.
- Первые игровые атаки были отправлены до открытия прохода. `Group::MoveTo` корректно вернул Unreachable; после открытия сетки нужен новый приказ. Сценарий сохранён как отрицательный/ошибочный порядок действий, а не Engine bug.
- В `r4-attack-open-gate` второй клик по движущейся цели не попал; этот запуск не считается успешным боем.
- Первый кадр `r4-selection-stable-two.bmp` показал 1/3 и не используется как доказательство 2/3. Корректный устойчивый кадр — `r4-selection-two-stable.bmp`.
- Первый `r4-order-replace` клик по пустой области дал Trace Miss, приказ не заменился; повтор с видимым полом (320,350) подтвердил replacement.

Кроме STRATEGY-016, новых подтверждённых дефектов Engine в этом этапе не обнаружено. STRATEGY-016 — исправленная координатором ошибка сопровождения ObjectRef у группы; после фикса свежая игра подтверждает изменение destination вслед за охранником.

## Результаты фактических прогонов

- Выбор рамкой: обратная рамка выбрала 3/3; пустая рамка очистила выбор. Shift-рамка добавила бойца, Shift-клик снял его; resize до 1000×720 и отмена протяжки при потере фокуса проверены в `r4-selection-controls-*`.
- Устойчивые визуальные selection кадры: `r4-selection-stable-empty.bmp` показывает HUD 0/3 и всех бойцов синими; `r4-selection-two-stable.bmp` показывает HUD 2/3, двух золотых и одного синего. Телеметрия второго кадра: selectedCount=2; одиночные группы бойцов 1/2 разделены.
- Замена приказа (чистый повтор): используйте `r4-order-replace-final-telemetry.log`; ранний `r4-order-replace-telemetry.log` содержит несколько запусков и оставлен только как история. В чистом логе активная атака (activeAttackOrders=1, acceptedOrders=1) сменена приказом пола; следующая запись acceptedOrders=2, attackOrders остаётся в историческом счётчике, activeAttackOrders=0, destination группы стал `0,-1.04167`, trace=Hit. Клик был по видимому полу.
- Основной actual Play `r4-attack-single`: один точный ПКМ после открытия прохода, затем только кадры. Наблюдались активное преследование и обновление destination; на выборке root из 25 samples максимум расстояния destination до охранника 0.02561 м. Итог: 1 приказ, 4 попадания, HP 4→0, guardDead=1, won=1/lost=0, активные приказы остановлены, нарушений барьера 0. D3D кадр после исхода — `r4-attack-single-late.bmp`.
- Окончательный source ZIP распакован в пустую `Engine/build/playtests/strategy-r4/fresh-final/RepairCorridor`, собран из чистой папки с `-Rebuild` (статус `r4-clean-extract-build.status`). Настоящий project.input Play с итоговым source ZIP: `r4-clean-extract-play-telemetry.log` подтверждает те же 4 попадания, победу и 0 нарушений барьера; D3D кадр `r4-clean-extract-play-win.bmp` показывает ПОБЕДА.
- Standalone smoke окончательной чистой распаковки: прямой запуск указанного Runtime `EngineRuntime.exe --project <fresh-final Project.json> --mode game --frames 60`, exit 0, `GameUpdates=60`, `EngineStopped` (`r4-clean-extract-runtime.stdout.log`). Это жизненный цикл runtime, не визуальная проверка. HUD block и fast release: `r4-hud-fast-release-telemetry.log` — рамка выбрала 3/3, acceptedOrders=1 перед click по HUD, затем acceptedOrders остался1, pointerBlocked=1 и trace=InputBlocked.

## Ограничения

- Коридор и его объекты процедурно строятся из `PreUpdate`; `Main.scene.json` почти пуст, редактирование уровня в Edit не сделано.
- Ближний бой намеренно прост: один охранник, 4 HP, фиксированный cooldown/урон; это игровой прототип, не общая combat-система.
- Отрядное перемещение использует NavGrid; полноценного NavMesh/планировщика тактики/боевого path planning нет.
- Основной путь пользователя проверен через настоящий Play/commandlet и Launcher smoke; интерактивное ручное прохождение оператором не заявляется.
