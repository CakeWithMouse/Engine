# Diary — Mesh Physics r2

1. Распаковал неизменённый r1 source ZIP `CF4474…6C0` в `Engine/build/playtests/strategy-040-r2/RepairCorridor`. Сверил project sources с предыдущим архивом; продолжил тот же game code. Сохранил usage checkpoint 53% (позже 54–55%, общий аккаунтный счётчик).
2. По PR31 сделал видимую асимметричную static Mesh-арку из indexed triangles: стойки и перемычка соединены без лишних зазоров, мирный проём после отрицательного X scale шириной 2 м. Прежние координаты gate/nav/grid и crate старого игрового эпизода сохранены. Добавил Dynamic/Mesh open tray, sphere probe и дальнюю неиндексированную вершину для REL040R2-002.
3. Первые CMake сборки прошли на выданном пакете `D0331318…52C9`, до фикса REL040R2-003; позднее обновлённый SDK их заменил. Во время кода обнаружил, что `SetPhysicsLinearVelocity` при регистрации до создания physics handle ничего не делает. Перенёс запуск пробы в `TickComponents` после `Game::TickComponents`, проверяя `HasPhysicsBody()`. Эта игровая последовательность вошла в финальную сборку.
4. До сборки на финальном SDK один PowerShell invocation дал parser error (`empty pipe element`) при выводе двух SDK identities. Сразу исправил только read-only команду; ошибка не меняла файлы и не является Engine-дефектом. Другой небольшой setup ошибкой был первый ZIP-фильтр, который ошибочно принимал авторские Content `.obj` файлы за compiler `.obj`; ошибочная проверка и архив сохранены под `source-archive-verifier-false-positive.*`, фильтр исправлен.
5. На final SDK выполнил CMake и MSBuild `ProjectTools.ps1 -Action Build -Rebuild`, обе сборки валидировали и активировали DLL. Хеши runtime/SDK и DLL сохранены в `evidence/final-runtime-identities.json` и build logs.
6. Игровой `project.input` replay завершил 1241 кадр с `ok=true`/exit 0. На первом sampled record crate был z=3.13567, затем достиг z=4.92988 и упёрся около z=5.52; gate/body flags равны 1, проход открыт. Probe в раннем sample: y=1.48259. Группа получила два приказа, 3 selected, к концу маршрут «на месте», `barrierViolationFrames=0`. После этого FSM охранника привёл к `lost=1`; победу не заявляю. В топ-down BMP форма отверстия визуально не различима; физическое прохождение подтверждается траекторией и runtime Mesh bodies.

Host проверил static/dynamic Mesh state после reopen. Коллизию импортированных моделей после reopen не запускал.
