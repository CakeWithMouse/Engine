# Отзыв — Curious City, персона 2

## Получилось в игре

Обычного проекта C++ хватило для короткого цикла города: щелчок по земле трассируется до точки, объект добавляется и списывает $100, по числу домов начисляется доход, а Save/Load восстанавливает объекты и баланс. Это понятное разделение: правила покупок, дохода и HUD остались в проектном модуле, а Engine дал Scene, Input, GameSubsystem, Trace, UI и SaveGame.

Импорт Suzanne с двумя материалами сделал назначение слота наглядным: перечень source IDs и двух `.mat` путей сохранён в проектной сцене. `SetMaterialAsset` работает как общий override, а пустой путь снова показывает отдельные слоты. Вызов API в игровом коде прямой, но автору приходится сначала узнать source ID из `GetMaterialSlots`; индекс может быть разреженным, поэтому редактору лучше показывать реальные ID и выпадающий выбор материала по каждому ID.

## Где тратится время

- Сценовый property setter `/materialSlots/<ID>` удобен для проверки и Undo/Redo, но без desktop-сессии я не смог подтвердить, как слотные поля выглядят и ведут себя в ручном Inspector. Хочется увидеть таблицу `source ID → asset path`, а не вводить цифру в JSON-путь.
- В базовом HUD контент можно сохранить и при следующем Runtime запуске увидеть. Точки редактирования и появления текстуры/панели раздельны; короткое сообщение UI editor «сохранено, следующий запуск перечитает файл» помогло бы отличать сохранение от live reload.
- Часть символов в тестовой строке `Дом • 100 ₽` не рисуется. Остальной HUD после сохранения побитово сохраняет панель, метки и кнопки. Для локализованных цен полезна явная подсказка, какие диапазоны глифов доступны в текущем font atlas.
- `blend-uv.blend` принялся импортёром, но ожидаемая плоскость не проявилась в тестовой камере. Импортная сводка показывает меш и индексный буфер, однако на экране я не получил результата; путь «поместить, сфокусировать выбранное и проверить texture/UV» был бы полезен для художника.

## Приоритетные пожелания

1. В Inspector добавить строки материалов со source ID и picker ассета, включая состояние «по умолчанию»; Undo/Redo должно явно менять только выбранный слот.
2. В `SetMaterialSlot` пример документации получать ID через `GetMaterialSlots()` и показывать обработку отсутствующего ID/битого пути рядом с кратким игровым сценарием.
3. После восстановления SaveGame показывать в редакторе состояние применения слотов, чтобы путь `.mat` в JSON не выглядел как доказательство уже восстановленного GPU material.
4. Кнопку фокусировки imported model и bounds preview полезно связать с одной командой проверки камеры/UV.

Пожелания 1 и 3 особенно важны для городской игры: десятки повторяемых домов и переживающая перезапуск экономика требуют, чтобы изменения фасада сохранялись и были видны на каждой копии дома.
