# r3 Tired Bomber — подготовка

## Статус
Жду от координатора READY с путём к frozen Runtime 2026.11.05.7. До этого не запускать CLI, сборку, Runtime или commandlet.

## Воспроизводимый путь после READY
1. Штатным EngineLauncher `--create-project` создать новый проект и отдельным процессом `--enable-code`; проверить exit code и CodeBuild.log.
2. Перенести из `srcarchive/Source` и `srcarchive/Content` старое поведение Tired Bomber, не переносить DLL/SDK/Build.ps1/Engine.lock.json/Generated/intermediate; сохранить свежие метаданные, Build.ps1 и lock нового проекта.
3. Добавить малый опыт: импортированная многоматериальная модель как цель и/или бомба, назначение слотов по исходному MaterialIndex, один общий override, сброс override к разным слотам, запись диагностики completed-frame и LOD.
4. Сравнить на простой контрольной геометрии: material slot blend и castShadows отдельно, материализированная модель и контроль UV BaseMap/texture объекта; проверить солнце/приём и отбрасывание теней. Держать камеру/свет/viewport неизменными; кадры сохранить рядом с логом.
5. Проверить слоты после установки/сброса, сохранения сцены, закрытия и повторного открытия; отдельно включить `projectData.materialSlots` и проверить сериализованный JSON.
6. Собрать через свежий `Build.ps1 -Runtime <.7>`, запустить именно активированный модуль на .7, наблюдать игровое движение/попадание, сохранить и повторно открыть штатный проект. Не считать exit 0 единственным evidence.
7. Уточнить три новых material-slots feature и назначенные персонажу 3 строки в корневом `feature-matrix.csv` по конкретным логам/снимкам. Только личные действия этой персоны; результаты тестов координатора отдельно.

## Исходники
`srcarchive/` — распакованный `final-source.zip` персонажа r2, включает Source, Content, README и исторические метаданные; никакого Runtime, SDK, DLL или build output там нет. Новый CLI проект будет создан отдельно после READY.

## Открытые вопросы, которые закрывает .7
- порядок GetMaterialSlots относительно мешей и исходного MaterialIndex;
- действия SetMaterialSlot, общий override и очистка, включая возврат массива слотов;
- persistence `projectData.materialSlots` в сцене и штатном повторном открытии;
- независимость blend/castShadows по слотам, отрисовка маски и UV;
- корректное применение слотов к импортированной цели в игровом кадре.
