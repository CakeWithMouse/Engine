# r7 — найденные проблемы и проверенные исправления

## R7-BUG-001 — устаревшие extension tables после Hot Reload

- Приоритет P1, Engine 2026.11.11.0, Release/v143, координатор.
- `GameEditModule::Reload` заменял базовую сессию и выгружал прежнюю DLL, но
  оставлял прежние таблицы AI, Script, GraphTrace и PointLightV2.
- Ожидание: все таблицы принадлежат новой сессии и остаются вызываемыми.
  Факт: regression до исправления завершился exit 1, `AI extension follows
  reloaded session`. Вызов через прежнюю таблицу мог использовать уничтоженный context.
- Исправление: перенос всех таблиц в той же точке commit; добавлена поддержка
  AssetImportApi в host wrapper и её перенос. Отказ кандидата оставляет старую сессию.
- Проверка: `EditorReloadTests` до исправления — fail; после — 57 checks passed,
  включая вызов AI describe после выгрузки и повторный reload.
- Логи: `Engine/build/playtests/20261114-r7/reload-before.log`,
  `reload-after.log`, соответствующие `.exitcode.txt` (1 и 0).
- Статус: исправлен. Независимый tired-bomber повторил executable в своём scratch:
  exit 0, 57 checks; проверил перенос таблиц и вызов после выгрузки DLL.

## R7-ENV-001 — на машине отсутствует MSVC v142

## R7-BUG-004 — начальный 3D-звук воспроизводится без пространственного расчёта

- Приоритет P1, Release/v143, обнаружен tired-bomber реальным WASAPI loopback.
- Play3D вызывал Start до Apply3D, который выполнялся лишь в следующем Update.
  При запуске во время загрузки сцены до первого кадра проходило около 1,2 с.
  В этот интервал дальний звук играл без затухания.
- A/B одной роли: без обхода near/far RMS около .115; немедленный public Update
  после Play3D дал ослабленный ближний сигнал и нулевой дальний (2000 единиц).
  QPC подтверждает, что первая игровая итерация всё ещё была значительно позже.
- Исправление: Commit listener и Apply3D выполняются до Start. Игровой workaround
  удалён перед повторными проверками; единый Runtime/SDK пересобран.
- SDK после исправления: DBD52453B2E385A031A86185363AAEA6F652A5BAA5A684B2D226075733989C44.
- Повторы: calm-city и tired-bomber. Проверяют фактическое расстояние до listener,
  который следует Player, и раздельные временные окна начального/устоявшегося звука.
  Их первоначальные world-origin near/far fixtures не считаются доказательством
  расстояния до движущейся/настроенной камеры.
- Статус: исправлено и независимо проверено. Bomber: два startup-повтора без
  workaround, затем warmed-up listener (0,24,0), near2m matched amplitude .04066,
  far2000m — нулевой обнаруживаемый сигнал. Calm: listener (14,12,18), реальные
  расстояния 2/20m, correlation .959/.995, linear gains .0504/.0200 (затухание
  примерно 2,5 раза). В обоих случаях используются собственные сигналы, конфигурации
  и анализ реального WASAPI output; прослушивание человеком не заявляется.

## R7-BUG-005 — Editor Play игнорирует масштаб времени Game

- Приоритет P2, Engine 2026.11.11.0, обнаружен curious-city в настоящем edit API.
- В собственном проекте scale0/1/2 давали одинаковые шесть тиков dt=.016 при
  Play/Pause/Resume. Ожидались dt0/.016/.032; standalone UpdateFrame применяет scale.
- Причина: SceneEditSession::frame передавал реальный dt напрямую в низкоуровневый
  StepProjectSimulation, который принимает уже масштабированное время симуляции.
  Это путь Editor Play, а не подмена игрового шага диагностикой.
- Regression до исправления: time-scale-before.log/exitcode.txt — exit1,
  `Editor Play applies simulation time scale exactly once`.
- Исправление: читать Game::GetSimulationTimeScale и применять множитель один раз
  в edit host; прямой StepProjectSimulation сохраняет прежний контракт. Render
  получает исходный реальный dt. Добавлены проверки 0/.5/2 с viewport и без него,
  отсутствия тиков в Pause и сохранения масштаба после Resume.
- Статус: root regression после исправления — exit0, 682 checks. Полная сборка
  All/Runtime/SDK и relink commandlet прошли; текущий SDK Engine.lib SHA256
  87F34A76ABF802F85264E20AF0897C85BE3B18C32D77E12DBDD91CAAE18B6527.
  Независимые повторы на новых DLL прошли: curious-city при scale0/1/2 получил
  накопленное время 0/.096/.192 за шесть тиков, Pause не вызывает ticks;
  tired-bomber при scale0/.5/2 получил 0/.48/1.92 за 60 тиков с Pause между ними,
  player displacement около 0/2.4/9.6. Все повторные процессы завершились exit0,
  Pause сохраняет состояние, Resume продолжает движение. Статус: исправлен и
  независимо перепроверен двумя агентами.
