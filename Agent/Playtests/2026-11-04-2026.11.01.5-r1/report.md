# Опробовать движок — 2026.11.01.5

Прогон выполнен 4 ноября 2026 года на Windows, Release x64/v143, RTX 4070 Laptop. Три агента **GPT-6-Luna / medium** последовательно сыграли четыре роли. Четвёртую роль получил первый агент после города. Координатор выполнял общие сборки и реальные UI-сценарии; агентам переданы наблюдения и снимки.

Созданы четыре небольших игровых фрагмента. **73 из 73 групп возможностей практически попробовали минимум две персоны; 58 групп имеют успешные проверки у двух персон.** Это покрытие сценариев из инвентаризации, а не утверждение, что проверена каждая комбинация всех API. Частичный результат и блокировка не считаются успешным прохождением. Заведено **8 дефектов: 2 исправлены по исключению для C++, 6 оставлены для отдельного навыка починки**.

## Ошибки и исключительные исправления

Полные шаги, ожидаемое/фактическое поведение, приоритеты и свидетельства находятся в [issues.md](issues.md). Первоначальные наблюдения сохранены вместе с последующими уточнениями; итоговые статусы ниже имеют приоритет над промежуточными записями.

| ID | Дефект | Итог |
|---|---|---|
| BUG-001 | Inspector обрезает Z и правые кнопки при исходном размере окна | Открыт; разворачивание окна помогает |
| BUG-002 | Ошибка подстановок и разбора Qt stylesheet | Открыт; есть лог первого запуска и причина в шаблоне QSS, визуальный ущерб отдельно не изолирован |
| BUG-003 | UI Editor Save не применяет активное текстовое поле | Открыт; Enter перед Save помогает |
| BUG-004 | Авария Qt при глобальном отключении окна во время C++ Build/Hot Reload | Исправлен: вместо рекурсивного setEnabled используются существующие busy-ограничения и обновление кнопок |
| BUG-005 | Унаследованный из PowerShell 7 PSModulePath ломает Get-FileHash в Windows PowerShell | Исправлен в Editor и Launcher: дочерний Windows PowerShell формирует собственные пути модулей |
| BUG-006 | Русская диагностика компилятора и PowerShell повреждается в Console | Открыт; коды ошибок и пути читаются |
| BUG-007 | После новой DLL Hot Reload ввод в игре бросков не срабатывал до переоткрытия | Открыт; повторное открытие той же DLL дало 3/3 попадания |
| BUG-008 | Перемещение за центр gizmo обходит включённую привязку | Открыт; перенос по оси округляет смещение правильно |

Изменены только `Editor/Source/CodeTools.cpp`, `Editor/Source/MainWindow.cpp` и `Game/Launcher/Source/Main.cpp`. Release-сборки Editor/Launcher прошли. Реальные повторные сценарии: неудачная пользовательская C2665 сохранила прежнюю DLL; исправленный код собрался и загрузился; новая DLL города сохранила несохранённую сцену; свежий проект с галочкой C++ создался и открылся из лаунчера. `git diff --check` пройден. Релиз не публиковался, коммит не создавался.

Пользовательские ошибки C3861/GetPosition, C2664/unique_ptr, C2013/include, C2027/UIComponent, C2665/ignore ID и ошибки формата/ID сцены записаны в дневниках и исправлены в тестовых проектах. Намеренно сломанный C++ и HLSL использовались для проверки диагностики/сохранности предыдущего результата. Sandbox C1902/LNK1101 и настройка PyYAML учтены отдельно как ошибки окружения, не как баги Engine.

## Границы проверки

См. [матрицу 73 возможностей](feature-matrix.csv), [фактические действия и свидетельства](all-evidence.json), [исходную инвентаризацию](feature-inventory.json). Ни одной группы с менее чем двумя практическими попытками не осталось. Следующие 15 групп не имеют двух полных успешных результатов:

- **Импорт моделей, смешивание материалов моделей и skeletal:** реальные OBJ/GLB/FBX попытки вернули `Assimp not enabled`. До загрузки/анимации моделей не дошли. Это ограничение подготовленной конфигурации, а не успешная проверка этих возможностей.
- **Controller:** персонажи созданы, но короткие W/D через инструмент не дали изменения координат. У инструмента нет удержания клавиши; непрерывное движение осталось непроверенным. B и T как события нажатия подтверждены. Причина отсутствия движения не объявлена дефектом движка.
- **Привязка и HUD Editor:** проверены с выявленными BUG-008 и BUG-003, поэтому часть сценариев имеет статус partial.
- **Trace debug, instances, LOD, mesh tools, particle collision, game settings, render modes, diagnostics:** есть реальные API/smoke/частичные визуальные проверки, но не для всех эффектов и обеих персон. В частности, не доказаны визуально столкновения частиц с глубиной; не все цвета LOD/инстансы осмотрены на экране; статистика в PreUpdate нуждается в уточнении момента чтения.
- **Host services:** VFS resolve/read и актуальная версия сервиса подтверждены; произвольный сервис и fallback несовместимой версии из игрового Game не проверены.

Две различные замороженные DLL (`lights`, `pre-lights`) прошли проверку SHA256 и `--smoke-project-current` без изменения DLL. Интерактивный выбор старого runtime/обновления версии остаётся отдельным сценарием. Редактор материалов дополнительно проверен через UI у ролей 1 и 4: предпросмотр, сохранение параметров, а у роли 1 — откат. Наличие успешного API вызова нигде не заменяет визуальное доказательство.

## Пожелания на следующие релизы

1. Всем персонам нужны доступные поля Inspector, понятная русская диагностика и надёжный цикл «изменить — собрать — играть».
2. Авторам города и экономики — короткие примеры свойств компонента, владения объектами, HUD и строительства по трассировке; меньше обязательного C++ для обычной настройки.
3. Автору бомбардировки — пример Controller с отображением фокуса/клавиш, понятные счётчики Drawn/Culled/LOD и документированный момент чтения статистики.
4. Авторам бомб и бросков — компактный пример движущейся цели, каналов трассировки и ignore ID; объяснение, как исключать предыдущие снаряды.
5. На следующем прогоне продолжить эти же проекты: проверить перечисленные открытые дефекты, импорт на сборке с Assimp, удержание ввода и оставшиеся визуальные эффекты. Новые игровые механики добавлять только в пределах возможностей нового релиза.

## Повторный запуск и артефакты

Рабочие проекты остаются в `E:/Engine/Engine/build/playtests/20261104-r1`: `calm-city/CalmCityProject`, `curious-city/Project`, `tired-bomber/Tired Bomber`, `ai-trash/TrashGame`. Финальные архивы выше содержат Source, Content, manifest, pin и файлы сборки; SDK/Intermediate/бинарники исключены. После распаковки нужен runtime **2026.11.01.5 Release**, его SDK и Visual Studio C++ v143. Для сборки используйте `Build.ps1 -Runtime <путь к Runtime>` из распакованного проекта; manifest после сборки получит путь к новой DLL. Затем `EngineRuntime.exe --project <абсолютный Project.json> --mode editor` либо `--mode game`. Старый module из архива до сборки отсутствует намеренно. Все четыре итоговых архива распакованы в новые каталоги и успешно собраны с нуля; результаты и логи — в [archive-restore-results.json](archive-restore-results.json).

[Сохранённые логи и снимки](reports/evidence/) зеркалируют относительные пути внутри build-каталога: 641 файл, около 60 MiB. [Дополнительные исходники](reports/sideprobes/) содержат ещё пять небольших проб. Публичный authoring probe и анализатор crash-стека находятся рядом с отчётом; crash-дампы в архив не включены. `archive-result.txt` фиксирует упаковку, `artifact-index.json` — размеры и SHA256. Чтение дампа было сканированием возможных адресов возврата, не полноценным unwind стека.

Все видимые тестовые окна закрыты. Оставшийся без окна процесс старого тестового Bomber завершён после сверки PID, executable и Project.json. Это наблюдение очистки, без неподтверждённого диагноза зависания Engine.
