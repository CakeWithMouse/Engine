# Отзыв: Curious City

Короткий сценарий экономики удалось собрать на уже существующих API: пользовательский `Game` запускает `GameSubsystem`, получает `Scene` в `OnSceneReady`, добавляет собственные компоненты и использует симуляционный `deltaTime` для дохода. Библиотечная экономика не понадобилась. Два smoke запуска быстро проверили генерацию/активацию модуля, а отдельный живой запуск подтвердил сумму через реальные секунды, и журнал оказался полезнее ожиданий по коду.

Сложное место было в контракте владения: `Scene::AddComponent` принимает ссылку именно на `std::unique_ptr<GameComponent>`, поэтому `unique_ptr<Derived>` не подходит. Ошибка C2664 указала номер строки и типы; после изменения типа владельца сборка прошла. Для автора с небольшим опытом программирования это место можно сделать понятнее рядом с примерами `AddComponent`, показав явную конверсию владения.

Проект сохранён обычной структурой проекта. CLI ожидает новый путь проекта: указание уже созданного каталога отчёта завершилось exit 1, без пояснения в захваченном stdout/stderr; после использования нового подпути создание прошло. Небольшое сообщение CLI «каталог должен быть новым» помогло бы быстрее понять отказ.

HUD впоследствии добавлен поверх проекта через штатный `ProjectHud` и `.ui`: панель показывает Balance, Income, Bar и кнопку паузы; runtime кнопка реально останавливает и возобновляет доход. Координатор UI подтвердил это на запущенном окне и приложил скриншоты. Это закрывает первоначальное пожелание о видимом балансе.

Полезный диагностический журнал сохранил ценность: он фиксирует покупку домов, тик, восстановленные свойства, смену сцены в GameSession, чтение VFS, выбор дома и причину отказа импорта. При этом экспортируемая portable сборка запускается без исходной рабочей DLL: пять кадров прошли и `/Game` смонтирован из пакета.

Ограничение: импорт GLB завершился понятным сообщением `Assimp not enabled`; текущая конфигурация Runtime не содержит Assimp. CLI `--create-code-project` также не существует в проверенном launcher; no-code создание и последующее включение C++ двумя штатными шагами работает. Нужен UI прогон checkbox прямого C++ создания.

Редакторский HUD текст не фиксируется при сохранении, пока курсор остаётся внутри редактируемого поля: координатор повторил Enter, затем Save; Save без Enter сохранил старое значение (BUG003 в общем UI журнале). Перемещение открытого проекта для portability проверки было ошибкой процедуры агента и исправлено без перезаписи; детали записаны в diary.

Runtime `DebugDrawTrace` probe теперь фиксирует Hit, число построенных линий, накопленные scene statistics и очистку debug state. CharacterController диагностический лог подготовлен для W/D: baseline без нажатий подтвердил нулевое смещение. Координатору нужен отдельный ручной удерживаемый ввод, чтобы подтвердить движение и изменение позиции.

Текущий `getService` VFS v1 и чтение через `/Game` работают. Проверить в этой игровой DLL версионный fallback нельзя: callback принадлежит BaseEngine и проектная Game не может подменить его. Recovery также остался непроверенным: общего Runtime `EditorUiTests.exe` устарел относительно имеющегося исходника и не принимает recovery workflow argument; отдельный проект-клон оставлен координатору для UI шага.



## Финальные наблюдения координатора

Итог координатора: свежая GUI Create C++ выявила BUG005; после исправления launcher повтор --enable-code успешен. Короткие W/D в ControllerProbe не изменили координаты. Удержание клавиш инструментом недоступно; не считать движение подтверждённым или диагностированной поломкой.
