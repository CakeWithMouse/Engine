# Анализ функционала к улучшению

Дата: 2026-11-04. Основание: финальные отзывы, дневники, evidence четырёх персон и общий report.md. P1 — следующий рабочий цикл, P2 — следующая итерация удобства, P3 — после подтверждения спроса. Это порядок полезности, не оценка сроков.

«Прямое» ниже означает явно выраженное пожелание/неудобство автора; «вывод» — предложение аналитика на основании наблюдения. Исправления BUG001–008 учитываются отдельно в fixes/report.md. Пожелания не реализуются этим анализом.

Не добавлять заново: точный Trace, три формы предметов, материалы, UI HUD, VFS и portable export работают. Итоговые Hits 3 / Throws 3 подтверждены после fresh reopen; отдельный дефект reload проверяется независимо.

## Общая последовательность

1. Закрыть восемь воспроизводимых дефектов и оставить команды регрессии: стабильный цикл Create → Build → Play → Edit → Save → Reload важнее новых подсистем.
2. Подготовить четыре коротких компилируемых примера: свойства/спавн, Raycast с ignore, HUD с единым действием, контроллер с фокусом. Проверять их тем же SDK в CI.
3. Добавить наблюдаемость: возможности сборки/Assimp, LOD и отсечение, контекст ввода, профиль валидации и фаза статистики.
4. Проверить спрос на расширение UI layout и post-frame API. Пока достаточно минимальных примеров и измеримых критериев; полноценная физика, большой visual scripting и новый UI framework из этих отзывов не следуют.

Сводка происхождения: у ролей 1, 2 и 4 большая часть новых предложений — выводы из затруднений, а не дословный wishlist. У роли 3 есть явный список четырёх приоритетных пожеланий. Исторические промежуточные «не проверено» не отменяют последующие подтверждения в общем отчёте.
