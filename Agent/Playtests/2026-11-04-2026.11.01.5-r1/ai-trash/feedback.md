# Отзыв — роль 4, «Хлам в ведро»

Вход через кнопку HUD и действие клавиши `T` подключаются к одному броску; координатор наблюдал изменение счётчика и первый успешный hit по основанию ведра. Проектный HUD отображается, камера и свет выставлены удобно. Точная проверка геометрии через `Trace::Geometry::Exact` была уместна для этой механики и не потребовала физического движка. Экспортированный пакет запустился отдельно от редактора.

Два выброса подряд не подтвердили надёжность попаданий: в третьем результат остался `Hits: 1 / Throws: 3`, вероятно, трасса пересекла ранее остановленный предмет. Я исправил фильтр в исходнике так, чтобы игнорировать все `TrashProjectile`, и укоротил текст успеха после замечания о переполнении HUD. Эти правки ждут повторной сборки и UI проверки координатора; до неё результат не считаю закрытым. Общая попытка Hot Reload завершилась аварийным закрытием редактора, но координатор нашёл отдельную проблему запуска Windows PowerShell и исправляет её на стороне движка.

Старые SDK fixtures для импорта/материалов и UI-сценарий rollback ещё не проверены в этой роли. Headless launcher smoke с frozen lights DLL вернул exit 1 без лога; не трактую это как доказанный ABI-дефект и оставляю совместимость непроверенной.

Дополнительно: первая версия фильтра завершилась пользовательской ошибкой C2665, потому что map key — строка, а Query ignore принимает числовой component ID. Исправление использует `GetComponentId()`, сборку и результат бросков после этой правки ещё не проверяли.

Финальный UI проход на повторно открытом проекте подтвердил все три формы мусора и счёт `Hits 3 / Throws 3`; короткий текст помещается в HUD. Сразу после Hot Reload новая DLL активировалась, но ввод кнопки/T не отвечал до fresh reopen. Поэтому разделяю успешный игровой запуск и отдельную проблему состояния ввода после Hot Reload (BUG007). Финальный экспорт и standalone запуск из отдельной папки прошли.

Отдельный SDK/VFS probe скомпилировал штатные ReferenceExamples; runtime разрешил `/Game/Config/message.txt` через host bridge и прочитал `host VFS ready`. Это подтверждает текущий путь к VFS и пример SDK, но не тестирует пользовательскую регистрацию нового host service.

Проверил второй старый fixture (`pre-lights.zip`) из архива релиза: сверены все SHA256. Launcher валидировал проект и запустил frozen DLL через текущий compatible-engine режим; три startup frame smoke прошли, DLL не изменился. В отдельном проекте экранный trace API вызвал воспроизводимый `Success` у ScreenPointToRay и `Hit` у центрального и дробного RaycastScreen запросов. Эти проверки можно повторять без окна редактора.


## Финальные наблюдения координатора

Итог координатора: свежий проект с галочкой C++ создался после исправления launcher, DLL25926d6. Undo/Redo, осевой snap и восстановление несохранённого куба после аварии подтверждены; center snap дал BUG008. Материал открыт через Inspector, Tint.x0.9→0.95 сохранён и сверён с .mat.
