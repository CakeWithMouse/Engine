# Находки релизной проверки 0.4.0

## REL040-001 — Несогласованные MSVC compiler/STL в CMake SDK

Категория: defect, P1, исправлено и повторено.

Условия: SDK собран MSVC 14.40; рядом установлен MSVC 14.44.
`Test-CMakeProjects.ps1` создаёт C++-проект в `CMake проект 日本語` и вызывает
`ProjectTools.ps1 -Action Enable` обычным Windows PowerShell 5.1.
Ожидание: сборка, проверка и активация Game.dll.
Факт: выбран абсолютный `cl.exe` 14.40 из Sdk.json, но INCLUDE/LIB — от
автоматически выбранного 14.44; компиляция STL падает, включая C2801.
Это воспроизводится до запуска игрового кода.

Исправление: `Get-ProjectCMakeTools` для MSVC берёт compiler из того же
native toolchain, который предоставляет INCLUDE/LIB/PATH. Выбор clang-cl сохранён.
Повтор исходного интеграционного теста в новом каталоге прошёл: создание,
startup, no-op build, новый класс и сохранение прежней DLL при `#error`
в исходнике с восстановленной старой датой.

Доказательства: `cmake-projects.log`, `cmake-projects-fixed.log`.
Последняя ошибка компиляции в исправленном логе намеренная; итог теста — PASS.

## REL040-002 — Значок игровой камеры классифицирован как обычная камера

Категория: defect, P2, исправлено и повторено.

`ViewportBillboardTests` добавляет `Gameplay.Camera` без дополнительного
gameplayKind в snapshot и проверяет категорию и цвет значка. После появления
CameraGuide общий `IsCamera` перехватывал объект раньше проверки игрового типа.
Ожидание: `iconGameCamera`; факт: обычный `iconCamera`.

Исправление: проверка игрового типа/вида выполняется раньше общего camera predicate.
Существующая регрессия до исправления упала, после — прошла вместе с UiTests.
Доказательства: `ui-before-fix.log`, `ui-after-fix.log`.
