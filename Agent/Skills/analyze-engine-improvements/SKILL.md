# Анализ функционала к улучшению

Прочитай отзывы, дневники и evidence последнего Agent/Playtests-прогона, общий report/issues и результаты последующих исправлений. Сопоставь пожелания с текущей документацией и кодом: уже существующая возможность может требовать лучшей доступности, примера или диагностики вместо новой реализации.

Для каждой из четырёх персон отдельно составь список: что улучшить/добавить/переделать, какая игровая задача этого требует, конкретное неудобство или цитата с ссылкой на источник, минимальное полезное изменение, приоритет и проверяемый критерий готовности. Отмечай происхождение: прямое пожелание автора либо вывод аналитика. Не приписывай автору собственные идеи.

Разделяй подтверждённые дефекты, улучшения UI/UX, документацию/примеры, изменение API и действительно новую возможность. Учитывай финальные уточнения координатора и уже закрытые пожелания. Непроверенная функция не означает отсутствующую; сборка без Assimp не означает отсутствие импортёра в движке.

После списков персон выдели общие потребности и предложи небольшой порядок следующих итераций с зависимостями. Не обещай сроки без оснований и не добавляй крупную архитектуру без пользовательского сценария. Этот навык составляет анализ: он сам по себе не поручает реализовывать wishlist или менять движок.

Сохрани самостоятельный improvement-analysis.md рядом с результатами прогона и дай краткий список по каждому разработчику в ответе. Ссылки на первичные отзывы обязательны. Сохраняй историю исходных отзывов и отличай факт от рекомендации.
