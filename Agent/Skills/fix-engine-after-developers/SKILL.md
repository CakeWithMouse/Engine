# Фикс движка после разработчиков

Примени результаты последнего пользовательского прогона PainEngine: сделай существующий функционал вызываемым без запущенного интерактивного редактора, воспроизведи дефекты, покрой контракты тестами и исправь все заведённые дефекты в согласованной области.

## Входные данные

Прочитай Agent/AGENTS.md, Agent/engine-developer.md, текущий код/версию/задачи, git status, последний Agent/Playtests/*/report.md, issues.md, feature-matrix.csv и свидетельства нужных жалоб. Учитывай исправления предыдущего прогона; не откатывай их. Старые документы могут расходиться с текущими API. Пожелание, неподтверждённое наблюдение, ошибка игрового кода и зависимость окружения не становятся дефектом Engine автоматически.

## Два слоя вызовов

В текущем репозитории начни с Engine/docs/COMMANDLETS.md и Editor/Tools/EngineCommandlets.cpp. Сборка: Invoke-MSBuild.ps1 -Project Editor/EditorModule.vcxproj -Configuration Release -EngineCommandlet. Сценарии: Editor/tests/CommandletTests.ps1, CppWorkflowTests.ps1, ReloadInputTests.ps1. Используй их как поддерживаемую точку расширения, не создавай второй несовместимый интерфейс. После изменения UI проверяй полную EditorTheme, активный фокус и уничтожение окна: голый QWidget может пропустить QSS/teardown дефект.

1. **Команды функционала.** Найди существующие CLI, публичные API и тестовые программы. Добавь небольшой расширяемый commandlet-интерфейс: список команд/справка, входные параметры или JSON, машинный результат, диагностика и ненулевой exit code при ошибке. Он должен вызывать настоящие операции движка и принимать разные данные; набор зашитых ответов или одни имена тестов не заменяют API. Для нового функционала релиза добавляй команды к этому интерфейсу, а не очередной одноразовый probe.
2. **Сценарии жалоб.** Для каждого ID бага сохрани воспроизведение через тот же функционал, с входными данными и измеряемым результатом. Параметры ширины окна, кодировки, незавершённого ввода, последовательности reload и ошибок сборки относятся к контракту сценария. UI-ошибки проверяй настоящими виджетами в отдельном offscreen-процессе; CPU-вызов не доказывает исправление отображения. D3D может требовать скрытый HWND/устройство: явно отделяй отсутствие редактора от отсутствия GPU.

Не строй универсальный удалённый RPC или аналог UE целиком. Предпочитай узкую локальную CLI-оболочку над текущими операциями и повторное использование существующих fixtures. Не меняй данные пользовательских проектов: проверки выполняй в отдельных scratch-каталогах. Зафиксируй требования команд к Qt, GPU и опциональным импортёрам; отсутствие зависимости должно быть явным blocked, не passed.

## Тесты и починка

Составь таблицу «функция/BUG → команда → ожидаемый эффект → тест». Запусти регрессии до правки, где это возможно; сохрани причину отказа. Проверяй наблюдаемый контракт (координаты/текст файла/доступность поля/событие после reload), а не совпадение исходного кода с шаблоном. Актуализируй устаревшие runner/fixtures, не ослабляя корректные ожидания ради зелёного результата.

Исправляй минимальную причину в Engine/Editor/Launcher, не прячь её адаптацией тестовой игры. Уже исправленные баги тоже должны иметь проверку. После правки повтори соответствующий сценарий, связанные существующие тесты и необходимые сборки. Для отображения добавь сохранённый результат render/layout и осмотри его. Не называй дефект исправленным, если регрессия не прошла или исходная жалоба осталась необъяснённой.

## Результат

Сохрани поддерживаемые команды и их документацию в репозитории, тесты рядом с существующими наборами. В Agent/Playtests/<run>/fixes сохрани план покрытия, результаты до/после, команды запуска, логи и итоговые статусы всех BUG. Исторические свидетельства не переписывай; актуальный итог добавь отдельно. Отчёт должен перечислить исправленное, проверки, ограничения и оставшиеся дефекты. Публикацию релиза или коммит выполняй только по отдельному запросу.

Соблюдай действующий бюджет сессии; проверяй общий недельный счётчик перед дорогими фазами. Не выдавай расход аккаунта за точный расход одного чата. Если работа упёрлась в лимит или внешнюю зависимость, оставь воспроизводимую точку продолжения и честный статус.
