## Инвентаризация

| Проект | Источник сцены | Классы и ресурсы |
|---|---|---|
| Triangles | FirstSemestrLegasy::FirstLabStart_a | Два вращающихся квадрата из треугольников, TriangleComponent; порядок рисования BaseGame, общие шейдеры, без файловых ассетов |
| Cube | FirstSemestrLegasy::FirstLabStart_b | CubeComponent, тот же порядок рисования без глубины, общие шейдеры, без файловых ассетов |
| Pong | FirstSemestrLegasy::SecondLabStart | PongGame, Ball, Rocket, Wall; процедурная сцена, общие шейдеры; специальные Draw/TickComponents и счёт |
| SunGame | GameExample/Source, ранее ThirdLabStart | SunGameConfig, сферы, свет, GPU-частицы, инстансинг; общие шейдеры, необязательная отсутствующая cosy.jpg |
| Katamari | FirstSemestrLegasy::ForthLabStart | KatamariGame, KatamatiSphereComponent, FBXComponent; Models/{1,2,3}.obj/.jpg и test_cube.obj имеются; cosy.jpg отсутствует; требуется Assimp |

FBXComponentCollision — вспомогательный неиспользуемый игровой класс, не отдельная игра. Архивы моделей сохраняются вместе с оригиналами в 1_Lab; игре нужны распакованные obj/jpg. Legacy-сцены не удаляются до проверки эквивалентности. BaseEngine/BaseResources/BaseGameConfig остаются в Engine; их незавершённый жизненный цикл не меняется.

MSBuild сохраняется. По умолчанию собираются четыре примера без внешнего импортёра; Katamari имеет самостоятельный полный проект и включается явной опцией Assimp. Это ограничение зависимости, а не альтернативная сцена. Лаунчер — отдельное Win32-приложение, запускающее exe процессов, не runtime-хост и не редактор.

## Результаты

Инвентаризация проверена чтением всех пяти точек построения сцены, классов игр и проектов. Установленного C:/vcpkg и VCPKG_ROOT нет. Пользовательские staged-изменения сохранены; индекс Git не изменяется.

### Перенос и небольшие исправления

Пять проектов созданы. Source/Content SunGame перенесены из GameExample; сцена SunGame и её настройки не переписаны. Четыре других точки входа извлечены из FirstSemestrLegasy с сохранением состава и параметров сцены. Исторический источник и игровые классы в 1_Lab оставлены для сравнения. Номера лабораторных не возвращались в Engine. BaseGame переименован в OrderedSceneGame и вынесен в Game/Common; массивы квадратов — в Triangles. Базовые компоненты остались общими в Engine.

Изменения при адаптации: include на публичный Engine API; абсолютные пути от exe; исключение SetGameType; обёртка регистрации с проверкой результата и передачей владения только при Ok; проверка LoadModel в Katamari; общий режим --smoke. В Pong исправлена опечатка Cube->SetRocketType(Right) на Cube2: исходник назначал правый тип левой ракетке, оставляя другую неинициализированной. Enum-поля ракетки и стены получили определённые начальные значения. Остальные правила счёта/коллизий не менялись.

Семь obj/jpg Katamari проверены SHA256: совпадают с оригиналами. Лицензии из трёх архивов скопированы отдельно. Исходные obj ссылаются на отсутствующие распакованные mtl; их материалы/дополнительные текстуры есть в архивах и требуют отдельного восстановления без конфликта имён. cosy.jpg отсутствует, сохранено прежнее поведение без соответствующих отражений.

При первой сборке лаунчера обнаружены два предупреждения преобразования ID контрола в HMENU на x64: исправлены использованием INT_PTR, затем пересобран только лаунчер в обеих конфигурациях, без предупреждений. Реальный запуск Start.cmd выявил дубли Path/PATH, из-за которых Windows PowerShell 5.1 не мог прочитать ProcessStartInfo.EnvironmentVariables: нормализация перенесена до чтения этого свойства, повторный запуск успешен. Повторные проверки выполнялись после этих исправлений, без повторной компиляции игр.

Воспроизводимые проверки: tests/run-games.ps1, tests/run.ps1. Журналы игр сохраняются в build/launcher-checks. Smoke-проверки не подтверждают визуальную эквивалентность сцен, управление, счёт Pong или сбор объектов Katamari. Полная сборка/запуск Katamari и ручной визуальный проход остаются открытыми пунктами.
