# 035-PLAN: Честный бенчмарк Battle + финальная проверка фазы 1 (VFS)

## 1. Контекст и цели задачи
- Создание воспроизводимого, статистически устойчивого инструмента замера производительности сцены `Battle` (CPU и GPU).
- Разрешение дефектов прежнего замера:
  1. Недостаточный прогрев (в 034 фактический прогрев составлял 10 кадров вместо заявленных 150; исправлено на 150 кадров по умолчанию).
  2. Попадание нулей и дубликатов в среднее `gpu_ms` при `S_FALSE` (исправлено монотонным счётчиком `GpuTimerSamplesReady` в `Game`, явным учётом готовых сэмплов и расчётом процента готовности).
  3. Аллокации в цикле кадра (исправлено предвыделением массива сэмплов фиксированного размера).
  4. Чувствительность к выбросам (вместо простого среднего добавлены медиана, p95, p99).
  5. Невалидность замера при активном VSync (добавлена валидация `bVSync` с аварийным выходом).
  6. Отсутствие аппаратного контекста (добавлен вывод DXGI GPU адаптера, CPU via `__cpuid`, разрешения и git-хеша).

- [x] **Факт по GPU:** Установлено, что замеры 033 и 034 фактически шли на встроенном видеоядре **AMD Radeon(TM) 610M** (iGPU), а не на RTX 5060 Laptop (при `pAdapter = nullptr` в `Game.cpp:517` Windows без явной записи в `UserGpuPreferences` выбирала iGPU; время GPU составляло 8.58 ms на iGPU против 0.67 ms на dGPU). Закрепление dGPU осуществляется в `bench-ab.ps1` через `UserGpuPreferences` без правок ядра.
- [x] **Backlog:**
  1. Дефект таймера в `Game.cpp:2860` (безусловный сброс `GpuTimerIssued[slot] = false;` затирает незавершённые запросы кольцевого буфера на медленных GPU / iGPU до вызова `GetData`, что приводило к `gpu_ready = 0`); старый метод `BuildReport` дублировал `LastGpuFrameMs` в `GpuMsSum` при `S_FALSE`. Ядро не правится в рамках 035.
  2. Утечка `/_ext_*` между тестами (`VfsRead.cpp:167-170`): динамические точки монтирования не снимаются при остановке движка.
  3. `std::getenv` в `viewportCamera` (`Base.cpp:515`): предупреждение C4996, требуется переход на `_dupenv_s`.
  4. `stderr` против `stdout` в `VfsRead`: диагностика в `stderr` при общем потоке `stdout`.
