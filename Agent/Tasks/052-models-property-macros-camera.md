# 052 — Модели, свойства и камера

Запрос: модель/материал для любого GameComponent; свойства без ручного JSON; настройки персонажа/камеры в инспекторе; Delete, размер viewport и читаемая консоль.

Реализовано:
- Визуальная модель хранится отдельно от игрового класса. Назначение через инспектор больше не меняет тип объекта; scene restore сохраняет модель, кодек и поведение класса. Ошибка загрузки оставляет предыдущую модель.
- Материал можно сохранить на любом компоненте. Старые position/color-примитивы получают mesh с нормалями и UV при использовании материала. Визуальная часть участвует в рендере, picking, bounds и Tick.
- PropertyMacros.h: ENGINE_PROPERTIES, ENGINE_PROPERTY, ENGINE_ENUM_PROPERTY. Наследование схемы/данных, диапазоны, типы, значения по умолчанию для новых полей, отмена невалидной загрузки, OnPropertiesChanged. Шаблон C++-проекта использует макросы. Руководство: Engine/docs/PROPERTY-MACROS.md.
- Character: скорость через общий инспектор без дублирования. SceneCamera: перспектива/ортографическая проекция, FOV, near/far, высота вида, точные плоскости XY/XZ/YZ или Transform. PlaySettings: ссылки и параметры управления/следящей камеры через свойства.
- Delete во viewport вызывает существующую undoable-команду; ввод в текстовых полях не перехватывается.
- Сняты минимумы layout дочерних панелей, мешающие изменению размеров. Проверено расширение viewport более 75% ширины окна.
- Время HH:mm:ss.zzz в консоли; буферизация строк компилятора, полный build.log, вывод диагностик проверки/старта DLL. Убраны покадровые сообщения overlay и повторяющаяся инициализация примитивов.
- Исправлена потеря фокуса у общих свойств из-за hide/show при каждом Refresh. UI-тесты хранят настройки в изолированной INI внутри fixture.

Проверено Release/x64 с Assimp:

## Уточнение 2026-11-01 — аннотации над полями

- ENGINE_PROPERTY("Подпись", min, max) / ENGINE_ENUM_PROPERTY("Подпись", варианты) стоят непосредственно над объявлением поля.
- ENGINE_GENERATED_PROPERTIES(Base) один раз объявляет методы класса; ComponentGenerator генерирует определения с доступом к private/protected-полям. Список имён полей вручную не нужен.
- Внутренний явный codec движка использует служебные ENGINE_PROPERTY_FIELD / ENGINE_ENUM_PROPERTY_FIELD; шаблон проекта и основное руководство переведены на аннотации.
- Проверено: 24 scanner-проверки; ComponentGenerationTests с private-полями, enum/string, наследованием, десятичными границами, откатом невалидных данных и полем data; внешний проект из обновлённого dev SDK собран, валидирован и запущен (O:/Engine/target/property-annotations-sdk-20261101).

## Уточнение 2026-11-01 — свойства в GameComponent

- GameComponent предоставляет виртуальный DescribeEditorProperties с пустой схемой по умолчанию; SceneAuthoring вызывает его напрямую. Дополнительное наследование больше не требуется в шаблоне и штатных компонентах.
- EditorPropertyProvider оставлен отдельным устаревшим интерфейсом только для совместимости исходников: прежний override реализует оба контракта. Не создаётся неоднозначное повторное наследование GameComponent.
- Версия разработки/SDK: 2026.11.01.0. Формат сцен 3 и DLL API не изменены. Штатный перенос сохраняет оригинал и пользовательские DLL, заменяет известные стандартные модули; новая C++ функциональность требует пересборки с новым SDK.
- Добавлены проверки вызова схемы через GameComponent, редактирования/Play без интерфейса, старого интерфейса, наследования и значений по умолчанию; расширен тест редактирования и перезагрузки перенесённого старого DLL.
- Новый Engine/tests/code-projects/property-upgrade.ps1 проверяет перенос ранее собранного starter-проекта с сохранёнными свойствами, пересборку неизменённых исходников, удаление старого наследования, повторную сборку/валидацию/запуск, сохранение значений и исходника.
- Проверено Release/x64/Assimp: EngineTests 47/47; ComponentGenerationTests PASS; CompatibilityTests 112 проверок (замороженные DLL); property-upgrade PASS на проекте 2026.10.31.3. Устаревшие ожидания формата 2 в compatibility-тесте обновлены до действующего формата 3.
