# 058 — GameSubsystem первой версии

Реализовано 02.11.2026 по согласованному контракту пользователя.

- `GameSession` владеет экземплярами, переживает последовательную замену `Game`/Scene.
- `ENGINE_SUBSYSTEM()` обнаруживается ComponentGenerator при обычной сборке;
  один GeneratedComponents.cpp на игровой модуль, без статической регистрации.
- `Initialize`, SceneReady/Closing, opt-in Tick и обратная очистка; частичная
  инициализация откатывается. Stop из callback откладывает уничтожение.
- Standalone Game создаёт собственную сессию; editor Play и runtime DLL имеют
  внешнего владельца внутри игрового модуля. Pause сохраняет данные, Stop и
  выгрузка очищают их. Edit и material preview не создают подсистемы.
- Публичный SDK содержит API, генератор, пример и руководство.

Документация: [GAME-SUBSYSTEMS](../../Engine/docs/GAME-SUBSYSTEMS.md).
Пример: `Game/BasicExamples/Source/SessionCounterSubsystem.h`.

Проверено MSVC v145, x64 Release:

- core с Assimp: 56/56;
- runtime: 18 проверок;
- scene-module: 109 проверок;
- edit-session: 651 проверка;
- существующий viewport suite;
- SubsystemTests: безоконные lifecycle/transition/rollback, порядок до BeginPlay,
  переключение тика, Pause, реентерабельный Stop, исключения Tick, настоящий
  viewport без двойного тика и material preview без подсистем;
- scanner: пустой каталог, добавление/удаление, дубликаты, ошибочные объявления;
- установленный SDK вне репозитория: сборка DLL и host, автоматическое добавление
  и удаление заголовка, отказ некорректного класса, Play/Stop, откат ошибки,
  уничтожение до FreeLibrary и чистое состояние после повторной загрузки;
- BasicExamples: сборка с новым каталогом и smoke 30 кадров.

Ограничения MVP: один активный Scene и один каталог на модуль, поток владельца,
без графа зависимостей, UI переходов и переноса состояния при hot reload.
Смена сцены — внутренний путь через внешний GameSession и последовательные Game;
тест подтверждает сохранение адреса и данных экземпляра.
