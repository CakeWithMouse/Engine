# P0. Общий CreateInstance оставляет GamePtr неинициализированным

## Где

`GameComponents.h`, поле `GamePtr`; `GameComponents.cpp`, конструкторы, `CreateInstance`, `Update`.

## Проблема

Поле `GamePtr` не имеет инициализатора. Обычная регистрация выставляет его, но общий `CreateInstance` создает объект и кладет в `InstanceArray`, не вызывая `SetGame`. Затем `Update` рекурсивно вызывает `Inst->Update`, где читается `GamePtr`. Это путь с неопределенным поведением.

## Исправление

Все raw observer pointers и shader pointers инициализировать `nullptr`; фабрика экземпляров должна устанавливать owner/context до помещения объекта в обновляемый список. Установить одинаковые постусловия для общего и специализированных API.

## Критерий приемки

Создание instance через общий API не приводит к чтению неинициализированного `GamePtr`; все instance API дают одинаково валидный объект.
