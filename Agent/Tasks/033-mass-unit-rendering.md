# 033. Рендер массовой техники: инстансинг мешей и LOD

## Зачем

Цель проекта — стратегия в духе Total War, где на поле одновременно сотни и тысячи единиц техники. До этой задачи каждая импортированная модель рисовалась отдельными draw call по сабмешам, инстансинг существовал только для примитивов, LOD не было. Сотня машин давала сотни вызовов и упирала CPU ещё до появления игровой логики.

## Что сделано

- `InstancedMeshComponent` (`Engine/Include/Engine/Components/SpecificComponents/InstancedMeshComponent.h`): один компонент на тип техники, экземпляры хранятся массивом записей (позиция, поворот по вертикали, равномерный масштаб, цвет).
- Раз в кадр компонент отсекает экземпляры по пирамиде видимости, выбирает LOD по расстоянию, раскладывает по корзинам и загружает по одному инстанс-буферу на уровень. Цветной проход и каскады теней используют один подготовленный набор.
- Тени получают собственный набор экземпляров: без отсечения камерой (иначе техника за краем экрана не отбрасывала бы тень), со своей дистанцией и смещением LOD.
- Материал `Engine/Content/Shaders/InstancedMesh.hlsl` с forward- и G-buffer-вариантами на общем `Common.hlsli`, так что освещение массовой техники совпадает с остальными материалами и в deferred считается в экранном пространстве.
- Счётчик отсечённых экземпляров в `FrameStats`, заголовок окна показывает нарисованные и отсечённые экземпляры.
- Сцена измерений `Game/Battle`: поле техники, стратегическая камера, движение каждый кадр, ключи `--units/--frames/--no-shadows/--forward/--static/--lod-debug`, строка результата в stdout. Добавлена в лаунчер, решение, `build.ps1` и `Game/tests/run-games.ps1`.
- Документ для дизайнеров и разработчиков: `Engine/docs/UNIT-RENDERING.md` (требования к моделям, подключение в коде, таблица замеров).

## Результат измерений

Release x64, VSync выключен, окно 1000×500, техника движется каждый кадр.

| Техники | Тени | Кадр, мс | FPS | draw calls |
|---|---|---|---|---|
| 2000 | вкл | 4.70 | 213 | 10 |
| 2000 | выкл | 1.63 | 613 | 4 |
| 8000 | вкл | 5.15 | 194 | 9 |
| 20000 | вкл | 5.68 | 176 | 9 |
| 20000 | выкл | 2.61 | 383 | 3 |

Число draw call не зависит от числа машин. Основная цена при включённых тенях — три каскада, которые рисуют всю технику в радиусе теней.

## Ограничения текущей версии

- Поворот экземпляра только вокруг вертикальной оси, масштаб равномерный: наклона по рельефу нет.
- Анимации (башня, гусеницы) нет; карт нормалей нет.
- Один материал и одна текстура на тип техники.
- Загрузка LOD из файлов моделей ещё не подключена: геометрия задаётся кодом (`Game/Battle/Source/UnitMesh.h`), импортёр включается отдельно вместе с Assimp.
- Тени не отсекаются по каскадам и используют ту же дистанцию для всех уровней.

## Следующие шаги

1. Отсечение экземпляров отдельно для каждого каскада теней и более грубый LOD в тенях; повторить замеры этой же сцены.
2. Подключить загрузку LOD из моделей дизайнеров (`<Name>_LOD0..2`) через существующий импортёр.
3. Наклон по рельефу и поворот башни, когда появится игровая логика.
4. При росте числа типов техники — сортировка и группировка по материалу, затем отбор на GPU.
